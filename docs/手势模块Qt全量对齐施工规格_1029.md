### 1.3 XGestureEvent 信封语义

- 现为扁平事件；对标 Qt 改为**信封**：可同时携带多个手势。
- Qt 权威 API（`qtbase/src/widgets/kernel/qgesture.h:243-282`）：

```cpp
class Q_WIDGETS_EXPORT QGestureEvent : public QEvent {
    QList<QGesture *> gestures() const;               // 全部手势
    QGesture *gesture(Qt::GestureType type) const;   // 按类型取
    QList<QGesture *> activeGestures() const;         // 进行中
    QList<QGesture *> canceledGestures() const;       // 已取消
    void setAccepted(QGesture *, bool);
    void accept(QGesture *);
    void ignore(QGesture *);                          // ← Qt 用 ignore 不用 reject
    bool isAccepted(QGesture *) const;
    void setAccepted(Qt::GestureType, bool);
    void accept(Qt::GestureType);
    void ignore(Qt::GestureType);
    bool isAccepted(Qt::GestureType) const;
    void setWidget(QWidget *widget);
    QWidget *widget() const;
private:
    QList<QGesture *> m_gestures;
    QWidget *m_widget;
    QMap<Qt::GestureType, bool> m_accepted;          // 按类型的接受状态
    QMap<Qt::GestureType, QWidget *> m_targetWidgets;
};
```

- 对应本库 API（命名按 Qt 方法名映射到 C 风格）：
  - `XGestureEvent_gestures(event)` — 取手势集合（**借用**，不转移所有权）
  - `XGestureEvent_gesture(event, type)` — 按类型取（借用；未命中返回 NULL）
  - `XGestureEvent_activeGestures(event)` / `XGestureEvent_canceledGestures(event)`
  - `XGestureEvent_setAcceptedGesture(event, gesture, bool)` /
    `XGestureEvent_acceptGesture(event, gesture)` /
    `XGestureEvent_ignoreGesture(event, gesture)` /
    `XGestureEvent_isGestureAccepted(event, gesture)`
  - `XGestureEvent_setAcceptedType(event, type, bool)` /
    `XGestureEvent_acceptType(event, type)` /
    `XGestureEvent_ignoreType(event, type)` /
    `XGestureEvent_isTypeAccepted(event, type)`
  - `XGestureEvent_setWidget(event, widget)` / `XGestureEvent_widget(event)`
- ⚠️ **命名校正**：Qt 是 `accept/ignore`（C++ 用 ignore 表「不接受」），本库规范文档
  惯用 `reject`。对齐 Qt 时**手势信封这一族用 `ignore`**（与 Qt 同名同义），
  事件基类的 `accept/reject` 沿用本库既有约定。
- 兼容期：现有扁平字段保留为「主手势快捷视图」（= 信封中类型匹配主手势者），
  注释标明来源与废弃计划。

### 1.4 XGestureManager 投递与仲裁（Qt 权威机制，本库当前完全缺失）

> Qt 侧基准：`qtbase/src/widgets/kernel/qgesturemanager.cpp`
> （`deliverEvents` 587-660、`getGestureTargets` 543、`cancelGesturesForChildren` 387、
> `cleanupGesturesForRemovedRecognizer` 444、`recycle` 706、
> `unregisterGestureRecognizer` 97、`cleanupCachedGestures` 121）。
> **本库现状 = 识别器直接投递事件给订阅控件，无集中管理器、无仲裁、无
> GestureOverride、无 hotSpot 猜目标** —— 这是「手势完全对齐 Qt」的结构性
> 缺口，也是最容易做错的部分。

Qt 投递流程（逐条照搬语义）：

1. **找目标**：手势刚 Started 时若尚无目标控件——
   - 若 `hasHotSpot()`：用 hotSpot 的**全局坐标**找控件
     （`QApplication::topLevelAt(pt)` → `childAt(mapFromGlobal(pt))`，
     取不到子控件则用 top-level）；
   - 否则：用手势的 **context 对象**（若为控件类型则取该控件）。
2. **冲突检测**：多个手势的 Started 阶段可能落在同一接收控件 →
   `getGestureTargets` 判为 **conflicted**。
3. **GestureOverride 仲裁**：冲突时先向接收控件发
   `QEvent::GestureOverride`（事件与其中每个手势**默认 ignored**），
   让控件选择接受哪些手势；未在此步接受的冲突手势不再投递。
4. **正式投递**：非冲突手势直接按目标控件分组投递
   （`QGestureEvent` 信封，含该控件收到的全部手势）。
5. **取消传播**：子控件上的手势被取消时，`cancelGesturesForChildren`
   连带取消其子控件上的同族手势。
6. **回收**：`recycle` 把结束的手势对象回池复用（Qt 用对象池，避免每帧分配）。

对应本库新增（命名按 Qt 方法名映射）：

- `XGestureManager`（内部实现，不公开；可放 `XGestureManager_Protected.h` 或
  识别器模块内部文件）：
  - `xgm_deliverEvents(gestures)` — 上述 1~4 步
  - `xgm_getGestureTargets(started, conflicted, normal)` — 冲突判定
  - `xgm_cancelGesturesForChildren(original)` — 取消传播
  - `xgm_recycle(gesture)` — 手势对象回收（与 Qt 池化语义一致，避免每帧分配）
- 事件类型新增：`XEVENT_TYPE_GESTURE_OVERRIDE`（对标 `QEvent::GestureOverride`），
  与既有 `XEVENT_TYPE_GESTURE` 并列。
  - **利好事实（L13 盘点实证）**：该事件号**已存在**——`XEventType.h:205` 定义
    `XEVENT_TYPE_GESTURE_OVERRIDE = 202`，但全库 `rg "GESTURE_OVERRIDE" Src/ Test/`
    **仅命中该常量定义一处，无任何投递路径**。即「仲裁事件号已预留，机制未实现」，
    仲裁机制落地时无需新增事件号，直接补投递路径即可。
- 手势对象需能回答「context 对象」与「hotSpot 全局坐标」——`XGesture` 增
  `m_context`（借用 XObject*）与 `m_hasHotSpot`/`m_hotSpot`（全局坐标）。

> **实现顺序约束**：本节依赖 §1.1（XGesture 活对象含 hotSpot）与 §1.3
> （XGestureEvent 信封），必须在其后落地；§1.2 的注册表也先于本节
> （管理器按注册表知道有哪些识别器类型）。

Qt 内置识别器源码位置：`qtbase/src/widgets/kernel/qgesture.cpp`
（`QPanGestureRecognizer` / `QPinchGestureRecognizer` / `QSwipeGestureRecognizer` /
`QTapGestureRecognizer` / `QTapAndHoldGestureRecognizer` / `QDoubleTapGestureRecognizer`）。

| 识别器 | Qt 判定要点 | 本库需核对/修正 |
|---|---|---|
| Pan | 阈值 `QApplication::styleHints()->mouseDragDistance()`（默认 10px）；`QPanGestureRecognizer::recognize` 判 delta 超阈值转 TriggerGesture；`setState` 迁移 Started/Updated/Finished/Canceled | 阈值来源应改为样式提示（现为硬编码 10px） |
| Tap | 位移容差 10px（Qt：`QTapGestureRecognizer::tapTimeout`/`maximum TapCount`，容差 = `QStyleHints::mouseDragDistance` 的 2 倍？）——**以源码为准，勿凭记忆** | 现 40px 容差与 Qt 源码核对 |

| Rotate | 角度变化检测；`totalRotationAngle` 累积 | 核对累积与归一 |
| Fling | **Qt 无独立 fling 识别器**（fling 在 QScroller / QFlickGesture 语义里，私有） | 本库 `XFlingGestureRecognizer` 属**专有扩展**：保留但**明确标注非 Qt API**，命名不要伪装成 Qt（建议 `XSwipeFlingRecognizer` 或加注释说明），否则违反「API 名对齐 Qt」 |

### 裁定修正（2026-10-30，主线程独立核查 Qt 源码后）

L02 台账判定 `XMenuBar_actionCount` / `XToolBar_actionCount` / `XToolBar_action`
三条「可删」，前提是「调用方改用 `actions()` 计数/索引」。**该前提不成立**：

| 事实 | 证据 |
|---|---|
| `XMenuBar` / `XToolBar` 的动作存在**各自容器** `m_actions`，与 `XWidget::m_actions` 是**两个不同容器** | `XMenuBar.h:57` / `XToolBar.h` 的 `m_actions` 成员；`XMenuBar_addAction`（`XMenuBar.c:584-596`）推入的是**自己的** `m_actions` |
| 故 `XWidget_actions((XWidget*)bar)` 返回的是**控件动作列表**（本库 MenuBar 为空），**拿不到菜单栏/工具栏的动作** | 语义不等价 |
| Qt 侧 `QMenuBar` / `QToolBar` **均无** `actions()` 公共 API | `qmenubar.h` / `qtoolbar.h` 无该声明；Qt 走 `QWidget::actions()`（空）+ `QMenu::menuAction()` 这类角色特定动作 |
| Qt `QMenu` 亦无 `actions()` 公共 API | `qmenu.h` 只有 `static QAction *exec(const QList<QAction*>&, ...)` |

**结论**：这三条不是「Qt 没有的冗余」，而是**本库专有但必要**的访问面（Qt 侧靠
`QWidget::actions()` + 角色特定 API 分散表达，本库集中在类自身）。**处置改为**：
1. **不删**这三条（删除会让调用方失去访问菜单栏/工具栏动作的途径）；
2. 另在 `XMenuBar` / `XToolBar` 补 `actions()` 访问器（返回各自容器的新建
   副本，语义与 `XWidget_actions` 一致），供新代码使用——**这一步是对齐 Qt
   「统一从 actions() 取动作列表」的使用习惯**，属补齐而非冗余；
3. 若后续要收敛现有 19 处调用点，应**改用新增的 `XMenuBar_actions()` /
   `XToolBar_actions()`**（而非 `XWidget_actions`），保持语义等价。

> 这条修正说明：**台账结论必须独立复核**——「前置依赖不存在」≠「前置依赖
> 补上就能删」，还要看**语义是否真的等价**。
