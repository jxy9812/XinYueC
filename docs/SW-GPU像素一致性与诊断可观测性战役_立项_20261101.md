## 0. 一句话

前序战役把 GPU 路径的 **CPU** 问题解决了（斜线绕行根除、重复上屏抑制、默认后端改回软件）；
本战役处理剩下的**画面与可观测性**问题：让软件光栅与 GPU 直通**渲染出同一张画面**
（当前差 877 px，其中 619 px 是结构性），并把「画面逐像素一致」这个**达不到的门槛**
改成可判定的口径；同时补齐让 V2/V4 可评的诊断能力。

## 1. 事实基线（2026-11-01 板端实测，非推测）

测量口径：`verify/xwd_mode_diff.py`（剔除同模式内的时变噪声——页面时钟——只报
**模式差异**像素与其最大通道差）；板端 RK3568，page 18（Modbus 从站），1000×700 窗口。

### 1.1 SW↔GPU 差异的三层分解

同一构建、三臂对照（最终数据）：

| 配置 | 模式差异像素 | Δ=1（混合舍入） | Δ≥8（结构性） |
|---|---|---|---|
| **改动前**（GPU 侧无 contrast LUT） | **30,833** | ~260 | ~30,570（直方图集中在 53~68 的中差值） |
| **改动后**（GPU 侧已施加 contrast LUT） | **850** | 241 | 609 |
| 改动后 + `XGPU_FASTPATH_EXT=0`（斜线回 Bresenham 同源） | **325** | 256 | 69 |

⇒ **文本分歧 30,833 → 850（−97.2%）**；斜线也切回同源后 → **325（−98.9%）**。

残差分层（改动后、斜线同源臂，325 px）：

| 类别 | 像素 | 归属 | 可否修复 |
|---|---|---|---|
| Δ=1（混合算术舍入） | 256 | SW 整数混合 vs GPU 硬件定点混合 | **不可修复**（§1.3） |
| 字形末行/包围盒差一行 | ~21 | 字形光栅**相位**：SW 在笔点位置光栅（覆盖含相位、包围盒随分数平移多一行），GPU 在 (0,0) 光栅（相位 0、包围盒少一行） | 可修（§2.1 A2） |
| 斜线/圆角硬边 | ~525（默认臂 609 − 同源臂差值） | GPU 轴向 quad 与软件 Bresenham 的端点/笔帽语义不同 | 可修（§2.2） |

### 1.2 三个根因（均已定位到代码行）

| # | 根因 | 证据 | 状态 |
|---|---|---|---|
| R1 | **文本覆盖对比曲线只在 SW 侧施加**。`painterTextContrastLut()`（γ + 带内提升包络，dpr 分档）在 SW 的三条字形链路都查：轮廓字混合端直写分支（`XPainter.c:11437`）、fallback 分支（`:11633`）、点阵 AA 链（`:10045`）；**GPU 侧上传原始 FT 覆盖、不查该表** ⇒ 每个 AA 边缘像素系统性地浅一档 | 板端样例：SW 灰 67/108 vs GPU 灰 128/161（有效覆盖差 ~0.26）；目视软件字形更饱满 | **已修**（30,833→877） |
| R2 | **几何抗锯齿（gridfit）只在 SW 侧施加**。SW 独有：笔点吸附（`roundf`）、笔画画吸附（`painterOutlineGridFitStrokesY`）、覆盖提升（中段 ×2 封顶 240）；GPU 路径的 `painterOutlineBuildPath(..., gridfit=false)` **恒关** ⇒ 字形几何与包围盒可差一行 | 残差 65 px 定位到字形末行：SW 该行无墨、GPU 有整段底横（x=651..659, y=99） | 待修（§2.1） |
| R3 | **斜线命令族在 GPU 侧走硬边 quad**（`XGPU_FASTPATH_EXT` 缺省开后的快速路径），与软件 Bresenham 覆盖非逐位一致：软件侧 1px 线是 Bresenham 阶梯，GPU 侧是宽度=线宽、端点沿方向外延半线宽的实心四边形（圆角=斜线段 ⇒ 圆角轮廓外扩 1~2px） | 关闭该开关差异 850→325 ⇒ 差值 525~609 px 即斜线硬边；目视：换边按钮的圆角，GPU 左端比 SW 长 2px | 待修（§2.2） |
| R4 | **GPU 字形路径丢失亚像素相位**：`painterGpuTextDevicePoint` 用 `(int)dx` 截断平移；GPU 图集按整数相位光栅（轮廓在 (0,0) 建），SW 在笔点位置光栅 ⇒ 分数落点下两者像素不同；字形**包围盒**还因此差一行（SW 的 ceil(penY+maxY) 多一行，GPU 的 ceil(maxY) 少一行） | 板端：字形末行整段缺失（SW 白 / GPU 有墨，21 px 结构差异）；修法=分数平移下 GPU 文本回退软件路径（与 SW 逐像素同源）——**已修**（该闸 CPU 代价实测为 0：7.1% vs 7.1%） | **已修**（`XGPU_TEXT_PHASE=0` 回退） |

### 1.3 一类**不可修复**的差异：混合算术舍入

SW 用整数混合（`painterComposeColor` / `mul255v`），GPU 用硬件定点预乘混合
（GL `(ONE, ONE_MINUS_SRC_ALPHA)`）。同一覆盖率经两条算术路径 ⇒ 边缘像素
**±1 灰阶**差异（实测：257 px 差值恰为 1；标题栏大字号样例差值直方图 `0:478, 1:2`）。

⇒ **「逐像素一致」在有 GPU 的构建上不可达**（除非让 SW 逐平台复刻各厂商硬件的
定点舍入——脆弱且无收益）。门槛必须改为**容差口径**（§3）。

## 2. 任务

### 2.1 A（主项）：几何口径统一（R2 + R4 的剩余部分）

**问题**：SW 的 gridfit 三件套（笔点吸附 / 笔画画吸附 / 覆盖提升）不在 GPU 路径，
⇒ 同一字形在两后端的**几何与包围盒**可差一行。

**方向**：

| # | 方案 | 说明 | 风险 |
|---|---|---|---|
| **A1** | **GPU 侧施加同一 gridfit 口径** | 把 SW 的三件套抽成可复用函数，SW/GPU 共用；GPU 侧在建轮廓后、FT 光栅前施加 | 中：gridfit 本身有「口不闭口/竖笔断裂」类历史副作用（2026-10-10 记录），且 SW 侧对 <20px 字号免网格 ⇒ GPU 侧须同口径 |
| A2 | **取消 SW 侧 gridfit** | 两侧都不做 ⇒ 口径统一，但**改变软件渲染观感**（细笔画变细、斜笔发虚），属产品可见变更 | 高：观感回归需用户确认 |
| A3 | **gridfit 视为 SW-only 并在文档固化** | 不追求逐像素一致，只保证「GPU 侧不劣化」 | 低，但放弃 V9 |

**建议**：先 A1（口径统一，且 SW 侧行为**零变化**——复用现有实现，只把调用点扩到 GPU 侧）。

**验收**：残差结构性像素 69 → ≤ 5；SW↔GPU 最大通道差 ≤ 1（除 §2.2 的斜线项）。

**已落地的 R4 部分**：分数平移下 GPU 文本回退软件路径（`XGPU_TEXT_PHASE` 缺省开）——
像素与 SW 同源，CPU 代价实测为 0（板端 7.1% vs 7.1%）。剩余的「包围盒差一行」需
在**相位已守恒**的前提下再定性（当前 21 px 分布于 4 处字形末行）。

### 2.2 B：A0 阶段二——斜线同源覆盖图直传（R3）

**问题**：斜线（非轴对齐）在 GPU 侧走硬边 quad，与软件 Bresenham 覆盖非逐位一致。

**方向**（前序实施记录 §4.1 已定方向，此处补口径）：给 Bresenham 循环加
「写 8bit 覆盖图」变体，GPU 侧经 `drawAlphaBitmap` 直传 FBO，
**与软件路径共用同一条光栅化** ⇒ 像素同源。

**验收**：`XGPU_FASTPATH_EXT=0/1` 两臂的 SW↔GPU 差异**收敛到同一量级**；
斜线相关的模式差异像素 → 0。

**跨平台要求**：全在 `Src/XGui/`（框架公共层），不碰 `Drive/`。

### 2.3 C：V9 验收口径修订 + 可跑的断言

**修订**：把「画面逐像素一致」改为：

> **结构一致 + 边缘容差**：同内容、同后端配置下，SW 与 GPU 的渲染结果
> 逐像素比对，**允许 AA 边缘像素 ±1 灰阶**；结构性差异（Δ≥8）必须为 0。

**理由**：§1.3——GPU 混合是硬件定点算术，逐像素一致不可达；硬扛「逐像素一致」
会逼出「让 SW 复刻某厂商硬件舍入」这类脆弱实现。

**配套断言**（新增回归，不依赖板端）：
新增 `xgui_regression_test.c` 用例：同一段文本/一组图元分别经 SW 与 GPU 渲染到
两张 XImage，逐像素比对，断言「Δ≥8 的像素数 = 0 且 Δ≤1 的像素占比在阈值内」。
GPU 侧无 GL 环境的变体按既有 `regression_gpuRequested()` skip 门跳过。

### 2.4 D：事件循环 lag 可观测性（V2 的前提）

**问题**：板端 `[WHEEL] lag=` 采样点太少（1s 级间隔、每统计窗仅数个样本），
⇒ V2「lag 中位 ≤20ms / p99 ≤100ms」**无法统计**。实测无论软件还是 GPU 形态都观测到
68~169ms（含启动首帧尖峰 742ms）。

**方向**：
- ① 提高采样率并明确 `lag` 的语义（是「事件循环单次迭代耗时」还是「距上次心跳的间隔」）
  ——**先澄清语义再动**（前序实施记录 §4.4 的结论）。
- ② 提供可离线统计的累计口径（p50/p95/p99 直方图，滚动窗口输出）。

**验收**：同一场景下能给出 ≥100 个样本的 p50/p95/p99；软件与 GPU 形态各自有结论。

### 2.5 E：V4 主站压测固化

把 PC 侧主站压测（`verify/mb_rtt_latency.py` + CH343 COM17）固化成可复跑脚本，
产出「主站请求/错误比」指标 ⇒ V4 可自动判定。

## 4. 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| **A1 引入 gridfit 到 GPU 侧后出现「口不闭口/竖笔断裂」**（SW 侧 2026-10-10 为此把小字号免网格） | 高 | A1 必须复用 SW 的**同款判据**（含 <20px 免网格、dpr 分档、密度字形钳制），不得简化；SW 侧行为零变化 ⇒ 观感回归风险仅限 GPU 路径 |
| **A1 使 GPU 字形图集条目随 gridfit 判据变化而失效** | 中 | gridfit 判据进图集键（与既有 flags 位扩展同款）；判据变化 ⇒ 换键换条目，旧条目自然淘汰 |
| **B 新增覆盖图分配**（每线一次）⇒ 泄漏风险 | 中 | 分配/释放严格配对（沿用现有 `XMalloc_System`/`XFree_System` 口径）；**泄漏门禁照旧跑**（板端 620s VmData/fd 恒定） |
| **C 口径放宽被当成「降低标准」** | 中 | 口径修订必须写明**理由与不可达性证据**（§1.3），并保留 Δ≥8=0 的硬门槛；不得整体放宽 |
| **D lag 语义澄清后指标反而不达标** | 低 | 本就未达标（68~169ms）；澄清语义只提高可评估性，不掩盖问题 |
| **几何改动波及面广**（gridfit 影响所有字形） | 高 | 分批：先只做「口径对齐」不做「观感调整」；板端逐页 xwd 比对 |
