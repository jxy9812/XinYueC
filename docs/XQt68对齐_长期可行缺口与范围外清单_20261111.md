## A. 【永久范围外（不可实现）】

判定标准：不是“还没排期”，而是**当前 C 架构/工具链下无法完整实现**；任何
“补一半”的接口都会变成会骗人的占位，故明确排除。每条给一句
“为什么 C 侧无法完整实现”，并列出当前已有的替代物（如有），避免误以为
完全空白。

> **2026-11-11 追加更正（用户口径）**：A4（文本栈）、A5（场景图）、A6（离屏表面）
> 原判“永久范围外”是**按工程量做的范围裁剪，不是技术不可能**。经用户追问后改为
> **“工程量大但可行，写入文档待后续执行”**，已移至 §B16–B18；下表 A4–A6 仅保留
> 历史判定记录并标注作废，不再作为排除依据。§A 真正生效的只有 A1–A3
> （语言/工具层不可等价项）。

| # | 条目（Qt 6.8 侧） | 当前 X 侧现状（证据） | 为什么 C 侧无法完整实现 |
|---|---|---|---|

| A6（已移至 §B18，作废） | `QOffscreenSurface::handle()`（`QPlatformOffscreenSurface*`）/ `nativeInterface()` 与平台离屏表面对象 | `XOffscreenSurface` 只承载 API 面：`create()` 仅置 `isValid` 标志，无真实平台表面（`XOffscreenSurface.h:15-27` 自述）；`XPlatformOffscreenSurface` 只是 GPU 后端的内部 FBO 宿主（`Src/XGui/Platform/XPlatformGraphics.c:27`、`:150-215`），**不与公共对象一一绑定**；头注释明确“不伪造这两个接口”（`XOffscreenSurface.h:23-26`） | 本库没有 `QPlatformSurface` 抽象层，也没有“公共表面对象 ↔ 平台原生表面”的所有权/生命周期模型；`handle()` 只能返回悬垂或别名指针，`nativeInterface()` 没有稳定的原生接口约定（eGPU/FBO/窗口系统句柄语义各不相同）。完整实现需要先建平台表面子系统（创建/销毁/重配/跨线程 makeCurrent 的所有权协议），且对嵌入式目标无收益——定为范围外，保留 `isValid/format` 的声明式差异。 |

## B. 【长期可行（本库可实现但工程量大）】

判定标准：C 侧可以实现、与现有架构兼容，但工作量/波及面超出“短期批”
（第三轮单批）。每条给：**现状与证据 → 依赖 → 估算规模 → 验收方式**。
排序按“业务价值 × 依赖清晰度”，不是排期承诺。

### B1. `QTimeZone` / `QCalendar`

- **现状**：`Src/XCore/XData/XDateTime` 只有 `XDate/XTime/XDateTime`，纯公历、
  本地时间口径；全仓无 `XTimeZone`（0 命中）、无 `XCalendar` 历法类（只有
  `XCalendarWidget` 控件）；`XDateTimeEdit_setTimeSpec` 只原样存取、不参与
  换算（`Src/XGui/Widget/README.md` 的 XDateTimeEdit 条目）。
- **依赖**：新增 `XTimeZone`（IANA tzdb 的 TZif v2/v3 解析，读
  `/usr/share/zoneinfo`；POSIX TZ 字符串解析作兜底）；`XDateTime` 增加
  “epoch 毫秒 + 时区”表示与转换；`XCalendar` 历法换算（儒略日 JDN +
  公历/可选历法表）；`XDateTimeEdit` 的 timeZone 属性联动与持久化。
- **估算规模**：约 1800–2800 行（tzdb 解析 500–800、时区缓存/转换 400–600、
  历法 500–700、控件绑定 400–700）+ 部署说明（板端 tzdata 路径/裁剪方案）。
- **验收方式**：
  1. 固定样本表与 Qt 6.8 对拍：UTC→各时区偏移、DST 进入/退出边界、
     历史偏移变更（如某年某地改标准时）；
  2. `XCalendar` 与 `QCalendar` 的样本日（公历/希伯来历/伊斯兰历）对拍；
  3. `XDateTimeEdit` 切换时区后“显示值→编辑值→回写”往返一致（字符串级）；
  4. 无 tzdb 环境：明确降级为本地时间并在状态行给诊断，不崩、不静默错。

### B2. `QModelIndex` / `QItemSelection` 值对象与树形层级模型

- **现状**：`XAbstractItemModel` 是平铺 (row,col)，`parent()` 恒 -1
  （`XAbstractItemModel.h:297-303`）；选择模型把格编码成 `(row<<16)|col`
  存 `XVector<int>`（`XItemSelectionModel.h:5-8`），**无 QItemSelectionRange
  值对象**；`XTreeWidget` 自带 item 树（`XTreeWidget.h:47-58`），但与
  `XAbstractItemModel` 不通。
- **依赖**：新增 `XModelIndex` 值类型（row/column/internalPointer/parent
  链）与 `XItemSelectionRange`；`XAbstractItemModel` 增加
  `index/parent/rowCount(parent)/hasChildren(parent)` 的树形重载；
  `XTreeView`/`XTreeWidget` 的模型桥改用 index；`XItemSelectionModel`
  改存 ranges（保留逐格查询的 O(1) 快路径）。
- **估算规模**：约 2500–4000 行（模型层 1200–1800、视图/树映射 1000–1600、
  选择模型 300–600）。
- **验收方式**：
  1. 三层树样本：`index→parent→child` 往返、无效索引（-1 行/列）语义与
     Qt 一致；
  2. `selection ranges` 与逐格选择的等价性（集合相等 + 顺序无关）；
  3. 现有 `XTreeWidget` 68 条 apitest 全绿（回归锁在
     `Test/XGuiDemo/xgui_demo_apitest_views.c:2140-2426`）；
  4. 排序/过滤后 index 的 internalPointer 不悬垂（ASan 一轮 + 稳定性断言）。

### B3. `XHeaderView` 自绘虚槽 / `sectionSizeFromContents`

- **现状**：`XHeaderView` 不覆写 `PaintEvent`（`XHeaderView.c:685-698` 只有
  对象槽 + 四个鼠标槽），表头由 `XTableView`/`XTableWidget` 自绘；
  `sectionSizeHint` 恒返回默认段尺寸、无内容感知（`XHeaderView.c:1998-2001`）。
- **依赖**：新增 `PaintSection` / `BoundingRect` 虚槽（对标
  `QHeaderView::paintSection`）与 `sectionSizeFromContents`（接模型
  `headerData` + 当前字体度量 + 排序指示器/高亮态）；`XTableView` 自绘
  路径改为优先调用表头虚槽（保留现自绘作缺省实现）。
- **估算规模**：约 500–800 行。
- **验收方式**：
  1. 独立摆放 `XHeaderView` 可见（当前“独立摆放不可见”，见 `XGui.md:1591-1593`）；
  2. `sectionSizeHint` 与 Qt 实测列宽差 ≤1px（按当前字体实测的样本表）；
  3. 表头像素与现状对拍（除新增样式差异外逐像素一致）；
  4. apitest 新增“派生表头覆写 paint 槽”用例。

### B4. `XTableWidget` 的 `selectionModel` 真接

- **现状**：`XAbstractItemView` 已有 `selectionModel()` 懒创建访问器
  （`XAbstractItemView.h:1174-1182`），但 `XTableWidget` 以**条目 selected
  位**为事实源（`XTableWidget.c:2925` 注释“施加选择命令到条目选中位”），
  `selectionModel` 未与条目双向桥接。
- **依赖**：selectionModel 的 ranges/current ↔ 条目 selected 位/当前格的
  双向同步；`selectionChanged`/`currentChanged` 转发到表格既有信号；
  防递归闸（同步中不重入）。
- **估算规模**：约 600–1000 行。
- **验收方式**：
  1. `selectionModel->select(ClearAndSelect/Rows/Columns/Toggle)` 后条目
     选中位与渲染一致；
  2. 反向 `setItemSelected`/`setCurrentCell` 后 selectionModel 查询一致；
  3. 无递归回调（同步入口计数器断言 = 1，ASan 不报栈溢出）；
  4. 现有表格 apitest/回归全绿。

### B5. `XItemDelegate` 的 `paint` / `sizeHint`

- **现状**：`XItemDelegate` 只承载编辑器生命周期五槽 + 三信号，头注释明写
  “绘制（paint/sizeHint）不在本批”（`XItemDelegate.h:5-12`）。
- **依赖**：新增 `XStyleOptionViewItem`（rect/state/font/palette/
  textElideMode/decoration 尺寸）、`Paint` / `SizeHint` 虚槽；`XTableView`/
  `XTableWidget` 自绘路径“先问 delegate、缺省回落现绘制”；role 消费补齐
  到 `FontRole`/`TextAlignmentRole`/`DecorationRole`/`SizeHintRole`。
- **估算规模**：约 700–1100 行。
- **验收方式**：
  1. 自定义 delegate 改字号/颜色/行高在 `XTableView`/`XTableWidget` 生效；
  2. 缺省 delegate 与现状像素一致（截图 dif ≤ 阈值）；
  3. `sizeHint` 参与行高与 `ResizeToContents` 列宽（数值断言）；
  4. QSS 与 delegate 同时设置时的优先级口径固定并锁测试。

### B6. `XMimeData` 驱动的 model/view 拖放

- **现状**：`XMimeData` 类已存在（`Src/XGui/Input/XMimeData.h`）；`XPlatformDrag`
  已有 Linux XDND / Windows OLE 的公共层（`Src/XGui/Platform/XPlatformDrag.h:4`）；
  `XAbstractItemView` 明确“拖放本体（dragEnter/dragMove/drop 与数据编码）
  不在本批，仅承载状态”（`XAbstractItemView.h:965-967`）。
- **依赖**：`XMimeData` 的 `mimeTypes/data/setData/clear` 完整化；
  `XAbstractItemModel` 的 `mimeData/dropMimeData/canDropMimeData/
  supportedDragActions/supportedDropActions`；`XAbstractItemView` 的
  dragEnter/dragMove/dragLeave/drop 虚槽 + 自动滚动 + 拖拽指示线；
  `XPlatformDrag` 双向接线（drag 发起/接受）与 dragAction 协商。
- **估算规模**：约 1800–3000 行（平台 600–900、模型 400–600、视图 800–1500）。
- **验收方式**：
  1. 同进程 list→table 拖放（CopyAction/MoveAction 各一）；
  2. 跨进程 XDND 拖文本/URI 进表格（外部客户端脚本发起）；
  3. `dropAction` 协商与 Qt 对拍（非法 action 拒绝）；
  4. 拖拽中 Esc 取消、源数据不被删除（Move 只在 drop 成功后删）。

### B8. `ScrollBar` transient / keypad / hover

### B9. `MDI` 图标排布 / Move-Size

- **现状**：`cascadeSubWindows`/`tileSubWindows` 已有（`XMdiArea.h:524-528`）；

- **依赖**：`arrangeIcons` 布局算法（最小化子窗图标网格、与 cascade/tile
  互斥状态）、八向边缘命中 + 光标 + resize 会话（复用现有 drag clamp 口径）、
  最大化/还原几何记忆。
- **估算规模**：约 700–1100 行。
- **验收方式**：
  1. 多子窗 `arrangeIcons` 后网格坐标/间距断言；

### B15. 网络 `FIONREAD` 其余后端

- **现状**：`XAbstractSocket` 的“引擎缓冲”只取
  `XDeviceNetworkProperty_ReadFinishedBytes`（异步读完成批次），**不查内核
  待读字节**；`FIONREAD` 只出现在注释（`XAbstractSocket.c:120-160`）；
  `XDeviceNetwork` 属性表无 PendingReadBytes（`XDeviceNetwork.h:449-451`）；
  仅 Win32 select 后端内部用了 `ioctlsocket(FIONREAD)` 三态判定
  （`Drive/windows/Device/Network/XDeviceNetwork_win32_select.c:14`、
  `XDeviceNetwork_win32.c:1403`）。
- **依赖**：`XDeviceNetwork` 增 `PendingReadBytes` 属性；posix 后端
  `ioctl(fd, FIONREAD)`、Win32 其余后端 `ioctlsocket(FIONREAD)`、
  lwip 后端按 `netconn` 可得信息返回（不可得则 0）；`XAbstractSocket`

  计数语义。
- **估算规模**：约 250–450 行（每后端 60–120）。
- **验收方式**：
  1. 对端连发 N 字节后**不 read**，`bytesAvailable()` ≥ 内核待读
     （posix / win32 IOCP / win32-select / lwip 各一组）；
  2. `readPaused`/读环满时不重复计数（现有 note 语义回归）；
  3. “完成包入队、SOCK_ACT 未派发”的假 EOF 用例不再触发；
  4. 后端不支持时返回 0、不改变现有行为（构建矩阵）。
