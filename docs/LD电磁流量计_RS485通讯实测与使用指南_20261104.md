# 上自仪 LD 系列电磁流量计 RS485 通讯实测与使用指南

> 📌 **本文的协议与实测数据已并入 `docs/HSF板端ttyS4三设备取数实测总表_20261109.md`**（现场三台
> 设备合并文档）。本文保留作为 LD 流量计的单机完整协议参考（含手册与实测的差异清单 §7、
> 探针脚本说明 §10）。2026-11-09 复测确认本文结论全部成立：FC04/FC03 均可读且值一致、
> 参数区只能逐点单读、空管报警置位、单位码 5/1。

> 依据《电磁流量计 485 通讯协议》（L_mag B 系列转换器 Modbus 协议 V101 / 2021-11-17）编写，
> 全部数据为 **2026-11-04 在实机上实测标定**（CH340 USB-485 转换器，`COM18`）。

## 一、测试环境

| 项目 | 实测值 |
|---|---|
| 仪表 | 上自仪 LD 系列电磁流量计（L_mag B 系列转换器，Modbus-RTU 从站） |
| 通讯接口 | RS485，端子 **TRX+ / TRX-**（即 485 A/B） |
| 主站设备 | PC + CH340 USB-485 转换器，`COM18` |
| 波特率 | **9600 bps**（参数 0x0002 读回 = 5 → 9600，见 5.1） |
| 数据格式 | **8N1**（无校验、1 位停止位；参数 0x002F 读回 = 0） |
| 从站地址 | **5**（参数 0x0001 读回 = 5） |
| 介质状态 | **管道空管**（未充液），流量恒为 0、电导比在 3301~3302 浮动 |
| 测试工具 | Python 3.12 + pyserial 3.5 |

### 1.1 接线

| 仪表端子 | 接 485 转换器 | 说明 |
|---|---|---|
| TRX+ | A（D+） | 通讯正 |
| TRX- | B（D-） | 通讯负 |
| TCOM | 不接 | 仅 RS232 模式需要（通讯地） |

> 411 一体式系列对应端子为 `T+` / `T-`，211 分体式与 511 一体式标注 `TRX+` / `TRX-`。
> 无应答时先对调 A/B 再排查其他。

### 1.2 Modbus 是选配

订货型号「输出信号」栏须带代码 **M**（4-20mA + 脉冲/频率 + ModBus）。若铭牌为 `S`（无通讯）
或 `N`（无输出），TRX 端子上没有 Modbus，只能走 IOUT 的 4-20mA。

## 二、协议帧格式

**本机实现是标准 Modbus-RTU**：帧结构、CRC16（init `0xFFFF` / poly `0xA001`，低字节先上线）、
设备地址、功能码语义、异常码全部符合规范，**未发现任何非标准改动**。

### 2.1 变量区读命令 FC04

```
请求: [设备地址] 04 [寄存器地址H] [寄存器地址L] [寄存器数H] [寄存器数L] [CRCH] [CRCL]
应答: [设备地址] 04 [字节数] [数据...] [CRCH] [CRCL]
```

### 2.2 参数区读/写 FC03 / FC06

```
读请求: [设备地址] 03 [寄存器地址H] [寄存器地址L] [寄存器数H] [寄存器数L] [CRCH] [CRCL]
写请求: [设备地址] 06 [寄存器地址H] [寄存器地址L] [数据H] [数据L] [CRCH] [CRCL]
```

### 2.3 异常应答

实测异常帧格式符合标准 Modbus：

```
05 83 01 xx xx      ← FC03 异常，功能码置 0x80，异常码 0x01（非法功能/地址）
       ↑ ↑  ↑
       │ │  └─ 异常码
       │ └──── 功能码 | 0x80
       └────── 设备地址
```

> 实测证据：`FC03 读 0x0047` 返回 `05 83 01 ...`，功能码**正确置了 0x80**。
> 这一点与 M512 变频器不同（M512 的 8 字节错误帧不置 0x80，见
> `docs/M512M513_变频器RS485通讯实测与使用指南.md` 11.x）。本仪表可以直接用标准库的
> 异常处理路径。

## 三、一帧读全部变量（核心结论）

> **结论：`05 04 10 10 00 16` + CRC 一条帧即可取回全部 22 个变量寄存器，实测稳定可靠。**

### 3.1 请求帧

```
05 04 10 10 00 16 75 45
│  │  │     │     └─ CRC16 (低字节先上)
│  │  │     └─────── 寄存器数 = 22 (0x0016)
│  │  └───────────── 起始地址 0x1010
│  └──────────────── 功能码 04
└─────────────────── 设备地址 5
```

### 3.2 实测应答帧

```
05 04 2C 00 00 00 00 00 00 00 00 00 00 00 00 45 4E 60 00 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 05 00 01 00 00 00 00
00 01 00 00 FB 0C
```

`2C` = 44 字节 = 22 个寄存器 × 2。CRC `FB 0C` 校验通过。

### 3.3 连读上限实测

从 `0x1010` 起尝试不同读数，**全部成功**：

| 请求寄存器数 | 结果 |
|---|---|
| 2 / 8 / 16 / 22 | OK |
| 23 / 30 / 64 / 100 / **125** | OK |

> **125 个寄存器（协议规范上限）仍能一次读回**。22 个变量远在能力范围内，
> 单帧读取没有压力。

## 四、变量寄存器表（FC04，0x1010~0x1025）

全部数据**大端、无字交换**。厂家文档里「Float Inverse」「Long Inverse」的命名具有误导性，
按标准大端 IEEE754 / 大端整型直接解析即可（文档自身示例可证：`C4 1C 60 00` = −625.5）。

| 寄存器 | 十进制 | 格式 | 内容 | 本机实测值 |
|---|---|---|---|---|
| 0x1010/0x1011 | 4112/4113 | F32 | 瞬时流量 | 0.0000 |
| 0x1012/0x1013 | 4114/4115 | F32 | 瞬时流速 | 0.0000 |
| 0x1014/0x1015 | 4116/4117 | F32 | 流量百分比 | 0.00 |
| 0x1016/0x1017 | 4118/4119 | F32 | 流体电导比 | **3301~3302**（空管态浮动） |
| 0x1018/0x1019 | 4120/4121 | U32 | 正向累积**整数部分** | 0 |
| 0x101A/0x101B | 4122/4123 | F32 | 正向累积**小数部分** | 0.0 |
| 0x101C/0x101D | 4124/4125 | U32 | 反向累积整数部分 | 0 |
| 0x101E/0x101F | 4126/4127 | F32 | 反向累积小数部分 | 0.0 |
| 0x1020 | 4128 | U16 | 瞬时流量单位 | **5 → M3/H** |
| 0x1021 | 4129 | U16 | 累积总量单位 | **1 → M3** |
| 0x1022 | 4130 | U16 | 上限报警 | 0 |
| 0x1023 | 4131 | U16 | 下限报警 | 0 |
| 0x1024 | 4132 | U16 | 空管报警 | **1（报警中）** |
| 0x1025 | 4133 | U16 | 系统报警 | 0 |

### 4.1 累积量必须两段拼装

正向/反向累积量是 **整数部分（U32）+ 小数部分（F32）** 两段，不是单个 64 位整型：

```python
total = ((regs[8] << 16) | regs[9]) + f32(regs[10], regs[11])   # 正向
total = ((regs[12] << 16) | regs[13]) + f32(regs[14], regs[15]) # 反向
```

### 4.2 瞬时流量单位代码表（0x1020）

| 代码 | 单位 | 代码 | 单位 | 代码 | 单位 |
|---|---|---|---|---|---|
| 0 | L/S | 4 | M3/M | 8 | T/H |
| 1 | L/M | 5 | **M3/H** | 9 | GPS |
| 2 | L/H | 6 | T/S | 10 | GPM |
| 3 | M3/S | 7 | T/M | 11 | GPH |

> 本机 = 5（M3/H）。**0x1020 是仪表侧可改的**，程序不能把单位写死，必须随数据读上来做标度。

### 4.3 累积总量单位代码表（0x1021）

| 代码 | 单位（B 型 / 511 型）|
|---|---|
| 0 | L |
| 1 | **M3**（本机） |
| 2 | T |
| 3 | USG |

> **C 型转换器**为 0~11，其中代码 0~11 每 4 个一组表示同一单位的三种精度档 + 基础档
> （如 0/1/2 = L 的 0.001/0.01/0.1 档，3 = 1L；4/5/6 = M3 的各档…）。
> 本机为 B 型口径（0~3），实测代码 1。

## 五、参数寄存器（FC03 读 / FC06 写）

### 5.1 本机实测参数值

| 地址 | 名称 | 实测值 | 解释 |
|---|---|---|---|
| 0x0000 | 语言 | 0 | 中文 |
| 0x0001 | 仪表通讯地址 | **5** | 与扫描结果一致 |
| 0x0002 | 仪表通讯速度 | **5** | 代码 5 = **9600 bps** |
| 0x0003 | 测量管道口径 | 9 | 代码 9 = 32mm（见表 4-4）|
| 0x0006 | 流量单位 | 5 | M3/H |
| 0x0007 | 测量阻尼时间 | 3 | 04 SEC |
| 0x000A | 流量积算单位 | 7 | 1 M3 |
| 0x000C | 电流输出类型 | 0 | 4mA |
| 0x0012 | 频率输出范围 | 5000 | — |
| 0x001F | 出厂标定系数 | 8822 | — |
| 0x0026 | 励磁方式选择 | 10000 | ⚠ 超出文档 0~2 的选项范围 |
| 0x002F | 通讯校验模式 | **0** | 无校验 + 停止位 1 |

### 5.2 波特率代码对照（0x0002，表 4-3）

| 代码 | 波特率 | 代码 | 波特率 | 代码 | 波特率 |
|---|---|---|---|---|---|
| 0 | 300 | 3 | 2400 | 6 | 14400 |
| 1 | 600 | 4 | 4800 | 7 | 19200 |
| 2 | 1200 | 5 | **9600** | 8 | 38400 |

实测波特率扫描（逐个波特率试读同一帧）：

| 波特率 | 结果 |
|---|---|
| 1200 / 2400 / 4800 | 无响应 |
| **9600** | **有响应** |
| 19200 / 38400 | 无响应 |

与参数 0x0002 = 5 完全对应。

### 5.3 校验模式代码对照（0x002F，表 4-24）

| 代码 | 模式 |
|---|---|
| 0 | **无校验 + 停止位 1**（本机）|
| 1 | 奇校验 + 停止位 1 |
| 2 | 偶校验 + 停止位 1 |
| 3 / 4 / 5 | 同上但停止位 2 |

### 5.4 写参数必须先写密码（未实测，据文档）

据协议文档 4.x：

1. 先向 **0x003F** 写入密码 `19818`（`0x4D6A`）
2. 再写目标参数寄存器（FC06）
3. 总量清零：向 **0x0047** 写入 `0xA55A`（`42330`）

> 本次**未执行任何写操作**（只读采集，避免误改现场仪表配置）。

### 5.5 ⚠ 参数区不支持连读

实测：**无论请求多少个寄存器，参数区永远只返回 1 个**：

```
请求 05 03 00 00 00 02 → 应答 05 03 02 00 00 49 84   (1 个寄存器)
请求 05 03 00 00 00 04 → 应答 05 03 02 00 00 49 84   (仍是 1 个)
请求 05 03 00 00 00 16 → 应答 05 03 02 00 00 49 84   (仍是 1 个)
```

字节数字段恒为 `02`。**参数区必须逐点单读**，这与变量区可以一次读 22 个形成鲜明对比。

## 六、功能码与地址空间实测

| 测试 | 结果 | 结论 |
|---|---|---|
| FC03 读变量区 0x1010 | **成功**，值与 FC04 完全一致 | 变量区**两种功能码都能读** |
| FC04 读参数区 0x0001 | 无应答 | 参数区**只吃 FC03** |
| FC03 读 0x0000 起 N 个 | 恒返回 1 个 | 参数区不支持连读 |
| FC03 读 0x0046（0x0047 前一个） | 成功 | 参数表边界正常 |
| FC03 读 0x0047 | 异常 `0x83 0x01` | 0x0047 不可读（只写寄存器）|
| FC03 读 0x0048 | 异常 `0x83 0x01` | 已越出参数表 |
| FC03 读 0x0100 / 0xFFFF | 无应答 | 远越界 |
| FC04 读 0x1026 / 0x1030 | 成功 = 0 | 变量区**越界不报错，静默返回 0** |
| FC04 读 0x1100 | 无应答 | 远越界 |

> **两条实务结论**：
> 1. **变量区越界会返回 0 而不是异常**——按固定布局读错地址时不会报错，只会读到 0，
>    排查"数据恒为 0"时要考虑地址是否写错。
> 2. **FC03 也能读变量区**，所以如果现场只有一个库只支持 FC03，仍然可以读变量，
>    只是要走参数区的"单点读"路径（每个变量单独一帧，效率低）。

## 七、手册与实测的差异

| # | 手册说法 | 实测 | 影响 |
|---|---|---|---|
| 1 | 「变量区使用 04 号功能码」 | **FC03 也能读，值完全一致** | 正面：兼容性更好 |
| 2 | 「参数区使用 03 号功能码」「地址表 0x0000~0x0047」 | FC03 读参数区**只能单点**，且 0x0047 本身返回异常 | 需逐点读；0x0047 只写 |
| 3 | 参数表 4-19「尖峰抑制系数」等行 | 表格有多处**列错位**（见 7.1） | 以十进制地址列为准 |
| 4 | 0x0013「电流零点修正」的 HEX 列写作 `0x000E` | 与下面的 0x0014 撞号，应为 `0x000D` | 照抄 HEX 列会写错地址 |
| 5 | 第五章示例：瞬时流量 `−185.85` | 用同帧真实字节 `C3 36 D9 9A` 解出是 **−182.85** | 示例算术错误 |
| 6 | 第五章示例：电导比 `1.68` | 用 `42 64 00 00` 解出是 **57.0** | 示例数字错误 |
| 7 | 1.1 节「支持波特率 1200~19200」 | 表 4-3 列到 38400；实测 9600 | 以参数表为准 |
| 8 | 0x0026 励磁方式「0/1/2」 | 本机读回 **10000** | 疑为不同固件版本，该点不可按文档解释 |

> **总原则：只信表结构（地址/格式/顺序），不信示例数字。**

## 八、接入本框架（XFlowMeter）

本仓库已实现设备类 `Src/Industry/XFlowMeter/`，可直接用于本仪表。

### 8.1 装配（一条帧、22 个 role）

role 0..21 与 22 个寄存器一一对应，高字在前：

```c
static const XChannelPointBinding s_ldBindings[] = {
    /* 瞬时流量 F32 */
    { XFlowMeterRole_InstantFlowHi,  0x1010, XModbusLink_hubAreaType(3), XIoPoint_AnalogInput, 0, 1, 1, 0, "FlowHi" },
    { XFlowMeterRole_InstantFlowLo,  0x1011, ... },
    /* … 其余 20 个按 XFlowMeterRole 顺序铺开 … */
};
```

### 8.2 三个必守约束

1. **32 位量的两个 role 必须相邻且高字在前**——设备类按 `(role, role+1)` 成对读取。
2. **这两个点的标度必须是恒等（1/1/0，signed=false）**——否则标度运算会破坏 IEEE754 位模式。
   标度换算只能发生在拼成 float 之后。
3. **变量区单位（0x1020/0x1021）必须随数据读上来做标度**，不能写死。

### 8.3 一致性保证

一帧应答由 Hub 整块回填、整块发信号，故同一帧内所有寄存器是**同时刻快照**。
设备类据此用 `XIoLink_readRole_base` 读两个字的原始值再拼装，**不会出现「新高位 + 旧低位」**。
不要改成"逐字读点缓存"——块回填按地址升序，收到高字事件时低字可能还是上一帧的值。

### 8.4 验证命令

```
XinYueC_Static.exe --test xindustry-flowmeter
```

覆盖：32 位拼装（用协议示例帧逐字节验证）、单位/报警解析、质量陈旧翻转、
成对缺失拒绝、编解码往返、300 轮泄漏压测。

## 九、现场快速排障清单

按顺序排查（从最常见的开始）：

| # | 检查项 | 命令/方法 |
|---|---|---|
| 1 | 铭牌「输出信号」是否为 **M** | 看铭牌；S/N 则无 Modbus |
| 2 | TRX+ / TRX- 是否接反 | 对调 A/B 再试 |
| 3 | 从站地址 | 扫 1~99：`ldprobe.py --scan` |
| 4 | 波特率 | 参数 0x0002 读回，或逐档试（1200~38400）|
| 5 | 校验模式 | 参数 0x002F，实测本机 0 = 8N1 |

| 7 | 空管报警 | 0x1024 = 1 说明未充液，流量恒 0 属正常 |
| 8 | 数据恒为 0 | 变量区越界**不报错**，先确认地址没错 |

## 十、附录：探针脚本

本次实测脚本（Python 3.12 + pyserial），位于 `verify/ld_meter/`：

| 脚本 | 用途 |
|---|---|
| `ldprobe.py` | 单帧读全部变量 + 解析 + 地址扫描 |
| `ldstream.py` | 连续采样，验证稳定性与数据变化 |
| `ldparam.py` | 参数区读取 + 连读上限 + 交叉访问验证 |
| `ldextra.py` | FC03/FC04 等价性 + 边界 + 波特率扫描 |

用法：

```bash
python -I verify/ld_meter/ldprobe.py  --port COM18 --baud 9600 --addr 5
python -I verify/ld_meter/ldstream.py --port COM18 --addr 5 --seconds 20
python -I verify/ld_meter/ldparam.py  --port COM18 --addr 5
python -I verify/ld_meter/ldextra.py  --port COM18 --addr 5
```

### 10.1 最小可复现脚本

```python
import struct, serial

def crc16(data):
    c = 0xFFFF
    for b in data:
        c ^= b
        for _ in range(8):
            c = (c >> 1) ^ 0xA001 if c & 1 else c >> 1
    return bytes([c & 0xFF, c >> 8])

def f32(hi, lo):
    return struct.unpack('>f', struct.pack('>HH', hi, lo))[0]

port = serial.Serial('COM18', 9600, bytesize=8, parity='N', stopbits=1, timeout=1)

# 一条帧读全部 22 个变量
body = struct.pack('>BBHH', 5, 0x04, 0x1010, 22)
port.write(body + crc16(body))
resp = port.read(49)          # addr+fc+bytenum + 44 数据 + crc16
port.close()

regs = [struct.unpack('>H', resp[3+2*i:5+2*i])[0] for i in range(22)]
print('瞬时流量 =', f32(regs[0], regs[1]))
print('正向累积 =', ((regs[8] << 16) | regs[9]) + f32(regs[10], regs[11]))
print('单位代码 =', regs[16], regs[17])
print('空管报警 =', regs[20])
```

实测输出：

```
瞬时流量 = 0.0
正向累积 = 0.0
单位代码 = 5 1
空管报警 = 1
```
