## 二、两台浊度仪分开设置（本轮重点）

### 2.1 用户口径与结论

> 「两台浊度仪要可以分开设置，他们是两台设备。」

现场两台是**独立设备**，型号/字节序/周期都不同：

| 台 | 站号 | 型号 | 字节序 | 读取 | 温度 |
|---|---|---|---|---|---|
| 浊度仪1 | 1 | WZT-701A | CDAB | 2 字 | 无（缺 `temp` 键） |
| 浊度仪2 | 3 | ZHEYI-5100ZDY | DCBA | 4 字 | 有（同刻快照） |

因此开关与周期都必须逐台：可能只装一台、或单独停一台检修。
此前「两台共用 `turbidityEnabled`、勾一台同步另一台」的临时口径**作废**。

### 2.2 协议键与回落链

`common/XhsfLinkProto.h` 与 `server_py/hsfsrv/proto.py`、
`client_py/hsfsrv_client/proto.py` 三处同值同键：

```c
#define HSF_CFGK_TURBIDITY_ENABLED  "turbidityEnabled"   /* 共同缺省（兼容） */
#define HSF_CFGK_TURBIDITY1_ENABLED "turbidity1Enabled"  /* 浊度仪1（站1） */
#define HSF_CFGK_TURBIDITY2_ENABLED "turbidity2Enabled"  /* 浊度仪2（站3） */
```

回落链：`turbidityNEnabled → turbidityEnabled → 编译期 HSF_BUS_B_ENABLED`。
旧配置文件/旧客户端只有共同键时，两台照它跑（向后兼容）。

### 2.3 Python 服务端（`server_py/hsfsrv/`）

- `config.py`：新增 `enable_turbidity1/2`；`load()` 先按旧共同键铺开、再由
  逐台键覆盖；`save()` 同时落三键（旧键写「任一启用」）；`turbidity_enabled(idx)`
  统一判定（逐台优先，回落共同键）。
- `app.py`：**设备对象无论开关都建**（逐台开关只门控轮询）——运行期改开关后
  `restart_polling()` 立刻生效，停采的台不会整组消失；`start_polling()` 逐台
  门控，只停一台时另一台照采；sim 下停用的台不建虚拟模型（读它只会超时，
  与真机未接一致）；健康表停用的台文字报 **「已停用」**，不伪装掉线。
- 配置收发：`_config_collect_doc()` 报三个键（旧键=任一启用）；
  `_cfg_set_collect_key()` 接受逐台键；`CFGK_TURBIDITY_ENABLED` 的扇出
  **放在 handler 按整条载荷判定**——同一 SET 里既有逐台键又有共同键时以
  **逐台为准**。原因：新客户端为兼容旧服务端会把共同键当「任一启用」一起发，
  若按键逐个扇出，会把刚停的台又盖回开（B3c 实测红后根修）。

### 2.4 C 服务端（`server/HsfServerIo.*` / `HsfServerApp.c`）

- `HsfCollectConfig` 增 `turbidity1Enabled/turbidity2Enabled`；
  `hsfIoCollectFromIni()` 读 `collect/turbidity{1,2}Enabled`，缺键回落
  `collect/turbidityEnabled`，再回落 `HSF_BUS_B_ENABLED`。
- **停用的实现**：`XModbusHubUnitLimits` 没有 enabled 字段，`hubUnitDue()`
  只按 `now-last >= m_minPollIntervalMs` 判到期 ⇒ 停用＝把该从站最小发送
  间隔顶到 `HSF_IO_UNIT_DISABLED_MS`（`0x7FFFFFF0`，≈24.8 天），静默不读；
  另一台照常按自己的周期采，且不参与「设备节拍取最紧」；重新启用同一入口
  写回正常周期即可，不必重建组/链路。
- 配置 GET 报三个键（旧键=任一启用）；SET 的 `kBoolKeys` 接受逐台键；
  旧共同键单独出现时同步写逐台 INI 键（旧客户端视作「两台一起」）。
- 注：C 端健康由 Hub 数据新鲜度推导，停用的台显示数据过期/离线
  （与 Python 的「已停用」文字不同，属已知口径差异，见 §十）。

## 三、运行模式与按钮灯规则（用户定案，两端同口径）

1. **手动模式不跑自动程序 ⇒ 按钮组灯归人工**：服务端按钮站只在**自动模式**
   跟随运行态写灯；手动模式自动逻辑一个 DO 都不写（采集/急停/停止照做）。
2. **切换模式 ⇒ 关闭所有设备**（手动⇄自动**双向**）；同一模式重复下发不动设备。
3. **只有按「启动」后设备才允许工作**：模式开关只是授权，切自动**不**启动
   控制器（自动运行位保持「已停止」）。

## 十一、温湿度「数据过期」板端实测（A/B 修复前 vs 修复后）

现场症状：温湿度采集周期调到 10s/1min 后，主界面温湿度在「有值 ↔ --」
之间来回抖、报警页同步刷「数据过期」。

### 根因（两层口径不一致，缺一不可）

| 层 | 修复前 | 修复后 |
|---|---|---|
| 设备层阈值（`XTempHumTransmitter_setStaleMs`，随周期算） | 30000ms | 30000ms |
| **站点层质量判定**（`temphumEvaluateQuality`） | **写死宏 `HSF_TEMPHUM_STALE_MS`=5000ms** | 用 `m_staleMs`（= 周期×3） |

修复前设备层已是 30000（所以遥测帧里 `staleMs` 回读就是 30000，看着
「阈值已经对了」），但**站点层判陈旧仍用 5000ms 的编译期宏** ⇒ 10s 周期
下每拍有 5s 落在阈值内 ⇒ 服务端把 `tempValid/humValid` 报 false ⇒
客户端显示 `--`、报警页判「数据过期」。这是「回读值对、行为错」的典型：
查 `staleMs` 字段看不出问题，必须看**有效位在两拍之间有没有翻 false**。

### 板端 A/B 实测（板 192.168.1.249，ttyS3 路 A，采集周期 10s，采样 40s）

| 二进制 | 有效帧 / 无效帧 | 回读 staleMs | 判定 |
|---|---|---|---|
| 修复前（`HsfServer.bak-20261110-204817`，19:47 构建） | 33 / **43** | 30000 | ✗ 界面闪 `--` |
| 修复后（现役） | **77 / 0**（另一次 49 / 0） | 30000 | ✓ 全程有值 |

服务端日志第一手证据：
`HsfServerIo: 陈旧阈值已随周期联动（温湿度=30000 浊度1=5000 浊度2=5000 流量计=5000 ms）`

### 新增一键链路（板端 编译→部署→复检）

| 脚本 | 位置 | 职责 |
|---|---|---|
| `Tools/posix/hsf-board-deploy.sh` | 仓库（Windows Git Bash 入口） | 同步工作区→WSL 交叉编译→scp 部署→板端重启→复检，一条命令 |
| `verify/board/build_board.sh` | 仓库（WSL 内） | HSF aarch64 交叉编译（端口宏 `-D` 注入，端口变了强制重配） |
| `verify/board/restart_c_stack.sh` | 仓库（板上执行） | 板端 C 栈起停（server/client/stop/stop-client） |
| `verify/board/verify_temphum_stale.py` | 仓库（客户端侧，零 Qt 依赖） | 温湿度「数据过期」复检：连盯 N 秒，判「有效值之后不得再有无效帧」 |

用法：`Tools/posix/hsf-board-deploy.sh`（板 192.168.1.249:6100，路 A
`/dev/ttyS3`、路 B `/dev/ttyS4`）。

坑（已固化进脚本）：

- **正在运行的二进制不能被 scp 直写**（`dest open ...: Failure` = ETXTBSY）
  ⇒ 部署前先停服务端，或先传 `.new` 再 `mv` 覆盖；
- **板端 C 栈没有 systemd 单元**（只有 `hsfserverpy`/`hsfclientpy` 两个
  Python 服务）⇒ 重启脚本按手工 `nohup` 的原口径来；
- **同账并发默认关** ⇒ 板端客户端在线时同账号再登被拒 ⇒ 复检前只停
  客户端（**不能停服务端**，否则采不到帧），复检后再拉起来；
- **`pkill -f` 会误杀远端 shell 自身**（命令行里出现目标进程名就中招，
  2026-11-10 实锅一次）⇒ 改用 `pkill -x`（按进程名精确匹配）；
- 部署用 Windows 侧 scp（WSL 里没有 askpass 凭据会卡在口令输入）。

## 十二、四个现场问题并发修完（板端逐项验收）

| 问题 | 根因 | 修法 | 板端验收 |
|---|---|---|---|
| 变频器数值「---」与真值循环闪 | Hub **每拍只发一个读组** ⇒ 数据刷新节拍 = 轮转一圈（组数 × 拍长 ≈ 2.8s），而快照缺省陈旧阈值是「发布周期 × 5」=1s ⇒ 盖不住一圈，每隔两拍掩码清零 | `XVfdDevice` 增 `m_staleMs` + `setStaleMs/staleMs`；`HsfServerIoVfd_applyStaleMs` 按「组数 × Hub 真实拍长 × 2」算；新增 `XModbusHub_pollInterval` 取真实拍长 | `verify_vfd_fresh.py`：修复前 283 帧全缺字段 → 修复后 133/133 全带值 |
| 历史表格「共 0 行」+ 停在「读取中」 | 板端 `storage/enabled=0` ⇒ 服务端回**失败包络**；客户端把它当分页文档解析 ⇒ 只剩 0 行，且看不到原因 | 客户端补 `HsfConfig.m_storagePresent`（没收到就不写这节）+ `HsfHistoryPage.m_error`（失败包络原文上状态行）+ 落盘勾选框缺省勾上；板端重开落盘 | 历史页 **共 2001 行**、行内含水温 19.4℃；落盘已恢复写入 |
