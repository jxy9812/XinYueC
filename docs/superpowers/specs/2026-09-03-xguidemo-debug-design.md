# XGuiDemo 分阶段调试设计

## 目标

在当前 Linux/X11 环境中，对 `XGuiWindowDemo_Test` 建立可复现的控件行为与渲染性能基线，逐项验证现有演示控件，修复由测试证据确认的不合理行为，并定位帧率从历史稳定 1w+ 降至几千的具体控件或公共绘制回归。

## 范围

覆盖 Demo 当前可见功能：页面导航按钮、普通按钮与信号联动标签、命令链接按钮、工具按钮及弹出菜单、三态复选框、互斥单选按钮、内层堆叠布局、性能悬浮层、窗口缩放/Expose/关闭，以及静态场景缓存和逐 tile 绘制路径。现有 `XGuiRegression_Test` 负责可自动断言的控件语义；真实 X11 窗口和截图负责平台链路与视觉行为。

不在第一阶段引入新控件或重构 XGui 公共架构，不以历史文档中的单一 FPS 数值直接作为当前验收标准。

## 测量定义

固定窗口尺寸、显示后等待稳定期、字体配置、刷新间隔和后台网络状态。至少同时记录：

- Demo 内部完成的刷新/绘制循环次数，作为高频循环性能指标；
- `XPerformanceOverlay` 的统计 FPS 和帧耗时，作为实际窗口渲染指标；
- 进程 CPU 时间或采样 CPU 占用；
- 标准错误输出、退出码和截图结果。

所有对照实验只改变一个变量。性能结论必须来自全场景与单控件禁用/替换对照，不能仅凭源码猜测。

## 分阶段方案

### 阶段一：基线

确认构建配置和运行环境，运行 `XGuiRegression_Test`，运行 `XGuiWindowDemo_Test` 的自动退出模式，并在可用 X11/Xvfb 下保存固定窗口截图和性能日志。确认计数器的来源、采样窗口和静态缓存是否有效。

### 阶段二：控件验证

按 Demo 页面建立操作矩阵：导航与堆叠索引、按钮点击和信号文本、三态循环、单选互斥、工具按钮菜单动作、窗口重绘和缩放、悬浮层固定/拖动/显示开关。每个行为要么有回归断言，要么有可复现的人工步骤和截图证据。

### 阶段三：性能归因

增加默认关闭或测试专用的细粒度计时/计数，不改变正常渲染语义。依次比较完整场景、每个页面、控件绘制关闭、悬浮层关闭、静态缓存关闭和公共绘制路径，输出每项的循环数、耗时和差值，定位最大回归来源。

### 阶段四：修复与复测

对每个确认的行为缺陷先添加能失败的最小回归测试，再实现最小修复。性能修复单独验证，不混入无关重构。完成后重新构建、执行 CTest/回归、运行 Demo 自动退出和真实 X11 截图，并在调试记录中保留基线、根因、修复前后数据及残余限制。

## 错误处理与环境限制

无 DISPLAY、Xvfb 不可用或窗口后端未编译时，区分“环境无法执行”与“程序行为失败”，保留源码级和自动回归证据，不伪造实窗结论。既有与本任务无关的 CJK/LVGL 或裁剪配置失败单独记录，不扩大修复范围。

## 验收标准

1. 控件行为矩阵中的每项都有通过的自动断言或可重复的实窗证据。
2. 每个生产修复都有先失败后通过的回归测试，且不破坏已有 XGui 回归。
3. 帧率下降能归因到具体控件、悬浮层、缓存策略或公共绘制路径；若受当前硬件/显示服务器限制不能恢复到历史数值，必须给出统一口径下的对照数据和剩余环境差异。
4. 最终构建和验证命令、退出码、失败项与截图/日志路径均可追溯。

## 约束

遵循仓库根目录《代码风格，类的创建，虚函数的重载注意，api命名风格和注意事项.md》；保持纯 C、现有 XClass/XWidget 继承和虚表模式；不保留用户明确要求删除的旧接口或回调；不覆盖工作树中与本任务无关的用户改动。
