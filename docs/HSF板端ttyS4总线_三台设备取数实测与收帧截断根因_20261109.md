# HSF 板端 ttyS4 总线：三台设备取数实测与收帧截断根因

> ⚠️ **本文档的「取数部分」已被 `docs/HSF板端ttyS4三设备取数实测总表_20261109.md` 合并取代**
> （2026-11-09 全量重测）。重测推翻了本文一处结论：**两台浊度仪字节序并不通用** ——
> 站1 WZT-701A 是 CDAB，站2（ZHEYI-5100ZDY）是 **DCBA**，按本文 §3.2.1 的「通用口径」读站2
> 会得到小 4 个数量级的假数。另新增两条实测：站2 应答功能码恒为 `0x03`；站1 在站5 的 49 字节
> 帧之后需要 ≥100~125ms 恢复期。
> 本文 §4（hsfsrv 收帧截断根因）与 §5（取数路径）仍然有效，是缺陷分析的第一手记录。

> 实测日期：2026-11-09
> 目标板：192.168.1.249（`hd-rk3568`，Debian 11 aarch64，root / hmklj20250803）
> 涉及设备：浊度仪站 1、浊度仪站 2（另一型号）、LD 电磁流量计站 5
> 探测器源码：`verify/ld_meter/`（板端部署在 `/root/`）

## 一、结论速览

### 1.1 总线拓扑（ttyS4，9600 8N1，Modbus RTU）

| 站号 | 设备 | 在线 | 读法 | 实测值 |
|---|---|---|---|---|
| **1** | 在线浊度监测仪 **WZT-701A** | ✅ | `FC03` 读 `0x0000` 起 **2** 个寄存器 | **2.3800 NTU** |
| **2** | 浊度仪（**另一型号**，现场未提供说明书） | ✅ | `FC03` 读 `0x0000` 起 **2** 个寄存器 | 0.0007 ~ 0.1854 NTU（随工况变） |
| 3 | （现场称"另一型号浊度仪"） | ❌ **不在线** | 全地址 `0x0000~0x001F` × `FC03/FC04` | **零应答** |
| **5** | **LD 电磁流量计**（上自仪） | ✅ | `FC04`（`FC03` 也通）读 `0x1010` 起 **22** 个寄存器 | 流量 0.0 m³/h，**空管报警置位** |

另一条总线 `ttyS3`（115200）是变频器站 2 + 温湿度站 4，与本文档无关。

### 1.2 一句话结论

**三台设备的取数口径都已实测确定、帧 100% 完整；但 hsfsrv 目前拿不到流量计数据**——
不是设备问题，是 hsfsrv 的 **收帧判据**（非阻塞读 + 3ms 静默判帧尾）在 9600 波特下
把 49 字节应答截成 32 字节，另有 `_flush_input()` 互踩与**浊度仪站号配错**两处。

## 二、现场环境与操作纪律

### 2.1 连接与串口

```sh

```

| 项 | 值 |
|---|---|
| 串口 | `/dev/ttyS4`（板子另有机载 UART：`ttyS3/5/7/8/9`） |
| 波特率 | 9600，8N1，无校验（Modbus RTU） |
| 流量计站号 | **5**（参数区 `0x0001` 自证） |
| 浊度仪站号 | **1**（WZT-701A）、**2**（另一型号） |
| 板端 pyserial | 解包 wheel 在 `/root/pyserv`，用 `PYTHONPATH=/root/pyserv` |

### 2.2 ⚠️ 必须独占串口

hsfsrv 用 pyserial 的 `exclusive=True`（Linux `TIOCEXCL`）打开 `/dev/ttyS4`。
**hsfsrv 在跑时，探测器脚本打不开该口**（`device reports readiness to read but
returned no data` / 打开失败）。手工探测必须先让出：

```sh
systemctl stop hsfserverpy     # 释放 ttyS4（本次实测全程这样做）
...                           # 探测
systemctl start hsfserverpy    # 探测完必须恢复
```

> 实测确认：两个独立 serial 实例并发读同一 tty 会互抢字节，pyserial 直接抛
> `SerialException: device reports readiness to read but returned no data
> (device disconnected or multiple access on port?)`。
> 同一进程内多 fd 抢同一 tty 是**抢字节**语义（数据被瓜分，不是复制）。

## 三、逐台设备取数方法

### 3.1 站号 1 —— WZT-701A 在线浊度监测仪

**读法（手册口径，实测复核通过）**

| 项 | 值 |
|---|---|
| 功能码 | `FC03`（**FC04 无应答**，只支持 FC03） |
| 起始地址 | `0x0000` |
| 寄存器数 | 2（32 位量） |
| 字序 | **低字在前（CDAB）** |
| 格式 | IEEE754 单精度 float32，**不除以 100** |

**实测原始帧**

```
REQ : 01 03 00 00 00 02 C4 0B
RSP : 01 03 04 51 EC 40 18 1A F0      (9 字节，CRC 校验通过)
       └┬┘ └┬┘ └────┬────┘
        │   │      └── 0x4018  高字
        │   └───────── 0x51EC  低字
        └───────────── 站号 1
```

**换算**：`bits = (0x4018 << 16) | 0x51EC = 0x401851EC` → float32 = **2.3800 NTU**

> 与 hsfsrv 历史表 `history.turb1 = 2.38` **完全一致** ⇒ 口径已闭环验证。
>
> 手册 4.3.10.2 的示例帧 `D7 0A 41 1F` → 9.99 NTU 同样是 CDAB float32、不除 100。

**寄存器图（实测扫描 `0x0000~0x001F`，`FC03`）**

| 地址 | 实测值 | 含义 |
|---|---|---|
| `0x0000` | `0x51EC` | 浊度 float **低字** |
| `0x0001` | `0x4018` | 浊度 float **高字** |
| `0x0002`~`0x0007` | 0 | — |
| `0x0008` | 12 | 有值，含义待核（量程/阈值类） |
| `0x0009`~`0x000D` | 0 | — |
| **`0x000E`** | **无应答** | 保留地址（该固件不响应） |
| `0x000F`~`0x001F` | 0 | — |

> `FC04` 对**所有**地址均无应答 ⇒ 探测时别用 FC04 试。

### 3.2 站号 2 —— 另一型号浊度仪

现场口头称"站号 3 是另一型号"，但**实测站 3 零应答、站 2 在线且读法与站 1 同构**，
故按站 2 记录（型号待现场补说明书）。

**读法**

| 项 | 值 |
|---|---|
| 功能码 | `FC03`（**`FC04` 也通，且应答完全一致**） |
| 起始地址 / 数量 | `0x0000` 起 **2** 个寄存器 |
| 字序 / 格式 | 低字在前（CDAB）float32，不除 100（与站 1 同） |

**实测原始帧**

```
REQ : 02 03 00 00 00 02 C4 38
RSP : 02 03 04 D7 7B 3A 3D 53 EF      (9 字节，CRC 校验通过)
       低字 0xD77B   高字 0x3A3D   → CDAB float32 = 0.0007 NTU
```

同一台设备多次实测取值：`0.0007` / `0.0116`（连续 10 次稳定）/ `0.1854`
⇒ **浊度值随工况变化**，属正常。

**寄存器图（实测扫描 `0x0000~0x000F`，`FC03`）**

| 地址 | 实测值 | 备注 |
|---|---|---|
| `0x0000` | `0xD77B` | 浊度 float 低字 |
| `0x0001` | `0x3A3D` | 浊度 float 高字 |
| `0x0002`~`0x0007` | 0 | — |
| `0x0008` | `0xDF2F` | — |
| `0x0009` | `0x953B` | — |
| `0x000A` | `0xDF2F` | 同 `0x0008` |
| `0x000B` | `0x953B` | 同 `0x0009` |
| `0x000C` | `0x0500`（1280） | — |
| `0x000D` | 0 | — |
| `0x000E` | `0x8C01` | **与站 1 不同**：站 1 此地址无应答 |
| `0x000F` | `0x0100`（256） | — |

> 与站 1 的两点差异：**支持 FC04**、**`0x000E` 有值** ⇒ 两型号寄存器表确有不同，
> 站 2 其余字段含义需等现场补该型号说明书后核对。

#### 3.2.1 两台浊度仪取数一致性验证（型号不同，但浊度值取法通用）

| 站号 | 型号 | 连续 20 读 | CRC | NTU | 稳定性 |
|---|---|---|---|---|---|
| 1 | WZT-701A | **20/20 完整** | 20/20 通过 | **2.3800** | 20 次完全一致 |
| 2 | 另一型号 | **20/20 完整** | 20/20 通过 | **0.1848** | 20 次完全一致 |

**结论：两型号虽不同，但"浊度值"这一组寄存器口径通用**——
都是 `FC03` 读 `0x0000` 起 2 个寄存器、低字在前（CDAB）、IEEE754 float32、不除以 100。
故 `hsfsrv` 的 `TurbidityMeter` 类**用同一套常量服务两台即可**（该类本来就把
字序/格式/除数做成运行期旋钮，正是为这种现场差异留的口子）。

**但通用范围仅限浊度值**：`0x0008~0x000F` 两型号含义不一致
（站 1：`0x0008`=12、`0x000E` 无应答；站 2：`0x0008`=0xDF2F、`0x0009`=0x953B、
`0x000C`=1280、`0x000E`=0x8C01、`0x000F`=256）。若将来要取量程/阈值/状态，
**必须按型号分开**，不能共用一张表。

**⚠️ 站 2 数值跨时段变化明显**（多次独立探测分别得到 0.0007 / 0.0116 / 0.1854 /
0.1848 NTU），而**同一时段内 20 读完全恒定** ⇒ 属**工况性变化**（沉淀/搅动/取样
导致），不是读数抖动或解析错位。**待现场核项**：看一眼站 2 那台面板当前显示值，
若在 0.18 NTU 附近即坐实"该寄存器就是浊度"；若面板显示的是别的量，
则站 2 的 `0x0000/0x0001` 不是浊度（虽有 CDAB float 的合理量级，仍需以面板为准）。

## 四、hsfsrv 现状与三处缺陷

### 4.1 症状（板端 `journalctl -u hsfserverpy`）

```
[15:03:38] 流量计 采集失败：读应答不完整：需要 49 实际 32（05032c000000...4556c000...）
[15:03:39] 浊度仪2 采集失败：无应答（0 字节）
[15:03:40] 浊度仪1 采集失败：无应答（0 字节）
[15:03:41] 浊度仪1 恢复通讯（此前连续失败 1 次）
[15:03:42] 流量计 采集失败：站号不符：期望 5 实际 0
```

数据侧佐证（`hsf_data.db` 的 `history` 表）：**`flow` / `flow_total` 全为 `NULL`**，
`turb1 = 2.38`（站 1 偶尔能读通），**`turb2` 全为 `NULL`**。

> 注：`turb1` 偶有值 ⇒ 站 1 并非稳定失败，而是**时好时坏**，符合"被别的帧冲掉后
> 偶尔抢到完整帧"的竞争特征。

### 4.2 根因一（主因）：非阻塞读 + 3ms 静默判帧尾，9600 下必截断

`hsfsrv/hsfsrv/modbus.py`：

```python
self._serial = serial.Serial(..., timeout=0, ...)     # ← 非阻塞读
RTU_IDLE_MS = 3                                          # ← 静默 3ms 即判"帧结束"
```

注释写「115200 下约 0.3ms，取 3ms 留足余量」——**这个余量在 9600 下是负的**：
9600 的 3.5 字符时间 = 3.5 × 11 / 9600 = **4.01ms**，本身就超过 3ms。

**实测证据一：内核分两批交付应答，批间隔 20.6ms**
（`verify/ld_meter/byte_arrival_timeline.py`，阻塞读看真实到达节奏）：

```
34.1ms:0    55.0ms:32    75.6ms:17      ← 49 字节被拆成 32 + 17 两批
```

**实测证据二：放宽静默阈值无效**
（`verify/ld_meter/rtt_timing_and_find.py` 实验 A，站 5 流量计各 20 帧）：

| idle 阈值 | 完整帧 | 长度分布 |
|---|---|---|
| 1ms | 0/20 | 随机断在 17/19/20/21/24/29/30/32 |
| 2ms | 0/20 | `{32: 20}` |
| **3ms**（现状） | **0/20** | `{32: 20}` |
| 4 / 5 / 8 / 12 / 20ms | 0/20 | `{32: 20}` |

⇒ 截断点恒定在 **32 字节**，与阈值无关；**说明"断"不是超时断的，是内核只给了第一批**。
（真实批间隔 20.6ms > 20ms，所以 20ms 阈值同样断。）

**实测证据三：手工探测 100% 完整**
阻塞读（`timeout=0.02`）下 pyserial 内部 `select` 等到凑满，49 字节帧 **每次都完整**。

### 4.3 根因二：`_flush_input()` 在共享 master 上互踩

`modbus.py` 每次事务前调 `self._serial.reset_input_buffer()`（= `tcflush(TCIFLUSH)`），
理由是"温湿度模块会吐 8 字节残尾"。但长帧跨 20ms 批次时，**上一帧还没收完**，
下一个从站的请求先把内核缓冲冲掉 ⇒ 连带把**自己**的应答前半截也冲掉 ⇒
表现为 `无应答（0 字节）`；若从流中间续读，首字节变成 `0x00` ⇒
表现为 `站号不符：期望 5 实际 0`。三者互为印证。

### 4.4 根因三：浊度仪站号配置与现场不符

- `cfg/hsf_server_py.json` **没有** `serial.unit_ids` 覆盖 ⇒ 取代码缺省：
  `flowmeter_unit_id = 5`（对）、`turbidity_unit_ids = [1, 3]`（**3 不在线，在线的是 2**）
- 服务启动横幅自证：`浊度仪(/dev/ttyS4/9600站1/3)`

⇒ 界面"浊度仪2"永远离线（`turb2` 恒 `NULL`），**站 2 那台真实在跑的浊度仪没被采集**。

### 4.5 建议修法

| # | 改法 | 说明 |
|---|---|---|
| **A（正解）** | **收帧改为"按长度收满"**：读应答 = `3 + byteCount`、异常应答 = 5、写应答 = 8；先读 3 字节头拿 `byteCount`，再 `read_exact` 凑满，总超时兜底 | Modbus RTU 应答长度可预知，不该靠静默猜帧尾。**实现注意**：不可像旧版那样"读 2 字节 → sleep → 再读 N 字节"（中间空档会错位），要用 `select` 阻塞等凑满 |
| **B（保底）** | 静默阈值按波特率自适应：`RTU_IDLE_MS = max(3, 3.5字符时间×3)` → 9600: 12ms、115200: 3ms | **单靠 B 不够**（实测批间隔 20.6ms），必须与 A 配套 |
| **C** | `_flush_input()` 只在"上一事务已收完"的前提下执行（或仅 CRC 失败重试时才 flush） | 由 A 保证帧收全后，flush 不会再冲掉未收完的帧 |
| **D** | 配置：`turbidity_unit_ids` 由 `[1, 3]` 改为 **`[1, 2]`** | 与现场在线设备一致 |

> **C 端对应**：`Src/Industry/XFlowMeter/` 与浊度仪设备类同样走框架 `XModbus`
> 串口通道，**若框架侧也用"静默判帧尾 + 阻塞读"，9600 下会犯同样的错**，
> 改 hsfsrv 时须同步核对 C 端收帧口径（AGENTS.md 双端对齐铁律）。

### 路径 2：在线集成取数（改完 A/C/D 后）

hsfsrv 采集正常后，数据落在 `hsf_data.db`：

```sql
SELECT ts, flow, flow_unit, flow_total, total_unit, turb1, turb2
  FROM history ORDER BY rowid DESC LIMIT 5;
```

**验收判据**

| 项 | 期望 |
|---|---|
| `history.flow` | 非 `NULL`（当前 m³/h 量级） |
