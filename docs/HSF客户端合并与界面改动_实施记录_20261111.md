# HSF 客户端：合并远端 + 三项界面改动（实施记录 2026-11-11）

> 起因：远端 `0a1f637d`（数据三页导出对话框化 + 双主题 + sim 路B采集开关）推上来了，
> 本地工作区与之分叉。本轮：① 暂存→拉取→合并（冲突按用户裁定逐项解）；
> ② 合并后发现**本地会话的「全局字体缩放」被覆盖掉了**，补回；
> ③ 按用户要求改「历史数据默认排序」与「列筛选多选复选」。

## 1. 合并过程与裁定

| 步骤 | 动作 |
|---|---|
| 1 | `git stash push -u`（含未跟踪文件）→ `git pull`（快进到 `0a1f637d`）→ `git stash pop` |
| 2 | 14 个冲突文件**按用户裁定**解：客户端 11 个取远端、服务端 3 个取本地（11-11 修正版）、导出格式死能力整个删掉、stash 保留 |

**合并本身的两个坑（都真踩了）**：

1. **取远端会连带覆盖本地会话的功能**：`HsfSettingsLocal.c` 取远端 ⇒ 「全局缩放
   （全部界面）」那一行没了；`HsfSettingsRemote.c` 取远端 ⇒ 远端设置页的字号
   不跟缩放走；`HsfPlaceHolder.c` 取远端 ⇒ 占位页字号写死；`HsfDataAlarm.c` 取
   远端 ⇒ 报警页只重放标题/状态、表格与工具条不跟；`HsfDataBar.c` 取远端 ⇒
   工具条字号回到「读回当前字号反解」的老实现。
   ⇒ **取远端 ≠ 丢功能**：合并后必须**逐文件对照本地版的特性清单**再收口。
   本轮用「本地日期注记 + 符号级审计 + `hsfUi_*FontPx` 用量对照」三招把漏网的
   找齐（`HsfSettingsLocal/Remote`、`HsfPlaceHolder`、`HsfDataBar`、`HsfDataAlarm`）。
2. **一键部署的同步环节有两个真 bug**（已修 `Tools/posix/hsf-board-deploy.sh`）：
   - 同步只传「与 HEAD 不同」的文件 ⇒ **合并时被还原成 HEAD 的文件永远不刷新到
     WSL 树** ⇒ 板端编译报 `HSF_THEME_KEY_SKIN undeclared` 之类的**假错**
     （本地树明明是对的）⇒ 改为**每次用 `git archive HEAD` 重建基线**再叠加差异；
   - Windows 检出的 `.sh` 带 CRLF ⇒ WSL 里 dash 读 `set -eu\r` 报
     `set: Illegal option -` ⇒ 同步后对 `*.sh/*.py/*.cmake` 归一 LF。
   - 另：**改公共头必须全量重编**（Windows ninja 缺头文件依赖 ⇒ 增量编译给假绿；
     本轮就是桌面增量「通过」、板端全量才暴露问题）。

  - `HsfPlaceHolder.c`：`hsfUi_fontPx` → 写死 17/13/12。
- 连带必须补 **`HsfDataBar_applyFont` 的绝对基准改写**（本地版）：旧实现
  「读回控件当前字号 × 新pct/旧pct 反解」，**引入全局合比后会双乘**
  （150%→160% 层层相乘）⇒ 改成「基准 = 源码常量 × pct」（与

  逐处把主题那一行补回。

## 3. 改动一：历史数据默认「最新在最上面」

- **协议与服务端口径不动**：两端服务端的分页语义是「offset 按 ts **倒序**数
  （offset=0 = 最新的一页），页内返回**时间正序**」（C 端
  `HsfServerStore_queryHistory` 与 Python `store.query_history_page` 的
  `list(reversed(rows))` 同构）⇒ 翻页定位本来就对，只是**页内展示方向**反了。
- 改法：**只改表格铺行方向**（`histFillTable` 倒着铺 ⇒ 第 0 行最新），
  导出顺序（按页内原序写盘）、图表取点（按页内原序累加）、关键字比对列
  （可见列）全不受影响。
- 顺带把 `HsfDataHistory.c` 的行 ts 快照（锚点用）也改成与表格行序一致。

## 4. 改动二：列筛选改「多选复选」（对齐 Python）

Python 口径（`pages_other.py` 的 `MultiCheckCombo`）：**「列」是视图设置
（看哪些列），不是筛选条件** ⇒ 多选复选、**默认全勾**、**至少留一列**、
**勾选变化立即生效**（不用按「筛选」）、按钮文字是汇总。

C 端实现（`HsfDataBar`）：

| 项 | 实现 |
|---|---|
| 控件 | 单选下拉 → **按钮 + 弹出勾选菜单**（`XMenu` + 可勾选 `XAction`） |
| 状态 | `uint32_t m_colMask`（位 i = 第 i 列），页侧按掩码取可见列 |
| 勾选标记 | **文字前缀 `[x]` / `[ ]`**：框架 `XMenu` **不渲染** checkable 状态（`XMenu.c` 无 `isCheckable/isChecked` 消费点；会画复选框的只有 `XListView`）⇒ 走文字前缀（ASCII：板端位图字库无 ☐/☑ 字形） |
| 汇总文字 | 全勾=「全部列（全部）」，部分=被勾列名顿号连接，**按 30 字节截断**+提示框放全量 |
| 至少留一列 | 取消最后一列被忽略（Python `min_checked=1` 同口径） |
| 立即生效 | 勾选变化直接回调 `HsfDataBarAction_ColumnFilterChanged` ⇒ 页面重排可见列；**「清除筛选」不再复位列勾选**（列是视图设置） |

### 4.1 两个实现坑（都是实测踩出来的）

1. **框架的槽约定：`receiver` = connect 时传的接收者**，不是被连接对象。
   按钮槽按「receiver 是被连接对象」写了 `offsetof` 反推 ⇒ 读到垃圾值直接
   return ⇒ **点了没反应**（板端连点两次都以为是弹层问题）。正确写法：
   槽里 `self = (HsfDataBar*)receiver`；要拿发送者用 `XObject_sender()`
   （同 `barChangeSlot` 的写法）。**被点的 XAction 用 sender 取。**
2. **工具条里的按钮文字不能长**：汇总文字不截断 ⇒ 按钮的 sizeHint 把行1 的
   最小宽顶爆 ⇒ 布局从「两行横排」塌成「一行一个控件」（整个工具条竖排）。
   Python 端靠 Qt 省略号限宽，本框架没有 ⇒ **自己按字节截断**（不截半个
   UTF-8 字符），完整清单放提示框。

### 4.2 弹出菜单的形态

- 菜单必须是**顶层窗口**：带 widget 父会变成子控件、被父矩形裁掉（弹出来看不见）
  ⇒ 用 `XMenu_create()`（无父）+ `DeleteOnClose`（与框架自带右键菜单同款）。
- 弹层定位：按钮下沿的**全局坐标**（`XWidget_mapToGlobal`）。

## 5.1 追加：远端设置页「点了保存没反馈」（2026-11-11 现场报）

**现象**：点「保存（需管理员）」后状态栏停在「**正在应用数据存储配置 …**」永不变化。

**取证**（板端 + 本机各一轮，带临时诊断）：
- 服务端**每条路径都有回包**（解析失败/缺 section/权限不足都回）⇒ 不会静默丢；
- 同一条 0x0117 用 Python 客户端发 ⇒ **秒回** `ok=true`（「落盘配置已保存」）；
- 板端 C 客户端点保存 ⇒ 服务端日志有「远程配置：落盘节已更新（运行期生效）」，
  客户端侧也收到了回包 ⇒ **协议与服务端都正常**；
- 真正的问题在**反馈链路**：
  ① 「正在…」只有**收到回包**才有终态（配置写/控制应答/模式错误三处）⇒
     回包一丢，状态栏就**永远停在「正在…」**（用户看着像界面死了）；
  ② 即使收到了，「配置已保存（以服务端回显为准）」会被随后的**「配置已刷新」**
     覆盖（写配置后服务端会推一次新快照）⇒ 用户只看到一句无关的话。

**修法**（`HsfSettingsRemote.c`）：
1. **在途操作登记 + 超时兜底**：七个动作（采集/落盘/登录/切手动/切自动/自动启/自动停）
   统一 `srOpBegin(kind)` 登记；定时器每拍 `srOpPoll` ⇒ 超过 10 s 仍无终态就提示
   「未收到服务端回执（可能已超时）：请查看服务端日志」⇒ **任何「正在…」必有终态**。
2. **粘滞消息**（`m_opMsgSticky`）：写完操作终态后，例行消息（「配置已刷新」）不得覆盖它。
3. **模式切换的成功终态**：回包里没有单独的 ok 键，靠**模式值回落**判定
   （目标态已生效 ⇒ 「已切换到自动/手动模式」）。

**板端实测**：点「保存」⇒ 状态栏显示「**配置已保存（以服务端回显为准）**」✓（此前会被
「配置已刷新」盖掉）。

> **教训**：凡是对外发请求的动作，「已发出」不等于「已生效」——UI 必须给
> **成功 / 失败 / 超时**三选一的终态，且终态消息不能被例行消息覆盖。

## 5.2 追加：列筛选真复选框浮层 + 时间列跳秒根修（2026-11-11 下午）

### ① 时间列在相邻两秒间快速交替（现场「第一列一直在跳」）

**现象**：历史页表格时间列整列在 `15:19:09 / 15:19:08` 之间快速切换，
看着像"数据一直在刷新"；总行数不变（库里确实 60s 才一行）。

**根因**：`hsfHistFormatTs`（`HsfLinkHistory.c`）每次重铺表格都重算时区偏移，
用**两个不同瞬间**的采样相减
（`toMSecsSinceEpoch(currentDateTime()) − currentWallMSecsSinceEpoch()`），
差值带 ±1ms 噪声。库里的 `history.ts` 全是整秒 ⇒ `ts + 偏移` 落到
`xx:xx:08.999` ⇒ 秒数少 1；噪声偶尔为 0 就显示正确秒 ⇒ 两个数来回跳。
**同一个根因也解释了 §N6 回归用例的间歇红**（23:59:59 → 23:59:58），
此前被误判成"既存 flaky"。

**修法**：时区偏移恒为整分钟的倍数 ⇒ 就近归到 60000ms 网格
（`((raw ± 30000) / 60000) * 60000`），噪声清零。同款写法全仓共 6 处
（HsfLinkHistory / HsfDataHistory / HsfDataAlarm / HsfDataLog /
HsfMonitorFlowMeter / HsfMonitorVfd 的 `xxxTzOffsetMs`），一并收口。
验证：回归连跑 3 次 758/0（§N6 不再 flaky）；桌面两帧截图时间列
像素差为 None。

**另一个澄清**：现场看到的"1s 周期入库"是**旧残留数据**（15:03 之前
某进程把 `storage/sample_ms` 写成过 1000），合并后服务端缺省 60000ms
实测入库间隔恒 60000。切换时刻与 INI 里的历史值在
`bin/cfg/hsf_server.ini` 可查。

### ② 列筛选浮层：从 XMenu 到「XFrame(Popup)+XScrollArea+XCheckBox 行」

用户口径：**对齐 Python**（`MultiCheckCombo`：QPushButton + QFrame(Qt.Popup)
+ 每行真 QCheckBox，点项不收层、点外面才收）。走了三层弯路，终版照抄
Python 结构：

| 尝试 | 结果 |
|---|---|
| ① `XMenu` + `[x]` 文字前缀 + 延迟一拍重开 | 板端验证失败（菜单建了不显示），回退 |
| ② `XListView` 派生 + CheckStateRole + clicked 翻转 | 弹层子类里 `IndexAt` 虚槽不稳 ⇒ clicked 不发射（XComboBox.c:1431 注释早有预警）；viewport 吞掉本体鼠标事件 ⇒ 点行没反应 |
| ③ **终版**：`XFrame(XWindowType_Popup)` + `XScrollArea` + 每行 `XCheckBox` + `toggled` 槽 | 与 Python 逐件对应；checkbox 自己发 toggled，不做坐标换算 |

**三个必记的坑**：

1. **Popup 类型必须构造即定**（`XFrame_init(..., XWindowType_Popup)`，
   与 `XMenu_init_2` 同款）：曾用 flags=0 让 `XWidget_init` 自动补成
   Window，后续 `setWindowFlags(Popup)` 只改字段、平台窗口已按 Window
   建柄 ⇒ 日志有 `200x420 surface` 却永不映射上屏（"点了没反应"）。
2. **禁止 `XWidget_grabMouse`**：它把所有鼠标事件绕过 childAt 直投弹层
   本体 ⇒ 子控件（滚动条/复选框）收不到事件。曾实测"滚动条拖不动"。
   只挂平台 `XWindow_setMouseGrabEnabled`（延迟 1ms 建立配合映射时序），
   窗口内正常命中子控件，窗口外点击转投弹层由 press 越界分支收起。
3. **水平滚动条按用户口径关掉**（`setHorizontalScrollBarPolicy(AlwaysOff)`）。

**列显隐（表格联动）**：曾因「XTableWidget 不消费 setColumnHidden」
做过「列宽 0」绕过；远端 `6fc0adb0`（Qt 6.8 全量对齐）后
`setColumnHidden` 转发表头隐藏段（qtableview.cpp:2705-2711 对位）、
表格几何/命中跳过隐藏段 ⇒ **绕过整体回退，回归正规口径**。
白盒回归锁 `testD9_columnHiddenSkipsGeometry`（转发/占宽 0/命中跳过/
恢复复位 7 项）锁住该链路。

**信号槽口径补课**（用户点名）：槽签名 `void(XObject* receiver,
XVarList* args)`，参数由框架自动打包进 XVarList（`XVarList_args_1`
解包，宏自带 const 声明——重复声明同名变量会 C2373）；
`XObject_sender(receiver)` 由 directEmit 的 pushSender 栈支撑；
`XSignal` 宏以 NULL 调用信号函数取 id（**双参信号函数不能喂给 XSignal**
——强转单参调用是 UB，多参信号按返回真址方式取 id）。

## 5.3 追加：板端 C 客户端「登录↔断开循环」根治（2026-11-11 晚）

**现象**：合并 6fc0adb0 后板端部署，C 客户端起来（主窗就绪）但立刻进入
「登录成功↔连接断开」循环 28 次，随后进程消失（无 segfault/无 core，
XPrintf relay 吞尾看不到退出原因）。现场界面一度靠 Python 客户端
（hsfclientpy）顶替。

**取证（决定性）**：`XDeviceNetwork_posix.c` 有编译期开关
`XDEVNET_IO_DEBUG`（`#ifndef` 包裹 ⇒ 命令行 `-D` 可覆盖；
`build_board.sh` 已加 `BOARD_EXTRA_CFLAGS` 透传）。板端跑 debug 版抓到
断开前最后的事件序列：

```
[XDEVNET] submit op=27 fd=7   ← 重挂读 #1（第一个 RECV 还在飞）
[XDEVNET] submit op=27 fd=7   ← 又挂一个 RECV（同 fd 双在飞）
[XDEVNET] event R result=-9223372036854775808 finished=0   ← 垃圾完成
HsfLinkClient: 连接断开（自动重连中）
```

**根因（三层叠加）**：
1. 远端 6fc0adb0 重写 `XAbstractSocket` 读路径（引擎缓冲搬运/
   假 EOF 防护），`socketDrainEngineReadBuffer` **每批**都发
   `ContinueRead`（重挂读）；
2. 板端 RK3568 定制内核走 `XNetIoRingPosix.c` 的 **epoll 回退引擎**，
   RECV 提交直接入挂起链、**没有同 fd 在飞去重**；
3. posix 设备层 `XDeviceNetwork_socketContinueRead` **无条件先清
   readPending 再重挂**——把 `startAsyncRead` 的在飞闸（607 行
   `if (p->readPending) return`）短路 ⇒ 同一 fd 两个在飞 RECV 共享
   单份 readContext ⇒ 后完成的那个读到 IO_PENDING 哨兵值（INT64_MIN）
   ⇒ 上层判链路死。

写侧 `ContinueWrite` 一直有 `if (p->writePending) return` 在飞守卫——
**读侧正是同款遗漏**。

**修法**（`XDeviceNetwork_posix.c` `socketContinueRead`）：
`if (p->readPending) return;`（幂等——在飞 RECV 本身就是"重挂的读"，
数据到来会完成并重新走 drain）。正常路径（完成处理器已清 readPending）
不受影响。**桌面 Windows 后端不在此文件（不受影响）**。

**验证**：debug 版板端实测——断开 0 次（修复前 35 秒内多轮）、垃圾完成
0 次、登录仅 1 次、7784 次重挂读正常轮询；换无调试宏的干净版再验
90+ 秒零断开，C 客户端界面全屏恢复、数据全通（截图）。

**附带修复/澄清**：
- `build_board.sh` 加 `BOARD_EXTRA_CFLAGS` 透传（调试宏等注入用）；
- WSL 有**多个发行版/目录**：一键脚本用 `-d Ubuntu` + `/root/xinyuec-board`
  + `/root/xboard-hsf`；`wsl.exe -e`（不带 -d）进的是另一发行版，
  其 `/root/xboard` 是**没传端口宏的错误构建目录**（COM17/COM18 坑）
  ——手动编译必须 `-d Ubuntu` 并核对 CMakeCache 里的端口宏；

**做法要点（与本仓「战役合并为一条」惯例一致）**：

1. **`reset --soft` 而不是 `reset --mixed`/`checkout`**：soft 只挪 HEAD，
   **索引与工作区原样保留** ⇒ 不会丢任何已改内容；mixed 会把索引退回基点
   （改动还在，但要重新 `add`），checkout 则直接**丢内容**。
2. **未跟踪文件必须显式 `git add`**：`reset --soft` 不碰它们 ⇒ 漏 add 就等于
   这批文件**没进提交**（本批的 `verify/board/kb_repro*.py` 就是这种）。
3. **零丢失校验用 `write-tree` 而非 `git diff`**：`diff` 比的是**两次提交
   之间**，看不到「未跟踪文件有没有被 add 进去」；`write-tree` 比的是**索引
   快照**，新增文件只要没 add 就立刻暴露。
4. **旧提交仍在 reflog 里** ⇒ 合成失败可 `git reset --hard <旧HEAD>` 回来
   （本批旧尖是 `9dd07a62`）。
