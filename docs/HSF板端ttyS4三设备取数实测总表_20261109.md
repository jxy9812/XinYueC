## 一、结论速览

### 1.1 三台设备总表

| 站号 | 设备 / 型号 | 制造商 | 功能码 | 起始地址 × 数量 | 字节序 | 本次实测值 | 响应时延 |
|---|---|---|---|---|---|---|---|
| **1** | 在线浊度监测仪 **WZT-701A** | 上海仪电科学仪器（雷磁） | **FC03**（FC04 无应答） | `0x0000` × **2** | **CDAB**（低字在前） | **2.29 NTU** | 37~43 ms |
| **2** | 水质浊度智能控制器 **ZHEYI-5100ZDY** | 浙江浙仪自控系统工程 | FC03（**FC04 也通**，但应答恒回 FC03） | `0x0000` × **2**（浊度）／× **4**（浊度+温度） | **DCBA**（整字节反序 = 小端 float32） | **0.0446~0.0458 NTU**<br>**19.25~19.31 ℃** | 31~33 ms |
| **5** | 电磁流量计 **LD 系列**（L_mag B 型转换器） | 上自仪 | **FC04**（FC03 同值） | `0x1010` × **22** | **ABCD**（高字在前，大端无字交换） | 流量 **0.0000**（空管）<br>电导比 **3354**<br>空管报警 **True** | 68~69 ms |
| 3 | （现场曾称"另一型号"） | — | — | — | — | **全地址零应答** | — |
| 4、6~20 | 无设备 | — | — | — | — | 零应答 | — |

### 1.2 五条硬结论

1. **两台浊度仪字节序不同**：站1 是 CDAB，站2 是 DCBA。同一套解码常量**不能**服务两台的
   `0x0000/0x0001` 这组字。（`0x0008~0x0013` 更是两型号含义完全不同的区间。）
2. **站1 有"长帧后恢复期"**：站5（49 字节帧）读完后**立刻**问站1 → 几乎零应答；
   间隔 **≥100~125 ms** 才恢复，**200 ms 稳定 10/10**。站2 **完全免疫**（任何间隔都是 10/10）。
3. **收帧必须"按长度收满"**，不能靠静默判帧尾：9600 下内核把 49 字节应答拆成
   **32 + 17 两批，批间隔 ~20.6 ms**，任何静默阈值（1/2/3/4/5/8/12/20 ms）都恒定断在 32 字节。
4. **站2 应答功能码恒为 `0x03`**，即使请求的是 FC04。按「应答功能码 == 请求功能码」校验会误判。
5. **两台浊度仪都不需要密码就能读**：取数走 Modbus 只读，面板 `Login` 与本项目无关。

### 1.3 采样稳定性（40 s × 20 轮，三台混跑）

```

# 站1浊度     最小 2.29          最大 2.29          均值 2.29        NTU

# 站5流量     最小 0             最大 0             均值 0           m³/h
```

```sh

...                           # 探测
systemctl start hsfserverpy    # 探测完必须恢复
```

> 同一进程内多 fd 也一样。

## 三、本文档用到的两个基础工具

### 3.1 CRC16（Modbus RTU）

```python
def crc16(data):
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc                      # 上线顺序：先低字节，后高字节
```

### 3.2 收帧：按长度收满（**唯一可靠口径**）

```python
def read_frame(port, timeout=0.6):
    hdr = read_exact(port, 3, timeout)          # 站号 + 功能码 + 字节数
    if len(hdr) < 3:
        return b""
    if hdr[1] & 0x80:                            # 异常应答：固定 5 字节
        rest = read_exact(port, 2, timeout)
    else:
        rest = read_exact(port, hdr[2] + 2, timeout)   # byteCount + CRC2
    return hdr + rest
```

**为什么不能用静默判帧尾**（实测证据，站5 各 20 帧）：

| idle 阈值 | 完整帧 | 长度分布 |
|---|---|---|
| 1 ms | 0/20 | 随机断在 17/19/20/21/24/29/30/32 |
| 2 / 3 / 4 / 5 / 8 / 12 / 20 ms | **0/20** | **恒为 `{32: 20}`** |

截断点恒定在 **32 字节**且与阈值无关 ⇒ 不是"超时断的"，是**内核只给了第一批**。
逐次 read 的到达时序实测：

```
34.1ms:0    55.0ms:32    75.6ms:17      ← 49 字节被拆成 32 + 17 两批（批间隔 20.6ms）
```

### 4.2 怎么读

```
请求: 01 03 00 00 00 02 C4 0B
      └┬┘ └┬┘ └──┬──┘ └──┬──┘ └──┬──┘
       │   │     │       │      └── CRC16（低字节在前）
       │   │     │       └───────── 寄存器数 2（32 位量 = 2 字）
       │   │     └───────────────── 起始地址 0x0000
       │   └─────────────────────── 功能码 03（**FC04 无应答**）
       └─────────────────────────── 站号 1

应答: 01 03 04 8F 5C 40 12 A1 38      (9 字节，CRC 通过)
      └┬┘ └┬┘ └┬┘ └──┬──┘ └──┬──┘
       │   │   │     │       └── 高字 0x4012（地址 0x0001）
       │   │   │     └────────── 低字 0x8F5C（地址 0x0000）
       │   │   └──────────────── 字节数 4
       │   └──────────────────── 功能码 03
       └──────────────────────── 站号 1
```

**解码（CDAB，低字在前）**：

```python
lo, hi = struct.unpack(">2H", rsp[3:7])       # lo=0x8F5C, hi=0x4012
bits   = (hi << 16) | lo                       # 0x40128F5C
ntu    = struct.unpack(">f", struct.pack(">I", bits))[0]   # 2.29
```

> 手册 4.3.10.2 原文明写：「按照低字在前高字在后传输(CDAB)…D7 0A 41 1F 对应的浮点型数据为
> 9.99NTU」。用同一条公式验算 `01 03 04 D7 0A 41 1F 92 1D` → `0x411FD70A` = **9.99f** ✓
> **不除以 100，不除以任何数。**

### 4.3 寄存器图（实测扫描 `0x0000~0x003F`，逐点 FC03）

| 地址 | 实测值 | 含义 |
|---|---|---|
| `0x0000` | `0x8F5C` | 浊度 float **低字** |
| `0x0001` | `0x4012` | 浊度 float **高字** |
| `0x0002`~`0x0007` | 0 | — |
| `0x0008` | `0x000C`（12） | 有值，**手册未定义**（疑为机号或量程代码） |
| `0x0009`~`0x003F` | 0 | — |

**能力边界**

| 项 | 实测 |
|---|---|
| FC03 读 `0x0000×1/2/4/8/16/32` | 全部成功（返回对应字数） |
| FC04 任何地址 | **无应答**（3 次全空） |
| 单读 `0x0001` | 正常（早期一次无应答属站1 偶发丢帧，见 §8） |

> 手册只给了 `0x0000×2` 这一帧的示例，**没有公开寄存器全表**；
> 上面除 `0x0000/0x0001` 外的含义均属推测，不要据此取数。

**面板**：品牌 `ZHEYI 浙仪` + `SMART CONTROLLER`；按键 `ESC` `Cal` `□` `□` `OK`；
LCD 主显大号浊度值，`TB: NTU` 为浊度单位标记；另有温度项；右侧软键栏 `Login` `Cal` `Info`。

> ⚠️ 这家「浙江浙仪自控系统工程有限公司」**≠** 网上查到的「杭州浙仪仪表制造有限公司」
> （`www.zjzheyi.com`）。后者自有产品线里没有浊度仪，5100 号段是 pH 计 —— 查手册别走错门。

### 5.2 怎么读

```
请求: 02 03 00 00 00 02 C4 38
应答: 02 03 04 4F DD 37 3D 98 3C      (9 字节，CRC 通过)
       └┬┘ └┬┘ └┬┘ └──┬──┘ └──┬──┘
        │   │   │     │       └── 0x373D（地址 0x0001）
        │   │   │     └────────── 0x4FDD（地址 0x0000）
        │   │   └──────────────── 字节数 4
        │   └──────────────────── **功能码恒为 03**（即使请求 04）
        └──────────────────────── 站号 2
```

**解码（DCBA，整字节反序 = 小端 float32）**：

```python
b4  = rsp[3:7]                                  # 4F DD 37 3D
ntu = struct.unpack("<f", b4)[0]                # 0.04489 NTU
# 等价写法：struct.unpack(">f", b4[::-1])[0]
```

**同时取温度**：一次读 4 个寄存器 `0x0000×4`，前两字是浊度，后两字是温度：

```python
b4_t = rsp[7:11]                                # 00 00 99 41
temp = struct.unpack("<f", b4_t)[0]             # 19.125 ℃
```

### 5.3 字节序判定过程（这是本次最关键的一步）

同一帧 `4F DD 37 3D`，四种口径分别解出：

| 口径 | 公式 | 结果 | 判断 |
|---|---|---|---|
| ABCD（大端） | `4FDD373D` | 7.4e9 | ✗ 天文数字 |
| CDAB（低字在前） | `373D4FDD` | **1.13e-5** | ✗ 小 4 个数量级 |
| BADC | `DD4F3D37` | 负值 | ✗ |
| **DCBA（小端）** | `3D37DD4F` | **0.04489** | ✓ **对上现场面板 0.04** |

温度的独立验证：同一帧后两字 `00 00 99 41` 按 DCBA 解 = **19.125 ℃**，
与面板显示的温度项（拍照时 18.0 ℃，本次测试时刻 19.27 ℃）同量级同趋势 ⇒ 坐实。

> **反证**：站1 的 `8F 5C 40 12` 按 DCBA 解是 6.07e-28（荒谬），按 CDAB 解 2.29（合理）
> ⇒ 两台表**确实不同**，不能统一。

### 5.4 寄存器图（实测扫描 `0x0000~0x00FF`，逐点 FC03）

| 地址 | 实测值（示例） | DCBA float | 含义 |
|---|---|---|---|
| `0x0000` / `0x0001` | `0x6E65` / `0x3B3D` | **0.045751** | **浊度 NTU** ✓ |
| `0x0002` / `0x0003` | `0x0000` / `0x9941` | **19.125** | **温度 ℃** ✓ |
| `0x0004`~`0x0007` | 0 | — | — |
| `0x0008` / `0x0009` | `0xBEEA` / `0x953B` | 0.0045751 | 实测恒为**浊度的 1/10**，含义未知 |
| `0x000A` / `0x000B` | `0xBEEA` / `0x953B` | 0.0045751 | 与 `0x0008` **完全相同**（重复项） |
| `0x000C` | `0x0500`（1280） | — | 常量，含义未知 |
| `0x000D` | 0 | — | — |
| `0x000E` / `0x000F` | `0x8C01` / `0x0100` | — | 状态字（含可变位） |
| `0x0010` / `0x0011` | `0x8C01` 或 `0x5C01` / `0x0100` | — | **会变**（实测 0x8C→0x5C） |
| `0x0012` / `0x0013` | `0xCB7D` / `0x5E3B` | 0.003395 | 含义未知（疑阈值） |
| `0x0014`~`0x003F` | 0 | — | — |

> 现阶段**只取 `0x0000~0x0003`（浊度+温度）**，其余字段不要用于业务逻辑。
> `0x0008` 恒为主值 1/10 这一现象已复现，但成因未证实。

### 5.5 能力边界（实测）

| 项 | 结果 |
|---|---|
| FC03 读 `0x0000×1/2/4/8/16/32` | 全部成功 |
| **FC04 读 `0x0000×2`** | **成功，数据与 FC03 完全一致，但应答功能码回 `0x03`** |
| FC04 读 `0x1010` | 异常应答（5 字节） |
| 读 `0x0040` 及以上 | 异常码 `0x02`（非法数据地址） |
| 写操作（FC06/FC16） | **本次未执行**（只读纪律） |

> **实现注意**：校验应答时用「`rsp[1] & 0x80` 判异常」是安全的，
> 但**不要断言 `rsp[1] == 请求功能码`**——站2 会打破这个假设。

### 6.2 怎么读（一条帧读全部变量）

```
请求: 05 04 10 10 00 16 75 45
应答: 05 04 2C 00 00 00 00 00 00 00 00 00 00 00 00 00 45 51 A0 00
      00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 05 00 01 00 00 00 00
```

`2C` = 44 字节 = 22 寄存器 × 2。**FC04 与 FC03 都能读，值完全一致。**

### 6.3 变量寄存器表（FC04，`0x1010~0x1025`）

**大端、无字交换**（Float = 高字在前 `ABCD`，Long 同理）。

| 寄存器 | 十进制 | 格式 | 内容 | 本次实测 |
|---|---|---|---|---|
| `0x1010/0x1011` | 4112/4113 | F32 | 瞬时流量 | **0.0000** |
| `0x1012/0x1013` | 4114/4115 | F32 | 瞬时流速 | 0.0000 |
| `0x1014/0x1015` | 4116/4117 | F32 | 流量百分比 | 0.00 % |
| `0x1016/0x1017` | 4118/4119 | F32 | 流体电导比 | **3354.0** |
| `0x1018/0x1019` | 4120/4121 | U32 | 正向累积**整数部分** | 0 |
| `0x101A/0x101B` | 4122/4123 | F32 | 正向累积**小数部分** | 0.0 |
| `0x101C/0x101D` | 4124/4125 | U32 | 反向累积整数部分 | 0 |
| `0x101E/0x101F` | 4126/4127 | F32 | 反向累积小数部分 | 0.0 |
| `0x1020` | 4128 | U16 | 瞬时流量单位 | **5 → m³/h** |
| `0x1021` | 4129 | U16 | 累积总量单位 | **1 → m³** |
| `0x1022` | 4130 | U16 | 上限报警 | False |
| `0x1023` | 4131 | U16 | 下限报警 | False |
| `0x1024` | 4132 | U16 | **空管报警** | **True（管道未充液）** |
| `0x1025` | 4133 | U16 | 系统报警 | False |

**累积量必须两段拼装**（不是单个 64 位整型）：

```python
total_fwd = ((regs[8] << 16) | regs[9]) + f32(regs[10], regs[11])
total_rev = ((regs[12] << 16) | regs[13]) + f32(regs[14], regs[15])
```

**瞬时流量单位代码表（`0x1020`）**

| 代码 | 单位 | 代码 | 单位 | 代码 | 单位 |
|---|---|---|---|---|---|
| 0 | L/S | 4 | M3/M | 8 | T/H |
| 1 | L/M | 5 | **M3/H**（本机） | 9 | GPS |
| 2 | L/H | 6 | T/S | 10 | GPM |
| 3 | M3/S | 7 | T/M | 11 | GPH |

> 单位是**仪表侧可改**的，程序不能把 `m³/h` 写死，必须随数据读上来做标度。

**累积总量单位代码（`0x1021`）**：0=L、**1=M3（本机）**、2=T、3=USG（B 型口径 0~3）。

### 6.4 参数寄存器（FC03 读，**只能逐点单读**）

| 地址 | 名称 | 实测 | 解释 |
|---|---|---|---|
| `0x0000` | 语言 | 0 | 中文 |
| `0x0001` | 仪表通讯地址 | **5** | 与扫描一致 |
| `0x0002` | 仪表通讯速度 | **5** | 代码 5 = **9600 bps** |
| `0x0003` | 测量管道口径 | 9 | 代码 9 = 32 mm |
| `0x0006` | 流量单位 | 5 | M3/H |
| `0x0007` | 测量阻尼时间 | 3 | 04 SEC |
| `0x000A` | 流量积算单位 | 7 | 1 M3 |
| `0x000C` | 电流输出类型 | 0 | 4 mA |
| `0x0012` | 频率输出范围 | 5000 | — |
| `0x001F` | 出厂标定系数 | 8822 | — |

**⚠ 参数区不支持连读**（实测）：

```
请求 05 03 00 00 00 01 → 应答 7 字节（1 个寄存器）
请求 05 03 00 00 00 02 → 应答 7 字节（仍是 1 个）
请求 05 03 00 00 00 04 → 应答 7 字节（仍是 1 个）
请求 05 03 00 00 00 08 → 应答 7 字节（仍是 1 个）
```

**写操作需要密码（本次未执行，仅据协议文档记录）**：

> `0x0047` **不可读**（FC03 返回异常 `0x83 0x01`），`0x0048` 起越界。

## 七、解码方法论：四种字节序怎么判

把两个寄存器（线上 4 个字节 `b0 b1 b2 b3`）拼成 float32，有四种常见口径：

| 名称 | 拼接顺序 | Python 写法 | 本项目哪台设备 |
|---|---|---|---|
| **ABCD** | 高字在前、字内高字节在前 | `struct.unpack(">f", b)[0]` | 站5 流量计 |
| **CDAB** | 低字在前、字内高字节在前 | `struct.unpack(">f", b[2:4]+b[0:2])[0]` | 站1 WZT-701A |
| BADC | 高字在前、字内低字节在前 | `struct.unpack(">f", bytes([b1,b0,b3,b2]))[0]` | 本次无设备使用 |
| **DCBA** | 低字在前、字内低字节在前（=小端） | `struct.unpack("<f", b)[0]` | 站2 ZHEYI-5100ZDY |

**判定方法（现场最快的办法）**：拿**面板显示值**当裁判，四个解里只有一个落在合理量级。
没有面板值时，用「量级合理性」判：浊度应在 0.001~1000 NTU，温度应在 -10~60 ℃；
解出 1e-5 或 1e9 的都是错的。

## 八、时序要求：站1 的「长帧后恢复期」

### 8.1 现象

三台混跑（顺序：站1 → 站2 → 站5 → 重复）时，**只有站1 掉**：

| 轮次 | 站1 | 站2 | 站5 |
|---|---|---|---|
| 1 | ✓ 2.29 | ✓ | ✓ |
| 2 | ✗ 零应答 | ✓ | ✓ |
| 3 | ✗ 零应答 | ✓ | ✓ |

### 8.2 定性（方向性 A→间隔→B，各 10 轮）

| 组合 | gap 0 ms | gap 50 ms | gap 200 ms |
|---|---|---|---|
| 站5(49B) → **站2** | A10/**B10** | A10/**B10** | A10/**B10** |
| 站5(49B) → **站1** | A10/**B0** | A10/**B1** | A10/**B10** |
| 站2(9B) → 站1 | A10/B7 | A10/B10 | A10/B10 |
| 站1(9B) → 站1 | A8/B10 | A8/B10 | A9/B10 |
| 站5(49B) → 站5 | A10/B10 | A10/B10 | A10/B10 |

### 8.3 恢复期门槛精扫（站5 之后问站1，每档 10 轮）

| 间隔 | 成功 | 间隔 | 成功 |
|---|---|---|---|
| 0 ms | 2/10 | 125 ms | **10/10** |
| 25 ms | 1/10 | 150 ms | 9/10 |
| 50 ms | 2/10 | 175 ms | **10/10** |
| 75 ms | 0/10 | 200 ms | **10/10** |
| 100 ms | 8/10 | 225 / 250 / 300 ms | 9~10/10 |

**结论**：站1 在站5 的 49 字节帧之后需要 **≥100~125 ms** 的空闲；工程上取 **200 ms**。
站2 对任何间隔都不敏感（0 ms 也 10/10）。

> 机制未进一步定位（可能是站5 延长驱动 485 总线，或站1 的接收恢复较慢）。
> 现象可复现、门槛已量化，**按 200 ms 设计即可**。

## 九、采样配方（推荐）

三台设备按「间隔 200 ms」轮流访问，实测 40 s × 20 轮 **三台全 20/20**：

## 十一、排障清单

| 症状 | 最可能原因 | 处理 |
|---|---|---|
| 某站**全地址零应答** | 未上电 / 未接线 / 站号不对 / 波特率不对 | 先跑 `--section presence` 普查 1~20；换站号 1/2/5 能通即证明串口没问题 |
| 某台**数值恒为 0 或天文数字** | **字节序错**（最常见） | 用 §7 四口径对照；拿面板值当裁判 |
| 站1 **时好时坏** | 站5 长帧后未留恢复期 | 站1 之前留 ≥200 ms（§8） |
| 应答**恒定 32 字节**（要 49） | 用静默判帧尾（非阻塞读） | 改「按长度收满」（§3.2） |
| 应答**0 字节**且日志说「站号不符：期望 5 实际 0」 | 事务前 `tcflush` 把上一帧尾巴/本帧头冲掉 | 只在确认已收完后 flush |
| 站2 报「功能码不符」 | 站2 应答功能码**恒为 0x03** | 只判 `rsp[1] & 0x80`，不做等值断言 |
| 流量计**参数区只回 1 个** | 设备本身不支持连读 | 逐点单读（§6.4） |
| 流量恒 0 | **空管**（`0x1024=1`） | 灌水后复查；空管时读数为 0 属正常 |
| 探针打不开串口 | hsfsrv 独占（TIOCEXCL） | `systemctl stop hsfserverpy` |

## 十二、服务端（hsfsrv）现状与必须同步的改动

### 12.1 当前仍在报错（`journalctl -u hsfserverpy`，18:14 实测）

```
流量计 采集失败：读应答不完整：需要 49 实际 32（05032c000000...）

```

`hsf_py/hsf_data.db` 的 `history` 表：**`turb1` / `turb2` / `flow` 全为 `NULL`**。

### 12.2 需要改的六条（本次重测后完整清单）

| # | 改法 | 依据 |
|---|---|---|
| **A（正解）** | **收帧改为「按长度收满」**：读 3 字节头拿 `byteCount`，再补齐；异常应答 5 字节、写应答 8 字节；总超时兜底 | §3.2。Modbus RTU 应答长度可预知，不该靠静默猜帧尾。实现要用 `select` 阻塞等凑满，**不能**「读 2 字节→sleep→再读 N 字节」（中间空档会错位） |
| **B（保底）** | 静默阈值按波特率自适应：`max(3, 3.5字符时间×3)` → 9600: 12ms | **单靠 B 不够**（实测批间隔 20.6 ms），必须与 A 配套 |
| **C** | `_flush_input()` 只在「上一事务已收完」时执行，或仅 CRC 失败重试时 flush | 现在每次事务前 `reset_input_buffer()` 会把未收完的帧冲掉 ⇒ 表现为「无应答 0 字节」或「站号不符：期望 5 实际 0」 |
| **D** | 配置 `turbidity_unit_ids` 由 `[1, 3]` 改为 **`[1, 2]`** | §3 普查：站 3 不存在，在线的是站 2 |
| **E** | **站2 需要独立的字节序（DCBA）** | §5.3。`TurbidityMeter.LOW_WORD_FIRST` 只能表达 CDAB/ABCD 两态，**表达不了"字内字节反序"**；按现值读站2 得 0.0029（真值 0.0458） |
| **F** | **站1 之前留 ≥200 ms** | §8。轮询表顺序若把站1 排在站5 后面，站1 会长期掉线 |

### 12.3 C 端同步项

`Src/Industry/XTurbidity/XTurbidityMeter.h` 现有三个旋钮：
字序（`LowHigh`/`HighLow`）、格式（float32/uint32/int32）、除数。

**缺的正是站2 需要的「字内字节序」**——建议加第四个旋钮
（如 `XTurbidityMeterByteOrder_HighLow / LowHigh`），缺省保持现值以不影响站1。
改完必须同步两处：
- `HighSpeedFilter/server_py/hsfsrv/devices.py` 的 `TurbidityMeter._decode`
- 回归用例（现用 WZT-701A 的 `D7 0A 41 1F` 帧做逐字节断言，需保留并**新增一组 DCBA 帧断言**）
