## 二、为什么"量程"必须靠现场注入

4~20 mA 与 0~20 mA 两个量程的**满量程采样电压相同**（20 mA × 249 Ω = 4.98 V）。二者只在**下限**上有区别：

| 量程 | 电流下限 | 对应采样电压 | 固定 3 位小数点下的寄存器值 |
|------|---------|-------------|--------------------------|
| 0~20 mA | 0 mA | 0.000 V | 0 |
| 4~20 mA | 4 mA | 0.996 V | 996 |

因此**只有当某通道的读数落在 0.996 V 以下时，才可能区分两个量程**——若某通道读到 0，说明量程是 0~20 mA（或该路未接信号）；若读到 0.996~4.980 V，则与 4~20 mA 一致。

本次实测 8 路全部落在 0.007~0.000 V，**全部低于 4 mA 下限**，所以现场没有任何数据可用于区分量程。详见 §6 与 §7。

## 五、关键行为约束（**上层集成必读**）

这一节是本次探测最有价值的产出。以下每一条都是**实测**得到的，违反其中任何一条都会导致**静默无响应**（不是报错，最难排查）。

### 5.1 ⚠ TCP 段必须「精确等于一帧」

| 发送内容 | 结果 |
|---------|------|
| 精确 1 帧（12 字节） | ✅ 正常应答 |
| 1 帧 + 1 字节尾巴 | ❌ 静默丢弃 |
| 1 帧 + 8 字节尾巴 | ❌ 静默丢弃 |
| 1 帧 + 64 字节尾巴 | ❌ 静默丢弃 |
| 1 字节垃圾 + 1 帧 | ❌ 静默丢弃 |
| 同一包内 2 帧 | ❌ 静默丢弃 |
| 一帧拆成两段发（间隔 50 ms） | ❌ 静默丢弃 |
| 一帧拆成两段发（间隔 ≈0，两次 send 几乎同时） | ✅ 正常（两次 send 被 TCP 合并成一个段） |

**实现要求**：每次请求用一次 `send()` / `sendall()` 发出，请求缓冲区里**不得有多余字节**；写操作时不要复用带残留的发送缓冲区。

### 5.2 ⚠ 必须一问一答，不能流水线

| 行为 | 结果 |
|------|------|
| 发一帧 → 等响应 → 再发一帧 | ✅ 正常（实测 20/20、30/30） |
| 连续 `send` 两帧后再收 | ❌ **两帧全部无响应** |
| 上述失败后再单独发一帧 | ✅ 立即恢复正常（**链路不卡死，无需重连**） |

**实现要求**：同一连接上必须严格 `send → recv → send → recv`。设备是单串行解析器，上一帧未处理完时到达的新段会被整段丢弃。

### 5.3 ⚠ 最多 3 条并发 TCP 连接

| 第几条 | 结果 |
|-------|------|
| 1、2、3 | ✅ 建立成功且可正常读写 |
| 4 | ❌ `ConnectionRefused`（WinError 10061）或 connect 超时 |

释放任意一条后可立即新建。

**实现要求**：客户端应使用**单连接 + 一问一答**的串行模型；不要为每个采集点开一条连接，也不要用多线程各自持有连接。

### 5.4 ⚠ 非法请求不返回 Modbus 异常码

| 请求 | 结果 |
|------|------|
| 功能码 `0x63`（非法） | ❌ **静默丢弃**（超时，无异常码） |
| FC04 起始地址 `0xFFFF` | ❌ 静默丢弃 |
| FC04 数量 = 0 | ❌ 静默丢弃 |
| FC04 数量 = 125 / 126 | ✅ 正常应答（返回对应长度的零） |
| FC04 起始地址越界（如读第 19 路） | ✅ 正常应答，返回 0（**不报非法地址**） |

**实现要求**：不要依赖 Modbus 异常码来判断错误，必须以**超时**为唯一失败判据；越界读不会报错，只会返回 0。

### 5.5 TransactionID 回显正常，但短连接高频开关会错位

| 场景 | 结果 |
|------|------|
| 单连接内连续 30 次，TID 递增 | ✅ 30/30 完全一致 |
| 反复「建连 → 发 → 立即断连」20 轮 | ⚠ **3/20 出现响应 TID 滞后一个请求**（如请求 `0x0016` 却收到 `0x000F`） |

**实现要求**：**优先使用长连接**。若必须用短连接，不要用 TID 严格匹配来判定响应，而应按**帧长度 + 到达顺序**匹配，并容忍一次错位。

### 5.6 主动上传（`HR0031H`）：断电前可用，断电重启后失效

**断电前实测成功**（两次独立验证）：

| 场景 | 写入值 | 实测推送 |
|------|-------|---------|
| 写入 50（0.50 S） | `0031H = 50` | 8 帧 / 4 秒，间隔 **0.500 / 0.500 / 0.501 / 0.500 / 0.500 / 0.500 / 0.501** s，精度极高 |
| 写入 100（1.00 S） | `0031H = 100` | 1.0 s 间隔推送，与查询响应同格式（FC04 + 8 路数据） |

**设备断电重启后**，以下组合全部**收不到任何推送帧**（已逐一排除）：

| 组合 | 等待时长 | 收到帧数 |
|------|---------|---------|
| 同连接：写 50 → 收 | 15 s | 0 |
| 写 50 → 换新连接 → 收 | 15 s | 0 |
| 写 1000（10 s）→ 收 | 14 s | 0 |
| 写 0 → 写 50（0→非 0 跳变）→ 收 | 12 s | 0 |
| 新连接上写 50 → 同连接收 | 12 s | 0 |
| 写 50 → 先发一次查询 → 再收 | 10 s | 0 |

写操作本身全部正常应答（`06 0031 0032`），且 `HR0031H` 读回确认为 50（**值已存入 EEPROM**），但上传任务不启动。

**结论与建议**：

1. **不要把主动上传作为主采集通道**——它的可用性依赖设备运行状态，不可靠。
2. **主通道用主动轮询**：单连接一问一答，实测 1.9 ms/帧、529 帧/秒，远超 30 Hz/通道的更新率需求，且无状态依赖。
3. 主动上传可作为**可选的省流量模式**，但上线前必须在目标设备上**现场复验**（含断电重启后复验）。

> 附：推送帧格式与主动查询的响应**完全相同**（MBAP + FC04 + 字节数 + 8 路数据），上层只能靠「MBAP 顺序 / TID」区分二者，无法从内容区分。

### 5.7 RTU-over-TCP 兼容

设备在同一个 TCP 端口上也接受标准 Modbus RTU 帧（地址 1）：

```
请求: 01 04 00 00 00 08 F1CC     (RTU 读 8 路)
响应: 01 04 10 00 08 00 00 ...   (RTU, CRC16 正确)
```

且**同一连接内可与 Modbus TCP 帧混用**（先发 MBAP 再发 RTU，两者都能正确应答）。但**首个帧必须是完整的一帧**——空连接上的第一帧 RTU 也正常应答。

## 六、4~20 mA 换算与验证

### 6.1 换算链（手册 2.2 / 2.4）

```
寄存器原始值 (uint16)
   │  按解析方式换算
   ▼
采样电阻两端电压 U (V)          ← 0~20/4~20 mA 量程下，寄存器里存的是电压
   │  I = U / 249Ω
   ▼
电流 I (A) → × 1000 → I (mA)
```

**可变小数点**（`HR003AH = 0`，出厂默认）：最高位数字（万位）表示小数点位数。
例：`31000` → 3 位小数 → `1000 × 0.001 = 1`（V）。

**固定小数点**（当前实测 `HR003AH = 2`，即固定 3 位）：直接除以 10³。

### 6.2 分辨率交叉验证（支持 ÷249 口径）

| 来源 | 数值 |
|------|------|
| 手册标称电流分辨率 | **1 µA** |
| 固定 3 位小数点下 1 LSB | 0.001 V → ÷249 Ω = **4.016 µA** |
| 实测 CH1 噪声峰峰 | 1 LSB ≈ 4.0 µA |

两者同量级（µA 级），且与"寄存器存的是采样电阻电压"这一口径自洽。若寄存器直接存的是 µA，则 12 位 ADC（4096 级）覆盖 0~20 mA 需要 4.9 µA/LSB，与手册标称的 1 µA 不符。

### 6.3 量程判定规则（写入脚本，注入信号后直接跑）

| 实测电流分布 | 判定 |
|-------------|------|
| 全部通道 ≥ 3.5 mA | **4~20 mA** |
| 存在通道 < 1.0 mA | **0~20 mA** |
| 最大 > 20.5 mA | **0~20 mA 或更大** |
| 全部为 0 | **无法判定**（无信号，需先注入） |

`4~20 mA` 量程下的期望寄存器值（固定 3 位小数点）：

| 实际电流 | 采样电压 | 寄存器原始值 |
|---------|---------|------------|
| 4 mA（量程下限） | 0.996 V | **996** |
| 12 mA（中值） | 2.988 V | **2988** |
| 20 mA（量程上限） | 4.980 V | **4980** |
| 0 mA（断线） | 0.000 V | 0 |

## 七、现场验证步骤（把"4~20 mA"闭环）

> 前置：**每一路的跳线帽必须短接**（手册 1.1：短接 = 电流采集；出厂默认是电压采集）。这是本次现场读数全为 0 的**最可能原因**。

### 步骤 1 — 短接跳线帽

逐路确认 IN+/IN−（或 CI+/CI−）对应跳线帽已短接。8 路逐一确认。

### 步骤 2 — 接入信号源

任选一种：

| 方式 | 说明 |
|------|------|
| 4~20 mA 电流源 / 变送器 | 直接串入通道回路，最贴近现场 |
| 精密电阻分压法（无电流源时） | 用 250 Ω 精密电阻 + 可调直流电压源：`I = U / 250`。4 mA→1.000 V，20 mA→5.000 V。**注意**：此时模块读到的是 1.000~5.000 V，比 4~20 mA 直采时的 0.996~4.980 V 略高 0.4%，属正常（电阻标称值误差） |
| 恒流源 + 串接采样 | 精度最高 |

## 八、缺陷清单与规避建议

| # | 缺陷 | 影响 | 规避 |
|---|------|------|-----|
| 1 | 同包多帧 / 多余字节 → 整包丢弃 | 静默无响应 | 一次 `send` 一帧，缓冲区精确 |
| 2 | 流水线 → 整批丢弃 | 静默无响应 | 严格一问一答 |

| 4 | 非法请求不返回异常码 | 错误被吞 | 以超时为唯一失败判据 |
| 5 | 短连接高频开关时响应 TID 滞后 | 响应错配 | 用长连接；按顺序而非 TID 匹配 |
| 6 | 越界读返回 0 而非报错 | 误判通道数 | 通道数用 `HR0039H` 判定 |
| 7 | 主动上传断电重启后不触发 | 上传模式失效 | 主用轮询；上传模式需现场复验 |
| 8 | 手册未定义 `HR0038H` / `HR0039H` | 量程/型号不可读 | 向厂商索取完整寄存器表 |
| 9 | 出厂默认跳线帽 = 电压采集 | 电流型模块读数全 0 | 逐路短接跳线帽 |

## 十、给上层的集成建议（面向本仓库 HSF / XModbus 采集页）

1. **单连接 + 一问一答**。本仓库 `XModbusTcpClient` 若存在"发送缓冲区复用后未清零"或"连续投递不等响应"的做法，在此设备上会**静默失败**——排查时看不到任何异常，最容易被误判为网络问题。
2. **失败判据用超时**，不要依赖 Modbus 异常码。
3. **通道数用 `HR0039H` 判定**，不要靠"读到全 0"来推断。
4. **采集周期建议 100~500 ms**：手册标称 30 Hz/通道，实测读取能力 529 帧/秒，100 ms 周期即可获得全部更新，同时把带宽占用压到很低。
5. **量程标定必须现场做**（§7），软件侧无法替代。
6. 采集页面应把**原始寄存器值**和**换算后工程量**同时显示：现场排查时，原始值是唯一无歧义的真相（避免解析方式配置变更导致历史数据错解）。
