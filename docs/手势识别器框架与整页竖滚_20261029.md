## 3. 未收口的两个问题（接手先看这里）

### 3.1 手势识别器判定回调被覆盖 → 识别器全部返回 Ignore

**现象**：`XGestureRecognizer_Test` **0/10 通过**；日志显示
`[DBG-rec] result=1`（`Ignore`）恒定，`[DBG-deliver]` 从不出现。

**已排除**：
- 帧投递链正常：`[DBG-hook]` → `[DBG-pt]` 均有输出，type 正确（194/195/196）。
- 订阅正常：`[DBG-set] target=<控件地址>` 正确（识别器已绑定目标控件）。
- 虚表重载在 `XPanGestureRecognizer` 上**确实生效**（`[DBG-pan] data==mine` ✅）。

**当前状态**：已从"虚表槽重载"改为"**函数指针登记**"（基类成员
`XGestureRecognizeFunc m_recognize`，派生类 init 时登记
`self->m_base.m_recognize = V<Xxx>GestureRecognizer_recognize;`），
**但仍失效**：`[DBG-fp] cb=0000000000000001`。

**关键证据（下一步的抓手）**：`cb == 1` 恰好等于 `XGestureRecognizerResult_Ignore`
的枚举值，也等于 `m_prevPointCount` 的典型取值。**强烈怀疑是内存越界写**：
`XGestureRecognizer_processTouch` 里有
```c
for (i = 0; i < pointCount && i < 8; ++i)
    self->m_prevPoints[i] = points[i];
self->m_prevPointCount = pointCount;
```
若 `m_prevPoints` 的实际写入越界，会正好覆盖紧随其后的 `m_prevPointCount`
与 `m_recognize`。

**建议排查顺序**：
1. 在 `XTapGestureRecognizer_init` 登记语句后立即打印 `m_recognize`，
   在 `XGestureRecognizer_processTouch` 入口再打印一次；两次不一致即证实被覆盖。
2. 检查 `XGestureRecognizerOutput`（含 `uint8_t` 尾成员）的**实际对齐/大小**
   与 `offsetof(XGestureRecognizer, m_prevPoints/m_prevPointCount/m_recognize)`
   是否与预期一致（MSVC x64 下 `XTouchPoint` 为 16 字节、`XPoint` 为 4 字节）。
3. 用 `offsetof` 打印三个成员的偏移，先确认布局，再查谁越界写。
4. 若确认是 `m_prevPoints` 越界：确认 `points` 指向的数组长度确实 ≥ `pointCount`
   （钩子里构造的 `localPts[8]` 长度是 `min(count,8)`，但传给基类的是
   **原始 count**——若 count > 8 就会越界，**这正是最可能的真因**）：
   `XGestureRecognizer_processTouch` 应把 `pointCount` 钳到 8，或钩子只传
   `min(count, 8)`。

> 备注：钩子当前把 `count` 原样传给基类，而 `localPts` 只有 8 个槽位——
> **单点/双点场景下 count≤2 无碍**，但一旦多点超过 8 即越界。优先复核此处。

## 4. 框架陷阱清单（本轮踩坑，接手必读）

### 4.1 `XClass_Parent` 会取到"自己" → 无限递归（已修，务必记住）

`XClass_Parent(Type, Enum, Sig)` 展开为
`XVtableGetFunc(Type##_class_init(), Enum, Sig)`（`Src/XClass/XClass.h:249`），
而 `XVtableGetFunc` 只是 `m_data[Offset]` 取函数指针，**不跳过本类自身**。

→ **重载了某槽的类，调用父类实现时必须指定"该槽真正拥有实现的类"**：
- `EXWidget_HideEvent` → 指定 `XWidget`（**不是** `XAbstractScrollArea`）；
- `EXObject_TimerEvent` → 指定 `XObject`（XWidget 刻意不重载它）。

本轮按 `XAbstractScrollArea` 取回自身，导致**点击 Demo 任意菜单按钮即崩**
（切页隐藏页根触发 HideEvent → 递归爆栈）。已修为：
```c
XClass_Parent(XWidget, EXWidget_HideEvent, XWidgetEventSlot)(self, event);
XClass_Parent(XObject, EXObject_TimerEvent,
              void (*)(XObject*, XTimerEvent*))(object, event);
```
> 顺带：`XAbstractScrollArea_resizeEvent_base` 里
> `XClass_Parent(XAbstractScrollArea, EXWidget_ResizeEvent, ...)` 是**既有正确
> 用法**（该槽由基类实现、调用者是派生类），不要误改。

### 4.2 `XPrintf` 的 `%p` 不可靠

`XPrintf` 底层是 `vsnprintf`，但本轮实测 `XPrintf("%p", ptr)` 输出与实际值
不符（打印出 `00000078374FF330` 之类野值，误导排查方向）。**排查指针一律用
`fprintf(stderr, "%p", p)`**（注意对应 .c 要 `#include <stdio.h>`，否则隐式
声明导致输出丢失——本轮因此误判过一次"函数没被调用"）。

### 4.3 `python3` 在本机是 WindowsApps 空壳

`python3` 存在但执行返回 **exit 49**（无输出）。**必须用 `python`**（3.11）。
批量改文件时优先写脚本文件再 `python script.py`，不要用 `python -c`
（bash 引号嵌套极易踩坑）。

### 4.4 柔性数组不可整体拷贝

`XTouchEvent` 尾部 `m_points[]` 是 C99 柔性数组：**结构体赋值/拷贝不复制数组
内容**，就地改写拷贝体的 `m_points[k]` 会污染原事件。钩子里必须把点拷到
**栈上数组**再传递。

### 4.5 栈模式虚表是"每次 class_init 重建"

`XVTABLE_STACK_INIT` 用 `static` 局部变量，`XVtable_init_stack` 会把
`m_size` 归零 → 每次 `class_init()` 都是完整重建 ✅（多次调用安全）。
