# DPR 渲染层（Qt 6.8.3 逐点对齐）实施记录 —— 2026-11-09

## 一、问题与裁定

**现象**（安卓模拟器 127.0.0.1:51714，dpr=2.0：surface 1920×1080 / 逻辑 960×540 /
presentScale=2.0）：框架按逻辑分辨率整帧渲染（字体按逻辑字号光栅化），present 层
最近邻 ×2 放大 ⇒ 字形边缘 2×2 马赛克阶梯（3× 放大取证
`emu_before_text_zoom.png`），与用户判断「先选字体再缩放」一致。Windows 125%/150%、
X11 强制 DPI 同链路同病；fbdev 更甚（dpr>1 连 present 放大都没有，UI 只占面板一角）。

**裁定**（用户）：完全对齐 Qt——引入 Qt 式 DPR 渲染层，落在通用框架层，一切 dpr>1
平台受益；默认启用 + `XGUI_DPR_RENDER=0` env 回退闸（bisect）；dpr>1 窗口本批暂关
GPU 会话（GPU 快路恒等变换假设 + 图集键不含 dpr，对齐旋转闸先例）。

## 八、第四轮（2026-11-11：点击整体偏移根修 —— 静态初始化器错位）

### 8.1 现象

用户在 BlueStacks 上点击，app 内光标/按压落点比真实鼠标位置**统一偏左上
320 物理 px（=160 逻辑 px）**，X/Y 同量常数偏移；触摸命中大面积落空。

### 8.2 取证链（屏显读数 + logcat，逐步排除）

| 步 | 证据 | 结论 |
|---|---|---|
| ① | 用户截图：BlueStacks 工具栏 `X/Y` = app 收到的 `raw`（1258.5/731.2 → 1258/731） | **注入层无损**，raw 即显示物理坐标 |
| ② | 屏显读数反推：raw(480,270)→map(80,−25) ⇒ `map = raw/2 − 160` | 两轴**同量常数**，与 raw 无关 ⇒ 不是比例失配 |
| ③ | logcat `input diag: dpr=2.000 viewSpace=0 origin=(0,48) logical=960x540 presentScale=2.000 surfW=1920`；`display real=1920x1080 covers=1`；`input-origin probe: contentOrigin=(0,0) statusBar=48` | origin 被 covers=1 强制 (0,0)，四条补偿通道应有值全为 0 |
| ④ | 逐条排除：①`/data/local/tmp` 无 `xgui_input_*.txt`（env 标定通道未生效）；②无 `touch calibration: runtime trim` 日志（trim=0）；③4 点校准 `solve degenerate: keep identity`（calib 未应用）；④origin=(0,0) | **常数 160 不可能来自任何输入补偿通道** |
| ⑤ | 偏移恒 160 逻辑 px、与 raw 无关、落在映射**结果**上 | ⇒ 是加在结果上的**常数平移**，源头在映射之后 |

### 8.3 根因：`g_xpad` 静态初始化器与结构体字段顺序错位

`Drive/Android/Graphics/XPlatformWindowAndroid.c` 的
`static XPadState g_xpad = { ... }` 用的是**位置初始化器**。本批为「四点触摸
校准」在结构体**中段**（`m_runtimeTrimY` 之后）插入 13 个新字段，初值块却
仍按旧字段顺序排列 ⇒ 整块初值**错位 13 槽**，后面的值全部落错字段：

| 字段 | 期望初值 | 实得 | 后果 |
|---|---|---|---|
| `m_runtimeTrimX/Y` | 0.0f | **160.0f** | **每个触摸被平移 −160 逻辑 px**（用户可见的整屏偏移） |
| `m_calibActive` | 0 | **160** | 四点校准模式**开机自启**，吞掉前 4 个触摸（"点几下没反应"） |
| `m_moveFrameMs` | 25 | 1 | MOVE 帧节流窗 25ms→1ms（拖动 CPU 上升） |
| `m_geomPending/m_geomW` | false/0 | true/1 | 开机推一次 1×0 的假几何 |
| `m_dpr/m_presentScale/m_densityDpi` | 1.0/1.0/160 | 0/0/0 | 首帧前退化（surface created 覆写，侥幸无害） |

肇事的正是初值块里的 `1.0f, 160, 160.0f, 160.0f, false`（DPI 兜底组）——
它落到 `m_moveFrameMs / m_runtimeTrimX / m_runtimeTrimY / m_calibActive /
m_calibIdx` 上：**160 既是 DPI 兜底值，又是偏移元凶**，纯属巧合叠加。

**为什么前几轮没看出来**：偏移量恒定、且 X/Y 同量，形态极像「模拟器宿主
窗口缩放换算残数」，于是前几轮先后怀疑并试过 ① 输入原点（origin）、② 宿主
缩放标定（env/marker 文件通道）、③ 四点线性校准（运行时自校准）——三者都
建立在「错位导致的常数平移长得像外部环境偏移」这一错误前提上。

### 8.4 修法

1. **`g_xpad` 改 C99 指定初始化器**（`.m_dpr = 1.0f` 逐字段点名）：字段
   增删/插位不再位移其余初值，结构体顺序与初值块解耦。
2. 删除本批引入的**死实验**：「四点触摸校准」（无 UI 入口、系误诊产物）
   与输入标定 env/marker 通道（`XGUI_INPUT_DX/DY/XSCALE/YSCALE`）一并移除。
3. 临时探针全量清理（见 §8.6）。
4. **安卓 DPR 链转正缺省开**（本轮计划项）：框架侧 `highDpiRenderingEnabled`
   与桌面统一口径——缺省开、`XGUI_DPR_RENDER=0` 精确关；安卓 env 是死通道
   （am start 不传进程环境），另认 adb 可写标记文件
   `/data/local/tmp/xgui_dpr_render_off.txt` 作为回退闸。
