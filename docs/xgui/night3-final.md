判读：

- **增量口径（A 路生效主战场）GPU 65→433–743 fps，脱离 60Hz 限频带，
  提升 ×7.9–×11.6**；脏区读回把每帧 800×600 全窗 glReadPixels 换成

- 整帧口径每帧全窗失效 → readbackRect 的 bbox 即整窗、自然退化为全帧
  读回（`XWidget.c:6003-6005` 注释即此设计），故整帧格维持 60Hz 限频带
  （59.7–66.0，页 6 更重 36.5–38.1），与基线持平（比值 ×0.91–×1.06，
  均在波动内）——符合预期，不是回归。
- SW 侧本夜整体变快（增量 +13–24%，exe 含 00:40 全部入树改动），故
  GPU/SW 比值的分母也在变好；增量口径差距仍从基线 93–149× 收敛到
  **14.7–18.2×**。
- **gpuBeatsSw = 否：16 格中 GPU 无一格 ≥1**。最接近格：整帧 page 6
  比值 0.091（38.1 vs 418.4，差 11.0×）；增量最佳 page 2 比值 0.068
  （742.6 vs 10898.0，差 14.7×）。8 个页格全部未超（0/8）。

## 3. A 路开关对照（XGPU_DIRTY_READBACK，GPU 增量口径，各采 1 遍）

开关语义以代码为准（`XWidget.c:6011-6018`）：env 未设或 `=0` →
`dirtyReadbackFallback=0` → **A 路（脏区读回 readbackRect）生效**；
`=1` → 回退每帧全窗读回（`:6008` 注释「置 1 回退」）。任务书把「=0」
称作回退态与代码相反，故两态都实测：`=1`（A 路关）与 `=0`（A 路开，
亦即任务书字面值）各跑 4 页，同 `-Takes 1` 口径成对对比。

| 页面 | =1（A 路关，全帧读回） | =0（A 路开，脏区读回） | A 路收益 | 终测矩阵第 2 遍（默认态） |
|---|---|---|---|---|
| page 0 | 650.5 | 724.6 | **+11.4%** | 737.1 |
| page 2 | 660.6 | 742.9 | **+12.5%** | 742.6 |
| page 4 | 453.1 | 502.0 | **+10.8%** | 517.1 |
| page 6 | 370.8 | 419.7 | **+13.2%** | 433.2 |

- **A 路收益：增量口径 +10.8%–+13.2%（均值 ≈+12%）**，四页方向一致。
- `=0` 与终测矩阵默认态差 0.1–3.3%（取第 1/2 遍的正常波动），实证
  `=0 ≡ 未设`，与代码解析一致。
- 整帧格两态无差（=1: 59.6/62.4/62.3/36.5 vs =0: 62.6/65.6/64.7/37.2，
  噪声内）——全窗失效下 readbackRect 本就退化为全帧读回，符合 §2 判读。
- SW 格两态亦无差（如 p0 增量 10761.5 vs 10721.4）——开关不触碰软件
  路径，对照组干净。

命令：`XGPU_PROF=1 xgui_bench3.exe --gpu --benchmark 3 --page 4`
（TEMP 副本、CWD=bin），输出：

```

[xgpu-prof] driver=opengl window=1

```

driver=opengl 且 fps=514.2 落在终测 GPU 增量带内 → GPU 路径真实激活，
非软件回退；渲染器仍为 AMD APU 核显 + 虚拟显示栈在位（与基线同环境）。

## 6. 结论

1. **GPU 反超 SW：未达成。** 同协议 16 格 GPU/SW 全部 <1（0.054–0.091），
   无任何负载反超；增量口径差距 14.7–18.2×，整帧口径 11.0–18.4×。
2. 但 A 路收益实测为正：增量 +10.8–13.2%，增量 GPU 绝对值 ×7.9–11.6 提升
   （65→433–743 fps）并脱离 60Hz 限频带；整帧格按设计维持限频带不变。
3. 闪烁清零（8/29→0/29，峰值 3826→0），远程栈翻动定性消除。
4. 剩余差距主体在整帧/全窗失效路径（仍被 60Hz 呈现限频钳制）与 SW 增量
   脏区 BitBlt 的极低成本；GPU 增量 433–743 fps 对 SW 7101–10925 fps 的
   11–18× 差距需继续压缩提交链成本（读回带宽、flush 路径）才可能反超。
