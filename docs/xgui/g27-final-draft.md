## 二、修复清单（文件:行 + 回退开关 + 证据）

四处修复开关为同一家族约定（[A] 逐处实读核实）：**变量设任意非 "0" 非空
值（惯用 `=1`）→ 旧路径诊断回退；`=0` 或未设 → 新行为（默认开启）**。
注意与「XX=0 恢复」直觉相反——恢复旧行为设 `=1`，不是 `=0`；`XGPU_SCISSOR_CACHE=0`
与未设等价（缓存保持开启）。

### P0-1 批后清画布按脏矩形宽 ✓

- 位置 [A 实读]：`Src/XGui/Graphics/XPainter.c:138-179`
  （`xgpu_batch_canvas_clear_rows`）；开关 `XGPU_CLEAR_ROWS_FULL=1` 回退
  每脏行整宽 memset 旧行为（`:144,153-158`）。
- 内容：批量暂存画布冲刷后，原每脏行整宽 memset 属白扫带宽——软件光栅
  写入恒被限在脏区内（painterGpuDrawCommand 脏区累计），画布其余像素本就
  应保持透明；改只清本批脏列 `[x0,x1)`（`:172-177`）。
- 效果 [M]：167.4→183.6 FPS。

### P0-2 scissor 同矩形缓存·安全变体 ✓

- 位置 [A 实读]：`Drive/windows/Graphics/XGpuRenderDriver_gl.c:1552-1611`
  （`xgld_set_clip_rect`）；开关 `XGPU_SCISSOR_CACHE`（`:1557-1563`，语义
  见上家族约定——设非 "0" 值=关缓存回退旧行为）。
- 内容：同矩形且已启用时直返，免去每命令一次 flush（此前批均 3–4 quad 即
  被 setClipRect 切断）。两道安全门防损坏：
  ①**批空门** `m_quadBatchCount == 0` 才早返回（`:1584-1589`）——有待定
  quad 时仍先 `xgld_flush_quads` 在旧 scissor 下落盘再改剪裁（`:1590`），
  顺序与剪裁语义不变，杜绝「待定 quad 被新 scissor 错误裁剪」的整页损坏；
  ②**旁路失效**——会话创建（`:1120`）、`xgld_begin_frame`（`:1324`）、
  present（`:1399`）三处旁路直接 `glDisable(SCISSOR_TEST)` 的路径置
  `m_scissorValid=false`，防同矩形早返回跳过重启用。
- 效果 [M]：198.7–206.0 FPS（健康期 best 206.0）。

### P0-3 BGRA 直传免 CPU R/B 交换（双路） ✓

- 位置 [A 实读]：
  ①drawImageRegion 子区域直传 `XGpuRenderDriver_gl.c:1735-1756`——
  `GL_BGRA + UNSIGNED_INT_8_8_8_8_REV` 字节语义（首分量取最低字节）与
  ARGB32 小端内存序 B,G,R,A 逐字节一致，配 `UNPACK_ROW_LENGTH=iw` 免
  CPU 逐像素 R/B 交换与暂存拷贝（桌面 GL 1.2+ 语义，AMD Radeon 实测
  4.6 支持）；开关 `XGPU_REGION_SWAP=1` 回退 CPU 交换旧路径
  （`:1740-1745`）。
  ②legacy 整幅直传 `xgpu_upload_image_flip` 快速路径
  `XGpuRenderDriver_gl.c:412-427`（无翻转时 ARGB32/预乘同布局直传）。
- 效果 [M]：181–193 FPS vs 直传前 112–146 FPS；颜色**逐位正确**（采样
  比对）。

### P0-4 flush 空 region 回退脏区包围盒 ✓

- 位置 [A 实读]：`Src/XGui/Widget/XWidget.c:5707-5743`；开关
  `XGUI_FLUSH_FULLFALLBACK=1` 恢复整窗 contentsRect 退化（`:5718-5723`）。
- 内容：region 未携带时（弹窗/菜单 `flush(NULL)`）原整窗退化在 GPU 直通
  持久 FBO 上表现为全页帧对闪与 FPS 覆盖层整帧重排抖动；改优先用当前
  脏区回退，回退链尾部保留整窗（m_dirty 空且无 region=首显/resize）。
- **教训（已吸收进实现）**：回退须用**包围盒单矩形**而非多矩形区域——
  paintTree 对区域逐矩形求交，多矩形脏区把每控件裁剪推入 O(控件×矩形)
  慢路，实测曾有 benchmark-full 掉帧至 1/3（58 FPS）（`:5731-5737` 注释
  在案 [A]）。
- 验证 [M]：autotest 143 PASS。

### ⑤ 环境卫生：周期性还原后台链清除 + 探针零残留 ✓

- 内容 [M]：清除周期性还原后台链（PID 15552）。
- 本草稿复证 [A]：
  ①`tasklist /FI "PID eq 15552"` → 「信息: 没有运行的任务匹配指定标准。」
  （该 PID 已不在）；
  ②三源文件（XPainter.c / XGpuRenderDriver_gl.c / XWidget.c）findstr 扫

## 四、遗留与建议

**遗留（按优先级）**
1. **整帧 ≥250 未达成**：健康期 best 206.0；后段 64–71 FPS 为环境性
   天花板，疑 AMD/RDP 显示栈态（非代码回归——与 night2 §2.3 SW 基线
   矛盾同款机制学：环境态维度必须入口径）。**建议**：复位显示会话后
   重测，沿 night2 基线协议（load%+CurrentClockSpeed 入元数据、单窗
   ≥8s、3 轮取中位、清理残留进程）。
2. **atlas stress 预存在失败**（本波正在修，【待填】）：修复结论回填前
   不视为门禁阻断项，但须在 §8.0g27 正式入册前收口。
3. **XGPU_PRESENT=swap 通道在 RDP 栈崩溃 0xC000041D**：swap 链路在
   RDP+OrayIdd 下帧不可达已是 §8.0g25/night2 双在册结论，崩溃码补齐
   证据链；readback（BitBlt 可达）保持默认通道。建议正式入册时把
   swap 通道标注「RDP 栈已知崩溃，非 RDP 环境待验」。
4. **PrintWindow 帧对闪烁量化未跑通**：以 autotest 143 + 目检替代收口；
   帧抓差分方法（night2 §4.6 capture_frames/diff_frames 口径）留待
   RDP 栈态复位后重试。
5. **开关语义家族约定与「XX=0 恢复」表述不一致**（[A] 本草稿核实）：
   四处开关实际均为「`=1`（或任意非 "0" 值）→ 旧路径；`=0`/未设 →
   新行为默认开启」。建议入册时统一表述为「`VAR=1` 诊断回退」，避免
   后人按「=0 恢复」直觉设错。

**建议（下波）**
- 整帧 250 线的剩余缺口在原语提交链（night2 §2.2：~454 原语/帧 ×
  ~15µs/原语），结构性出路仍是 P0-4 场景保留（原语 454→<30 验收锚，
  night2 §3 P0-4 在册），逐命令微优化已近收益边界。
- 终基准对照表回填时把「健康期/后段」两列拆开——今晚 64–71 vs 206
  的摆幅本身就是 RDP 环境态维度的第一手数据。
