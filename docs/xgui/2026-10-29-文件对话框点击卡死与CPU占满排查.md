# 文件对话框点击卡死与 CPU 占满排查（mcgs 192.168.1.252）

> 2026-10-29 排查战报。现象：在昆仑通态屏（mcgs，全志 A33，armel/fbdev）的
> XGuiWindowDemo「对话框」页点击「文件对话框」按钮后界面卡死、CPU 占满，
> 最终进程被杀（demo.log 末尾 `Killed`）。本文记录双端对照证据链、三个
> 已确认的框架层缺陷、已排除项、可复用的注入/诊断手法，以及尚未闭合的
> 两个尾巴。**结论先行：是框架问题，且不止一处；桌面同构建一切正常，
> 全部症状为设备（fbdev 单窗口 + armel）特有。**

## 1. 设备冻结时间线（用户现场的 demo.log 逆向）

日志共 3 次运行（`Terminated`×2 + 末尾 `Killed`）。最后一次运行：

- 启动于 line 104914（fbinput 接入、`switch page=19 窗口设置`）。
- 空闲段 `[FBSTAT] pan n=…` 以 ~1.5 pan/s 推进（顶栏时钟 1Hz 重绘口径）。
- `[29827.792] mousePress … pos=(421,385)` ← **最后一次触摸输入**。
- 随后 `[PUMPGAP] 268.2ms` 首次出现，`[WHEEL] lag=49~415ms` + `PUMPGAP
  300~892ms` 交替 **持续约 54 分钟**（cur 65570828→68812946），
  **FBSTAT pan 彻底停止**（渲染零输出）→ `Killed`。

读日志要点（下次排查直接复用）：

- `VDemoWin_mousePressEvent`（`Test/XGuiDemo/xgui_window_demo.c:4634`）
  是**顶层兜底日志**：press 被子控件消费时不打日志。所以「日志里没有
  mousePress」≠「没有触摸」，反而常常 = 按到了真按钮。
- `[PUMPGAP]`/`[WHEEL]` 是 2026-10-29 新加的诊断（默认关闭，设备端构建
  已打开）：`Src/XCode/XEvent/XAbstractEventDispatcher.c:807`（>200ms 泵
  间隔打点）。
- `[FBSTAT] pan n=` 每 500 次 pan 一条；归零即「自该点起零渲染」。

## 3. 三个框架层缺陷（待修）

### 缺陷 A：触摸 tap 被误合成为长按→右键（用户症状主因之一）

- 位置：`Src/XGui/Widget/XWidget.c` `xwidget_touchGestureFireLongPress`
  （约 :2899）+ 手势时钟 `xwidget_gestureNowMs`（约 :2780，触摸时间戳域
  优先、回退单调墙钟）+ 长按间隔 800ms（`XStyleHints`
  mousePressAndHoldInterval，`XWidget.c:2755` 查询）。
- 症状：设备上真人短 tap 频繁落成 `button=2`（右键）按下，且**第一发
  长按误触发后同会话后续触摸整段失联**（两个新实例均复现：首次 tap 正常，
  一次误判后注入的后续 tap 全部无 enter/press）。
- 疑点方向：释放沿的处理时机按主循环节拍走，循环一旦被重活拖慢
  （见缺陷 B），80ms 的 tap 在手势时钟上变成 >800ms；且误触发后手势
  状态机的 END/Abort 收口对不齐时整条触摸通路挂死。**与 `XWidget.c`
  注释里「长按退格中断根修（2026-10-25）」同族，建议一并复查。**

### 缺陷 B：fbdev 下嵌套模态循环渲染停摆 + 每圈数百毫秒重活

- 位置：`Src/XGui/Widget/XDialog.c:1252` `XDialog_exec`
  （`while (m_inExec) processEvents(All|WaitForMoreEvents)`）。
- 实测（设备）：模态打开后 WHEEL lag 在 60↔350ms 间翻板（每圈有
  300ms 级重活），FBSTAT pan 归零（合成器不跑）；用户侧即「画面冻结」。
  用户日志的 54 分钟 PUMPGAP 风暴 = 同一状态持续。
- 悬而未决：每圈的 300~900ms 具体花在哪（候选：poll 回调链
  xpfi_pump/远程帧泵、时间轮兑现、布局/重绘调度未在嵌套循环内驱动）。
  需要带逐线程 `/proc/PID/task/*/stat` 采样 + PUMPGAP 复现一轮。
- 另实测：**关闭对话框后仍有 ~100% 一个核不释放**（4000ms/2s），
  遗留空转的归属同样未定位。

### 缺陷 C：一次未定位的段错误

- 复现条件（不完全）：对话框页点「文件对话框」→ 按钮进入按压态
  （帧抓证）→ 1~4 秒内进程消失，demo.log 末行 `Segmentation fault`。
- 限制：该内核无 `/proc/sys/debug/exception-trace` 节点（dmesg 无用户态
  fault 记录）；根分区仅 ~6MB 可用（94% 用满），本地 core 放不下。
- **下次复现前的准备**（按序）：
  1. `ulimit -c unlimited` 后经 `xguidemo_run.sh` 拉起；
  2. `core_pattern` 用管道脚本把 core 经 nc 流回开发机（设备 busybox nc
     可用性需先验）；
  3. 或在 WSL 构建 Linux 版复现（§6.5，注意 Xvfb 下 demo 会无输入静默
     退出（exit 0，原因未查），但 `--remote-server` 端口可正常握手，
     输入注入路径可用）。

## 4. 已排除项（防止下次重走弯路）

- **控制字符文件名**：`/root/xguidemo` 有名为 `\x01\x02\x1aZ` 的文件
  （0 字节，旧物）。最初怀疑是列目录崩溃诱因，但对话框首过滤器为
  「文本文件 (*.txt)」，该文件**根本不进列表**——崩溃运行同样如此。
  嫌疑大幅削弱但未完全排除（「所有文件 (*)」过滤器的列表路径未测完，
  远程会话重建时监听端劣化，见 §7）。
- **窗口激活门控**：Win32 后端无 WM_ACTIVATE 门控，PostMessage 注入
  有效（`Drive/windows/Graphics/XPlatformNativeWindow_win32.c:2112`）。
- **单文件名合法性**：`\x01\x02\x1aZ` 是合法 ASCII/UTF-8（控制字符），
  XString/strcmp 排序层面无编码坑；NTFS 不允许控制字符文件名，桌面
  无法精确重演此名（WSL ext4 可）。
- **evdev 注入协议**（绕过 xinj2 时用）：16 字节 `input_event`
  (i32 sec, i32 usec, u16 type, u16 code, i32 value)；ST 单点屏按压判据
  是 **BTN_TOUCH(0x14A)**（`Drive/Posix/Graphics/XPlatformFbInput_posix.c`
  状态机：BTN_TOUCH=全局接触判据，ABS_PRESSURE 只补坐标有效性）；
  **内核对与当前状态相同的注入事件静默丢弃**——重复同坐标 tap 会
  「失联」，需加抖动。真空触流（TSC2007）无 BTN_TOUCH、压力 ~700 连续
  上报。

## 5. 可复用的注入/诊断手法（本次沉淀）

### 5.1 远程协议注入（推荐：框架级鼠标事件，绕过触摸手势）

设备自启配置即带 `--remote-server --remote-port 46300 --remote-profile
resource`（`/root/start_xguidemo.sh`，注意该文件 2026-10-29 晚被误移至
`/root/`，见 §7）。协议要点（全部实测）：

- 连接后**服务端先发 8 字节 banner**：`"XGR1" + u16 版本(LE) + u16 保留(0)`
  ——**客户端 banner 必须也是 8 字节**（少发 2 字节会被服务端把帧头前缀
  粘进 banner，流错位后长度字段判 >16MB 报 ERR_PROTOCOL(1) 断链）。
- 帧格式：`u32 负载长(LE) + u8 类型 + 负载`。
- HELLO(type 1)：`u16 版本 + u32 caps + u8 auth(0=无) + u16 名长 + 名`；
  回 HELLO_ACK(type 2) 后即 STREAMING，可发 INPUT_POINTER。
- INPUT_POINTER(type 11，16 字节)：`u8 action(0 move/1 press/2 release)
  + u8 button(1=左/2=右) + u16 buttons + u32 modifiers + i16 x + i16 y +
  u32 timestampMs`，坐标=远端窗口客户区坐标。
- 可用脚本：WSL `/tmp/click.py`（单点击）、`/tmp/cli.py`（含十六进制
  收帧调试）。**注意**：服务端似有单会话约束，断链后短时间重连会被
  拒/收残帧，重试或重启应用可解。

### 5.2 全屏对话框页关键坐标（1024x600）

| 目标 | 客户区坐标 |
| --- | --- |
| 导航「对话框」 | (113,393) |

| 文件类型下拉 | (565,467) |

### 5.3 帧抓与换算

- `dd if=/dev/fb0 of=x.raw bs=1228800 count=1`（单缓冲，可见即唯一缓冲，
  禁裸 dd 的旧口径是针对 pan 多缓冲场景）→ Python RGB565 小端转 PNG
  （行距 2048）。
- 触摸标定：`/etc/pointercal` =
  `-65 -17145 68857112 10909 117 -2486499 65536`；**app 实际落点 =
  xinj2 面板坐标 + (-24,-1)**（fbinput 内建偏移，实测两点线性确认）。
- evdev 直写替代 xinj2（若工具再丢）：SSH 管道
  `cat > /dev/input/event0`，raw 值可由 xinj2 历史 print 反推
  （raw_x=0.0398x+6.0046y+185.7, raw_y=-3.8204x-0.0158y+4011.9）。

### 5.4 日志/状态速查

- app 日志：`/root/xguidemo/demo.log`（stderr 通道，追加写）。
- CPU：`A=$(awk '{print $14+$15}' /proc/$P/stat); sleep 2; B=$(awk …);
  echo $(( (B-A)*50 ))` ms/2s（USER_HZ=100、双核板，>2000 即超一核）。
- 线程/wchan：`for t in /proc/$P/task/*; do … $t/stat $t/wchan $t/comm`；
  本应用单线程，state=R 持续 = 主循环在烧。
