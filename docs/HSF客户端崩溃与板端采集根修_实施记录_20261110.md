## 一、本地客户端启动即崩（Run-Time Check Failure #2）

### 1.1 现象与定位

MSVC 弹窗原文：

```
Run-Time Check Failure #2 - Stack around the variable 'cols' was corrupted.
```

`/RTC1` 的栈检查点名了变量名 ⇒ 直接锁定 `HsfDataHistory.c` 里的
`uint32_t cols[15]`。历史页 16 列（新增「水温(℃)」）是**显示列**，
而那三处栈数组还停在 15：

| 位置 | 用途 |
|---|---|
| `histRequest` | 请求时按可见列下标取线 |
| `histExportStart` | 导出时按可见列下标取值 |
| `histChartRequest` | 画折线时按可见列下标取点 |

`histVisibleCols()` 按 16 列写满 15 元素数组 ⇒ **每元素 4 字节越界
4 字节** ⇒ 踩坏栈上相邻变量 ⇒ 启动即崩。

### 1.2 修法：类型别名 + 编译期断言（不是"记得改长度"）

改长度是治标——下次再加列又会踩。改成**长度与列数绑死**：

```c
/** @brief 可见列下标数组类型（**容量 == 显示列数**）。 */
typedef uint32_t HistCols[HSF_HISTORY_DISPLAY_COLS];
typedef char hist_cols_size_assert[
    (sizeof(HistCols) == sizeof(uint32_t) * HSF_HISTORY_DISPLAY_COLS)
        ? 1 : -1];
```

调用点用宏再断言一次（真实变量可下标，故能在调用点校验）：

```c
#define HIST_COLS_SIZE_ASSERT(cols)                                   \
    typedef char HIST_COLS_ASSERT_CAT(hist_cols_size_assert_at_,      \
                                      __LINE__)[                      \
        (sizeof(cols) / sizeof((cols)[0]) == HSF_HISTORY_DISPLAY_COLS)\
            ? 1 : -1]
```

两个坑（都实踩过）：

- **`_Static_assert` 在本项目不可用**：MSVC 默认 C 模式（非 C11）拒绝
  `_Static_assert` ⇒ 改用**负数组长度 typedef 断言**（C89/C99 通用，
  两家编译器都生效；不匹配时报 C2118/C2148）。
- **C 里 typedef 的数组名不可下标**：`sizeof(HistCols[0])` 非法 ⇒ 文件级
  断言只能比较 `sizeof(HistCols) == sizeof(uint32_t) * N`，调用点宏
  （真变量）才能下标。

**结论已验证**：人为把 N 改错 → 编译期直接报错（不再等到运行期踩栈）。

## 二、历史页 16 列与表头空白

### 2.1 表头空白（4 列）

「输出频率(Hz)」「搅拌转速(rpm)」「浊度1(NTU)」「浊度2(NTU)」四格**全空**。

- 根因（两层）：
  1. **应用层**：列宽按固定经验值给，而表头文字（QSS 下 `font-weight:bold`
     + `padding: 6px 8px` + `border-right: 1px`）实宽比经验值多 1~2px；
  2. **框架层**：QSS 表头绘制路径里有一条「文字放不下就**不画**」的分支
     ⇒ 不是省略号，是**整格空白**。
- 修法（两层都改）：
  - 应用层：列宽改为**按当前字体实测表头文字**（`XPainter_textWidth`）+
    `HIST_HEADER_EXTRA_PX 17`（QSS padding 6+8 + border 1 + 余量），
    与 Python 端 `auto_min_texts` 同口径；
  - 框架层：改成**先省略再画**（Qt 6.8 语义：文字永远有输出，超宽走省略号
    而非留空），复用既有原语 `XCommonStyle_elideText`；
    同步把 `QStyleOptionHeader::m_textElideMode` 补上
    （`XAbstractItemViewTextElideMode` 枚举从 `XAbstractItemView.h` 移到
    `XStyleOption.h`，全树单一编号），`XTableWidget` 注入与单元格同款。

### 2.2 「水温(℃)」列

- 线上列序**追加在末尾**（19 列）：`history.water_temp`，
  `HSF_HISTORY_WIRE_COLS` 是单一定义（服务端 `HSF_HISTORY_COLUMNS` 就是它），
  Python `store.HISTORY_COLUMNS` 同序；
- 显示列序另有一套（16 列）：水温插在第 8 位（紧跟「浊度2」）；
  服务端 `DISPLAY_COLUMNS/DISPLAY_EXPR`、C 端 `kHistoryHeaders[16]`、
  Python `HistoryPage.COLUMNS` 三处同步；
- C 客户端 `HIST_NUM_LAST` 12→13（水温也画折线）。

## 三、关键字筛选「静默返回 0 行」

### 3.1 根因：缓冲区截断 ⇒ SQL 语法错 ⇒ 无声失败

`HsfServerStore.c` 的关键字条件缓冲是 `char kwCond[1536]`，而 16 列的条件
字符串实长 **1544 字节** ⇒ 截断 ⇒ SQL 语法错 ⇒ 查询返回 0 行，
**且没有任何错误提示**（用户看到的是"筛不出东西"，不是"报错了"）。

修法（两条都要）：

1. 缓冲放大到 8192（`sql` / `where` / `kwCond` 三处同步）；
2. **fail-closed**：条件构造失败时**显式记日志并返回 0 行**，
   不再让截断的 SQL 悄悄跑（`storeBuildKwCondition` 返回 bool，
   失败即 `XPrintf("关键字条件未建出…⇒ 本次查询返回 0 行")` + return 0）。
   日志类同样处理（`storeBuildLogKwCondition`）。

**验证**：0 行 → 20 行；Python 客户端回归 1239/1 → **1240/0**。

## 四、历史页时间戳跳一天 + 整表粉红

### 4.1 时间戳跳一天

- 根因：用 `XTime_addMSecs` 跨天——它只绕 24 小时，**不向日期借位**
  ⇒ 「昨天 12:00」显示成「今天 12:00」（age < 24h 时恒现）。
- 修法：改走**绝对纪元毫秒 + 时区偏移**：
  ```c
  const XDateTime nowLocal = XDateTime_currentDateTime();
  tzOffsetMs = XDateTime_toMSecsSinceEpoch(&nowLocal)
               - XDateTime_currentWallMSecsSinceEpoch();
  XDateTime_setMSecsSinceEpoch(&dt, ts + tzOffsetMs);
  ```

### 4.2 整表粉红（异常行全被判）

- 根因：异常判定读 `m_cells[10]`——**插了水温列后下标平移**，
  `m_cells[10]` 变成了「正累计」（几乎总有值）⇒ 每行都被判异常。
  且判据本身也错（应是"压差说明文字非空"，不是"格值 ≠ --"）。
- 修法：解析时用**逐行局部** `pressNote` 标记（取自说明文字格），
  行解析完再落 `m_abnormal`；**判据 = 说明文字非空**（对齐 Python 的
  `bool(press_note)`）。

### 4.3 回归锁（`Test/XProtocolTest/hsf_regression_test.c` §N6，8 断言）

构造"昨天 23:59:59"（age 恒 < 24h ⇒ 旧 bug 必现）：

- 显示值 == 期望值（把实现回退一次 ⇒ 断言转红，已实测）；
- 有压差值但**无说明** ⇒ 不算异常；
- 有累计值但无说明 ⇒ **不算**异常（这条卡"整表粉红"方向）；
- 有说明 ⇒ 算异常；
- 浊度 ≥ 20 NTU ⇒ 算异常。

## 五、陈旧阈值必须随采集周期联动（板端「数据过期」反复闪）

### 5.1 根因

陈旧阈值与采集周期是**两个独立的量**，但有硬约束：**stale 必须 ≥ 周期**，
否则两拍之间值必然被判陈旧 ⇒ 界面在「---」与真值之间来回闪。

现场实锅：温湿度周期改成 1 分钟（60000ms）> 固定 stale 5000ms ⇒
几秒后就变「---」。

### 5.2 口径

```
有效阈值 = max(设备基线 stale, 采集周期 × HSF_STALE_FROM_POLL_MULT(=3))
```

倍数 3 = 允许连丢 2 拍仍不判陈旧（丢 1 拍是正常等待）。

### 5.3 落点（**两层都要改**，这是本项最容易漏的点）

- **设备层**：`XTempHumTransmitter_setStaleMs` / 浊度 / 流量计；
- **站级层**（`HsfServerIoTempHum/Turbidity/FlowMeter`）：各站结构体新增
  `uint32_t m_staleMs`，挂载时赋值、质量判定改用 `st->m_staleMs`
  （`XModbusHub_pointValid(hub, area, addr, staleMs)`），
  运行期改周期时同步更新两层。

> **只改设备层是修不好的**：站级质量判定仍按编译期宏
> （`HSF_TEMPHUM_STALE_MS`）⇒ 现场仍闪。本轮实锅：先只修了设备层，
> 板端仍旧「数据过期」；补齐站级层后板端快照 `staleMs=30000` 正常。

另：变频器另有基线 `HSF_VFD_STALE_MS=3000`——设备层缺省是
「发布周期 × 5 = 1000ms」，而 Modbus Hub 每拍只发**一个**读组，
现场变频器 14 组 × 200ms = **2.8s 一圈** ⇒ 1000ms 连一圈都盖不住。

## 七、板端部署与实机（2026-11-10 21:00~21:35）

### 7.1 链路（WSL 交叉编译 → scp → systemd-run）

```bash
# 1) 同步工作区到 WSL（排除 .vs/.git/out/bin）
rsync -a --delete --exclude='.git' --exclude='.vs' --exclude='out' \
      --exclude='bin' --exclude='.zcode' --exclude='docs' \
      /mnt/f/Code/CMake/XinYueC/ /root/xinyuec-src/

# 2) 交叉编译（端口/总线开关必须走 **编译器宏** -DCMAKE_C_FLAGS）
PORT_FLAGS='-DHSF_BUS_A_PORT=\"/dev/ttyS3\" -DHSF_BUS_B_PORT=\"/dev/ttyS4\" -DHSF_BUS_B_ENABLED=1'
cmake /root/xinyuec-src -DCMAKE_BUILD_TYPE=Release \
     -DCMAKE_TOOLCHAIN_FILE=/root/toolchain-aarch64.cmake \
     -DCMAKE_RUNTIME_OUTPUT_DIRECTORY=/root/xinyuec-src/out-arm \
     -DCMAKE_C_FLAGS="$PORT_FLAGS"
make -j$(nproc) HsfServer HsfClient

# 3) 部署（先停进程，否则 ETXTBSY）
pkill -f "HsfServer|HsfClient"; scp out-arm/Hsf{Server,Client} root@BOARD:/root/Desktop/XinYueC/bin/
md5sum 双向比对

# 4) 启动（板端 C 栈**没有 systemd 单元**，用 systemd-run 建 transient unit）
systemd-run --unit=hsf-c-server.service --property=WorkingDirectory=/root/Desktop/XinYueC/bin ./HsfServer 6100
systemd-run --unit=hsf-c-client.service --property=WorkingDirectory=/root/Desktop/XinYueC/bin \
             --property=Environment=DISPLAY=:0 ./HsfClient --login root:root@127.0.0.1:6100
```

坑：

- `-DHSF_BUS_A_PORT=...` **当 CMake 变量传是无效的**——真实机制是
  编译器宏（`-DCMAKE_C_FLAGS`）。传错 ⇒ 二进制用 Windows 缺省 COM17/COM18
  ⇒ 板端 485 全离线（"两端都开着但一个设备都不在线"）。
- `wsl.exe` 会把 `/root/...` 路径啃成 `D:/Program Files/Git/root/...`
  ⇒ WSL 内跑脚本时用 `wsl.exe -e bash -lc "bash /root/xxx.sh"`，
  脚本先 `cp` 进 WSL 本地再执行；`rsync` 源用 `/mnt/f/...` 形式。
- `rsync` 必须 `--exclude='.vs'`（`.vs/FileContentIndex/*.vsidx`
  权限拒绝 ⇒ 整条 rsync 失败）。
- 板端服务是 **transient unit**（`systemd-run` 建的），`systemctl stop`
  后单元即消失 ⇒ 重启必须**重建**。

## 八、未修完 / 待现场复验（**本节是重点**）

### 8.1 「10000 ms」被显示成「0000 ms」——**根因已定，改动已落，未板端复验**

**根因链**（Qt 6.8 源码逐行核对，见 `qabstractspinbox.cpp:866-898`）：

1. Qt 的 `QAbstractSpinBox::sizeHint()` = 文本宽 + `style()->sizeFromContents(CT_SpinBox)`，
   且**高度取 `d->edit->sizeHint().height()`**（内嵌编辑框自己的提示）；
2. 我们的 `spinbox_computeSizeHint()` 早期只量**当前文本宽**，值从 3 位
   变 5 位时宽度不跟 ⇒ 布局不重协商 ⇒ 文本溢出；
3. 更关键：Qt 的 `sizeHint` **没有**把"内嵌编辑框自身的边框内缩"漏掉，
   而我们漏了 ⇒ 预留宽比实际可用文本区**少 8px**（左右各 4px，
   `xlineedit_textStartX`/`textEnd` 各让 `frame?4:2`）⇒ 文本放不下
   ⇒ 行编辑按光标位置**横向滚动**（保后缀、裁前导数字）
   ⇒ 「10000 ms」显示成「0000 ms」。

**已落地的改动**（`Src/XGui/Widget/XSpinBox.c`）：

- 按 Qt 口径取**最宽候选值**：`textFromValue(min)` / `textFromValue(max)` /
  当前值三者取最大（`+ specialValueText` 语义）；
- 用**内嵌编辑框自己的 sizeHint 减去其当前文本度量**求出差值
  （`chromeW` / `chromeH`）⇒ **与绘制路径同源**（不写死像素），
  且度量用**编辑框自己的字体**；
- 最终宽度 = `sizeFromContents(CT_SpinBox)` 结果 **+ chromeW**。

**为什么还不能算修好**：

- 本地只验证到**编译通过**（`ninja HsfClient` → NINJA_EXIT=0）；
- 板端二进制已部署（md5 一致：HsfServer `6dd1f240…`、HsfClient `789d3a55…`），
