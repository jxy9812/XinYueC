# HSF 变频器参数设置：三端实施记录（2026-11-18）

> 起因：用户要求远程查看/设置变频器（M512）的**参数**（电机铭牌组起步），且
> 口径明确——「界面上显示的必须是变频器里实际的值，不是我以为写进去的值」。
> 本轮战役：① 新增 **0x011B 参数读/写**命令并在 Python 服务端 / Python 桌面
> 客户端 / 网页端三端落地（C 端只占协议号，用户明确暂缓）；
> ② 收尾 2026-11-17 变频器故障复位透传（补回归锁）；③ 网页端报警页数据源
> 对齐 0x011A（服务端单一数据源）；④ 对 10 项历史需求做完成度审计。

## 1. 背景与范围

- **参数 ≠ 运行控制**：既有 0x0101（启停/调速/点动）是运行期动作；参数
  （P1 电机铭牌组等）是**停机维护动作**——需要独立的权限闸（写=管理员）与
  **运行锁定**（变频器在转时不许写），且必须**回读确认**（总线 ACK ≠ 写进去了，
  运行锁定下的写驱动器会 ACK 但不生效）。
- **范围**：第一期只开放 **P1 电机铭牌组 6 项**（0xF100~0xF105）；后续扩组 =
  在 PARAM_DEFS 追加条目，三端镜像与对账回归自动跟上。
- **C 端**：用户明确暂缓（`XhsfLinkProto.h` 只占协议号防他号复用）。

## 2. 协议契约（0x011B CMD_VFD_PARAMS）

**单一事实源** = `HighSpeedFilter/server_py/hsfsrv/proto.py` 的
「变频器参数读写（0x011B）」节（常量、键名、文案、参数表都在那里）；
C 侧 `common/XhsfLinkProto.h` 的 `HSF_CMD_VFD_PARAMS 0x011Bu` 同号。

**请求（BSON）**：

```text
{"op": 0=读整组 / 1=写若干项,
 "values": {"<addr 十进制字符串>": raw(int32)}}   ← 写才带
```

- **为什么键是十进制字符串**：BSON 文档键只能是 cstring（两端 bson.py/_cstr
  与 C 侧 XBsonDocument 同口径），int 键上不了线。地址以十进制串作键
  （"61697" = 0xF101；**0xF100=61696，0xF000 才是 61440**——别混）。
- 服务端 `int(key)` 归一后校验，解析不了即报错（fail-closed）。

**应答（BSON）**：

```text
{"ok": bool, "err"?: utf8,
 "params": [ {code, label, addr, raw, value, unit,
              writable, runLocked, applied?} ... ],
 "vfdFaulted": bool, "runState": int}
```

- `params[].value` = **服务端从驱动器回读的工程值**（raw ÷ scale）。写操作后
  服务端**重新读驱动器**再用回读值填表（重试 ≤3 次 × 0.2s，跨不应答窗口），
  **绝不把提交值当成功值**。
- `params[].applied` 仅写操作的项携带：True = 回读值与写入值一致。
- `runState` = 0x3000 原始字（1 正转 / 2 反转 / 3 停机）；
  `vfdFaulted` = 0x8000 ≠ 0。
- 失败包络（未装配/离线/权限/运行锁定）**不带 params**，只带 ok/err。

**闸门**：

| 动作 | 权限 | 说明 |
|---|---|---|
| 读（op=0） | 登录即可（PERM_VIEW） | 只读面 |
| 写（op=1） | 管理员（PERM_ACCOUNT_ADMIN） | 0x0117 config_set 同款闸与拒绝文案 |
| RunLocked | 0x3000 = 1/2（运行中）⇒ 拒写，**不发总线写** | err=「变频器运行中禁止写参数（请先停止）」**三端同款文案**（客户端按文案匹配展示，漂移会让现场看到两套说法） |
| 变频器未装配/离线/总线失败 | 一律包络 | err=「变频器未就绪」（与 _h_vfd_control/_h_vfd_snapshot 既有文案同字面），不给假值 |

## 3. 参数表：P1 电机铭牌组（0xF100~0xF105）

数据来源**不是编的**：`docs/M512_511_512_513寄存器映射表.md` §9.5 参数描述表
（与 C 侧 `Src/Industry/XVfd/XVfdM512.c` 的 `s_m512Params[]` 逐项一致）；
0xF100 段组表允许 **6 连读**（单帧 ≤12 上限内，见该文档 §9.2）。
scale = 10^小数位（C 侧 `XVfdParamDesc.m_decimals`：raw ÷ 10^decimals 为工程值）。

| code | label | addr | unit | scale | min | max | 模拟器缺省 raw |
|---|---|---|---|---|---|---|---|
| P1.00 | 电机类型选择 | 0xF100 | — | 1 | 0 | 2 | 0（异步机） |
| P1.01 | 电机额定功率 | 0xF101 | kW | 10 | 10 | 10000 | 150（=15.0 kW） |
| P1.02 | 电机额定电压 | 0xF102 | V | 1 | 1 | 2000 | 380 |
| P1.03 | 电机额定电流 | 0xF103 | A | 100 | 1 | 65535 | 3000（=30.00 A） |
| P1.04 | 电机额定频率 | 0xF104 | Hz | 10 | 1 | 50000 | 500（=50.0 Hz） |
| P1.05 | 电机额定转速 | 0xF105 | rpm | 1 | 1 | 65535 | 1440 |

- 第一期全部 `writable=True` + `runLocked=True`（手册 RunLocked 列）。
- **P1.04 的小数位手册标「1（待实机标定）」**——先按 1 落，实机标定后三端
  同步改（server proto.py / client proto.py / webui page14_remote.js scale 表）。

**镜像关系**：`server_py/hsfsrv/proto.py` PARAM_DEFS 是单一事实源；
`client_py/hsfsrv_client/proto.py` 与 `webui_py/hsfweb/proto.py` 各镜像一份，
回归锁逐值对账（客户端 §V9；webui_check 静态检查）。

## 4. 三端实现要点

### 4.1 Python 服务端（`server_py/hsfsrv/app.py`）

- `_h_vfd_params`（注册进 CMD 分派表）→ 读直接整组回读；写分派给
  `_vfd_params_write`。闸门顺序：包络（未就绪）→ 权限 → RunLocked → 解析。
- `_vfd_params_norm_values`：values 键 `int()` 归一 + 按地址表校验
  （未知地址/解析失败即报错，fail-closed）。
- **写后回读**：写完重新读驱动器，回读值填 `params[].value`，逐项比
  `applied`；回读失败重试 ≤3 × 0.2s（跨 M512 偶发不应答窗口）。
- 读参数走既有变频器读组链路（0xF100 段 6 连读），失败进「变频器未就绪」包络。

### 4.2 Python 桌面客户端（`client_py/hsfsrv_client/`）

- `bridge.vfd_params(op, values)`（0x011B 请求，应答经网络线程 emit 回 UI 线程）。
- `pages_other.py` 远端设置页新增**「变频器参数」卡**（位置在「运行保护」卡
  之后）：每参数一行（code+label+回读值+unit）、可写项输入框（量程按参数表
  min/max 夹取）+「刷新」「应用」；无管理权限时输入框与「应用」置灰、
  「刷新」常可用（读=登录即可）。
- **显示只认回读值**：本地不做「写成功就把输入值当现值」的假设；写成功文案
  **「已写入并回读确认：N 项」**（有失败项时逐项列名）。
- 终态纪律：「正在读取/正在写入变频器参数…」必有成功/失败终态且不被例行
  消息覆盖（A4 同款）；入页自动读一次 + 重连补读。

### 4.3 网页端（`webui_py/hsfweb/`）

- `hub.vfd_params()`：0x011B 请求转发（复用既有 XLink 请求通道）。
- `api.py`：`GET /api/vfd/params`（读，PERM_VIEW 三档都放行）/
  `POST /api/vfd/params`（写，PERM_ACCOUNT_ADMIN，只收 op=1）。
- `static/js/pages/page14_remote.js`：远端设置页**卡 7「变频器参数」**同名
  区块——工程值↔raw 换算的 scale 表前端镜像一份（注释点名三处同源）；
  显示值=服务端回读值；「正在读取/正在应用」状态行 + 入页自动读一次
  （一次真实 485 读，不随节拍轮询）。

### 4.4 C 端（占号）

- `common/XhsfLinkProto.h` 加 `#define HSF_CMD_VFD_PARAMS 0x011Bu` + 注释
  「暂缓实现，协议号先占住防他号复用，契约见 server_py proto.py 的 0x011B 节」。
- C 服务端/客户端的实现用户明确暂缓（见 §9 待办）。

## 5. 模拟器（`server_py/hsfsrv/virtualdev.py` VirtualVfd）

- 补 **0xF100~0xF105** 参数组：`PARAM_DEFAULTS`（0/150/380/3000/500/1440，
  按手册标度编码的 raw 原始码）；读路径（组读）与写路径（FC06 单写落
  `self.params`）都接上。
- **运行中写不应用**（0x3000=1/2 时 FC06 应答成功但寄存器不落）＝模拟真机的
  RunLocked 拒写行为 ⇒ 服务端写后回读看到不一致 ⇒ `applied=False`。
  这条行为被 `test_vfd_params.py` C3 锁住——没有它，「回读不撒谎」在 sim 里
  永远测不到。

## 6. 战役内其它三项

### 6.1 变频器故障复位透传（2026-11-17 实施，本轮收尾回归锁）

- 主页「复位」op=4（AUTO_OP_RESET）在变频器处于故障时**顺带给变频器发故障
  复位**（写 0x2000=7）：`app.py` 新增 `_auto_reset_and_vfd()`——`ctl.reset()`
  之后若变频器 faulted/fault_code 非 0 ⇒ `vfd.apply_control(OP_RESET_FAULT)`
  （与变频器页「故障复位」按钮同一条命令，走设备级命令锁串行）；**无故障不写
  总线**；下发失败只记日志不拦（复位的清锁存部分照常生效）。变频器页的故障
  复位按钮本来就发，零改动。

  否则断言「命令真的清了变频器故障」没有落点。

## 8. 三个坑（本轮实锅）

1. **0xF100 的十进制是 61696，不是 61440**：报告/注释里两处把 0xF100 误算成
   61440——那是 **0xF000** 的十进制；addr 键面锚错一个段（0xF100 段的注释/
   文档里出现 61440 即为错）。已修两处注释（server proto.py / client
   proto.py）。凡手算十六进制↔十进制，用工具算，别心算。
2. **values 键必须十进制字符串**：BSON 文档键只能是 cstring，int 键上不了线；
   服务端 `int(key)` 归一后校验、解析不了即报错（fail-closed），不让拼错的
   键悄悄丢掉。
3. **自洽测试抓不到「地址错」**：服务端测试的 FakeVfd 与虚拟模型若用**同一组
   地址**，地址写错了测试照样全绿（写进哪儿就从哪儿读回）。⇒ 地址必须对着
   手册（`docs/M512_511_512_513寄存器映射表.md` §9.5）与
   `XVfdM512.c` 的 `s_m512Params[]` **逐项核**（本轮主线程核过；test_vfd_params
   D 段再把表钉进回归，防后续漂移）。
