## 一、结论摘要

### 1.1 直接可用的取数方法（**先看这一节**）

**一条命令拿到温湿度，已验证**：

```
发: 04 04 00 00 00 02  71 9E
收: 04 04 04 00 D9 02 88 7E 79
      │  │  │  └─┬─┘ └─┬─┘ └─CRC─┘
      │  │  │   温度    湿度
      │  │  └ 4 字节数据
      │  └ FC04（读输入寄存器）
      └ 站号 4

温度 = 0x00D9 = 217 → 217 × 0.1 = 21.7 ℃
湿度 = 0x0288 = 648 → 648 × 0.1 = 64.8 %RH
```

- 功能码：**FC04**
- 起始地址：`0x0000`，数量 **2**
- 解码：**两个 uint16，各 × 0.1**
- 负温度：`raw >= 10000` 时 `-1 × (raw - 10000) × 0.1`（手册 2.1）

> **这就是全部所需**。下面的章节是约束、坑和证据。

### 1.2 关键参数确认

| 项 | 实测 | 与你给定值 | 判定 |
|---|------|-----------|------|
| 串口 | `COM17`（CH343 USB-485，VID:PID=1A86:55D3） | COM17 | ✅ |
| 波特率 | **115200**（保持寄存器 `000BH = 7`） | 115200 | ✅ |
| 数据格式 | **8N1** | — | ✅ |
| 站号 | **4**（保持寄存器 `000AH = 4`；1~247 全扫仅 4 应答） | 4 | ✅ |

### 1.3 实测数据概览

| 项 | 值 |
|---|---|
| 当前温度 | **21.3 ~ 21.7 ℃**（多次采样） |
| 当前湿度 | **64.8 ~ 65.4 %RH** |
| 单帧往返（读 2 个寄存器） | p50 **5.81 ms** / p95 7.45 ms |
| 单帧往返（读 6 个寄存器） | p50 **6.64 ms** / p95 6.72 ms |
| 30 s × 1 Hz 长稳 | **30/30 成功**，温湿度稳定不跳变 |
| 连续 2000 帧 | 异常 11 帧（**0.55%**），见 §5.2 |

## 二、寄存器映射（实测）

### 2.1 输入寄存器（FC04，只读）

| 协议地址 | PLC 地址 | 实测值 | 功能 | 解析 |
|---------|---------|-------|------|------|
| `0000H` | 30001 | 213~217 | **温度 uint16** | `v>=10000 ? -1×(v-10000)×0.1 : v×0.1` |
| `0001H` | 30002 | 647~654 | **湿度 uint16** | `v×0.1` |
| `0002H~0003H` | 30003~30004 | `0x41AB 0x1EDB` | 温度 float32 | 大端，≈21.3901 |
| `0004H~0005H` | 30005~30006 | `0x4282 0x954A` | 湿度 float32 | 大端，≈65.2916 |
| `0006H~0013H` | — | 0 | 保留（可读写，不参与功能） | — |
| `0014H` 及以上 | — | — | **不存在**，请求静默丢弃 | — |

> 手册表 2.1 与本表一致。

### 2.2 保持寄存器（FC03 读 / FC06 写）

| 协议地址 | 实测值 | 手册 | 说明 |
|---------|-------|------|------|
| `0000H~0005H` | 与输入寄存器同值 | 表中误列 | 输入寄存器的镜像 |
| `0006H~0009H` | 0 | 未定义 | 通用可写 RAM（写 1234 可读回） |
| `000AH` | **4** | 站号（默认 1） | ✅ 一致 |
| `000BH` | **7** | 波特率索引（0:4800 … 7:115200） | ✅ 索引 7 = 115200 |
| `000CH~0013H` | 0 | 未定义 | 保留 |
| `003DH` | **不存在** | 奇偶校验 | ❌ **手册错误，见 §4.2** |

### 2.3 手册地址表的排版错误

手册表 2.1（输入）与表 2.2（保持）的 PLC 地址列**完全相同**（都是 30001~30006）。保持寄存器按惯例应为 `40001` 起。属排版复制错误，**设备行为本身正常**（FC03 读 `000AH` 返回 4，确认是保持寄存器语义）。

## 四、取数时必须遵守的约束

### 4.1 ⚠ 一次 write 送出完整帧（帧内字节间隔 ≤ 1.5 ms）

模块用约 1.5 ms 的字符超时判帧结束。**逐字节发送会整帧丢弃、静默无响应**：

| 字节间隔 | 应答率 |
|---------|-------|
| 0 ~ 1.2 ms | 15/15 ✅ |
| 1.8 ms | 12/15 ⚠ |
| 2.0 ms | 4/15 ⚠ |
| 3.0 ms | **0/15** ❌ |

**要求**：
- 一次 `write()` 写出完整 8 字节；
- Linux 串口必须 `cfmakeraw()`（关 `ICANON`/`ECHO`/`OPOST`）+ `VMIN=0, VTIME=0`；
- 115200 下 8 字节 0.7 ms 发完，正常不会触发；**只有应用层逐字节写才会踩到**。

### 4.2 ❌ 手册的 `003DH`（奇偶校验）不存在

- 逐地址扫 `0000H~0060H`：**`0014H` 及以上全部超时**；
- `FC03 003DH` → timeout；`FC03 003CH` → timeout；
- 有效地址上界精确为 `0013H`，与块读上限 20 完全自洽。

**结论**：本固件**没有**校验配置寄存器。校验方式只能在出厂/烧录时确定，实测 **8N1**。**软件层不要写 `003DH`**，会静默失败并被误判为通信故障。

> 注：8E1/8O1/8N2 也「能读到数据」是**假阳性** —— 从站按 8N1 发送，主机按带校验位方式采样时位宽误差落在采样窗内，恰好能对齐。**不能据此判断校验方式**。

### 4.3 ⚠ 非法请求静默丢弃，无异常码

| 请求 | 结果 |
|------|------|
| 非法功能码 `0x63`（120 次） | **120/120 静默超时** |
| FC01 / FC02 / FC05 / FC0F / FC10 / FC11 | 全部静默超时 |
| 地址 `0014H` 及以上 | 静默超时 |
| 数量 = 0 / 21 / 125 / 126 | 静默超时 |
| 错误站号（3 / 5 / 0 / 255） | 静默超时（正常行为） |

**要求**：**只用超时判定失败**，永远等不到 0x80 异常码。

### 4.4 ⚠ FC10（写多寄存器）不支持

手册 1.3 声称支持 `10H`，实测：

| 请求 | 结果 |
|------|------|
| FC10 写 `000AH` × 1（写回原值 4） | **无应答**，复核站号仍为 4（未生效） |
| FC10 写 `000AH` × 2 | 无应答 |

**要求**：写配置**只用 FC06**（单寄存器）。取温湿度不需要任何写操作。

### 4.5 块读上限 20 个寄存器

| count | 结果 |
|-------|------|
| 1~20 | ✅ OK |
| 21 / 24 / 32 / 64 / 120 / 125 | ❌ timeout |

恰好等于有效地址空间 `0000H~0013H`（20 个）。取温湿度只需 **count=2**。

### 4.6 帧间可背靠背

| 帧间间隔 | 结果 |
|---------|------|
| 0 ms（真正背靠背） | 49~50/50 ✅ |
| ≥0.3 ms | 50/50 ✅ |

与多数 RTU 从站要求的 3.5 字符静默不同，本设备**不需要**。仍建议留 ≥1 ms 帧间隔作余量。

## 五、性能与稳定性

### 5.1 单帧往返（115200 8N1）

| 读寄存器数 | 回包长度 | p50 | p95 |
|-----------|---------|-----|-----|
| 1 | 7 B | 5.61 ms | 5.74 ms |
| **2（取温湿度）** | **9 B** | **5.81 ms** | **7.45 ms** |
| 3 | 11 B | 6.01 ms | 7.60 ms |
| 6（含 float） | 17 B | 6.64 ms | 6.72 ms |
| 10 | 25 B | 7.43 ms | 7.53 ms |
| 20 | 45 B | 9.43 ms | 9.50 ms |

**RTT 构成**：固定开销约 5.4 ms（主要是 SHT30 测量等待），每增加 1 个寄存器 +0.19 ms。

### 5.2 稳定性

| 项 | 结果 |
|---|---|
| 30 s × 1 Hz 长稳 | **30/30 成功**，温度 21.3~21.4 ℃，湿度恒定 65.3 %RH |
| 静默 2 s 后首帧 | 5.27~5.84 ms（**无唤醒开销**） |
| 背靠背 200 次 | 196/200，**127 帧/秒** |
| 连续 2000 帧（含残尾统计） | 1989/2000 完全干净（**99.45%**） |

> 手册标称数据更新率 30 Hz/通道。115200 下 5.8 ms/帧 ≈ 170 帧/秒，**远超更新率**。采集周期 200~500 ms 足够。

### 5.3 偶发残尾字节（0.55%，不影响取数）

连续 2000 帧中 11 帧（0.55%）在正常应答后**多出 8 字节**：

```
正常应答 04 04 04 00 D9 02 88 7E 79        (9 B, CRC 正确)
多余字节 02 8D 80 01 00 03 15 E7           (8 B, 自身 CRC 也正确)
```

- 多余 8 字节**自身 CRC 自洽**，不是线路噪声；
- 内容规律：`[湿度 u16][0x8001][0x0003]`，首字段随测量漂移；
- 出现间隔不规律（26~254 帧），不随外部节拍聚集；
- **未能完全定性**（离线穷举各种帧解释均无匹配前缀）。

**规避（两行代码即可，已在探测工具中验证有效）**：

1. **每帧发送前清空接收缓冲区**（`reset_input_buffer()` / `tcflush(TCIFLUSH)`）；
2. 收帧用**长度 + CRC 双校验**，CRC 失败直接丢弃重发。

> 0.55% 是在**极限背靠背**（无间隔连发 2000 次）下测得。正常 200~500 ms 轮询周期下未观察到。**取温湿度场景下按上面两条规避即可，无需深究根因。**

## 六、编解码口径

### 6.1 三种数据表达共存

同一份测量值在寄存器里出现 3 次：

| 表达 | 寄存器 | 示例 | 精度 |
|------|-------|------|------|
| uint16 × 0.1 | `0000H` / `0001H` | 217 → 21.7 ℃ | 0.1 |
| float32 大端 | `0002H~0003H` / `0004H~0005H` | `0x41AB1EDB` → 21.3901 | 全精度 |
| 保持寄存器镜像 | `0000H~0005H`（FC03） | 同输入寄存器 | 同上 |

### 6.2 u16 与 float 的关系（30 帧对照）

| 项 | 最大偏差 | 判定 |
|---|---------|------|
| 温度 `\|float − u16×0.1\|` | **0.0901 ℃** | u16 = float **截断**到 0.1 |
| 湿度 `\|float − u16×0.1\|` | **0.0694 %RH** | 同上 |

样例：`u16 温度 213(21.3) / float 21.3901`；`u16 湿度 653(65.3) / float 65.3358`。

**结论**：两者**同源**，u16 是 float 截断到 1 位小数（不是四舍五入，也不是独立测量）。

> **早期误判订正**：曾以为 `0003H`/`0005H` 是「随机噪声」，实为 float 尾数低位在缓慢漂移 —— 单独看低字当然像随机数，配合高字即可解出真实浮点值。

### 6.3 负温度解码（**必须按手册实现，本次未实测**）

```c
/* 手册 2.1 */
if (raw >= 10000)
    t = -(raw - 10000) * 0.1;   /* 例：10250 → -25.0 ℃ */
else
    t = raw * 0.1;              /* 例：250   →  25.0 ℃ */
```

现场 21 ℃ 无法验证负温度分支。**但这是本型号唯一的负数表达方式，必须实现**；否则 -1 ℃ 会被解成 999.9 ℃。

> 验证方法：模块放冰箱冷冻室（-18 ℃），读 `0000H` 应得 `>= 10000` 的值。

### 6.4 取数策略

| 场景 | 建议 | 理由 |
|------|------|------|
| **一般监控（推荐）** | `FC04 0000H count=2`，取 u16 | 帧最短（9 B）、RTT 最低（5.8 ms）、0.1 分辨率够用 |
| 高精度/标定 | `FC04 0000H count=6`，取 float32 | 全精度，避免截断误差 |
| 诊断 | `count=6` 后两套都解析 | 便于交叉校验 |

**不要**分两次读 u16 和 float —— 两次读之间测量已刷新，两者会对不上。

## 七、接入建议

### 7.1 采集配置

| 项 | 建议值 | 依据 |
|---|-------|------|
| 功能码 | **FC04** | 输入寄存器为只读测量值，语义正确 |
| 起始地址 / 数量 | `0x0000` / **2** | RTT 最低 + 够用 |
| 轮询周期 | **200~500 ms** | 数据 30 Hz 更新，5.8 ms/帧 |
| 超时 | **≥ 50 ms** | 实测 p95 7.45 ms，留 7 倍余量 |
| 重试 | 2 次 | 0.55% 偶发残尾，重试即可自愈 |
| 发送 | **一次 write 完整帧** | §4.1 |
| 收帧 | **先清缓冲 → 长度 + CRC 双校验** | §5.3 |
| 写配置 | **仅 FC06** | §4.4 |
| 校验寄存器 | **不访问 `0x003D`** | §4.2 |

### 7.2 与本仓库 `XTempHumTransmitter` 的对应

`Src/Industry/XTempHum/XTempHumTransmitter.{c,h}` 的状态模型是
`TempValue / HumValue / TempValid / HumValid / StaleMs`，与本次口径天然吻合：

| 语义 | 地址 | 功能码 | 换算 |
|------|-----|-------|------|
| 温度 | `0x0000` | FC04 | `v>=10000 ? -(v-10000)*0.1 : v*0.1` |
| 湿度 | `0x0001` | FC04 | `v*0.1` |
| 站号（配置） | `0x000A` | FC03/FC06 | 直读 |
| 波特率索引（配置） | `0x000B` | FC03/FC06 | 0~7 → 4800~115200 |

若现有适配器实现中：
- 引用了 `0x003D` 校验寄存器 → **删除**，改平台层静态 8N1；
- 用 FC10 批量写 → **改为循环 FC06**；
- 按 125 寄存器上限一次读全表 → **改为 ≤20**；
- 未实现负温度分支 → **补上**。

## 八、缺陷清单

| # | 缺陷 | 影响 | 规避 |
|---|------|-----|------|
| 1 | **`003DH`（校验）不存在**，`0014H` 以上全无应答 | 配置读写静默失败，误判通信故障 | 不访问；校验按 8N1 静态配置 |
| 2 | **手册称支持 FC10，实际不支持** | 批量写静默失败 | 仅用 FC06 |
| 3 | **帧内字节间隔 >1.5 ms 整帧丢弃** | 逐字节写全失败 | 一次 write 完整帧 + `cfmakeraw()` |
| 4 | **非法请求不返异常码** | 错误被超时掩盖 | 只用超时判失败 |
| 5 | **块读上限 20**（非 Modbus 的 125） | 超限静默失败 | 一次读 ≤20；取数用 2 |
| 6 | **偶发残尾字节（0.55%）** | 后续帧错位 → CRC 错 | 每帧前清缓冲 + 长度&CRC 双校验 + 重发 |
| 7 | **手册 PLC 地址列排版错误**（保持寄存器标 30001） | 组态时地址填错 | 保持寄存器用 40001 段 |
| 8 | 负温度编码需特殊分支 | 忽略则 -1℃ 解成 999.9℃ | 按 §6.3 实现 |
| 9 | 8E1/8O1/8N2「假通过」 | 误判校验方式 | 不靠「能读到」判断校验位 |

### 9.3 报文样例（留证）

```
取温湿度（推荐，唯一必需的一条）
  TX: 04 04 00 00 00 02 71 9E
  RX: 04 04 04 00 D9 02 88 7E 79
      → 温度 217×0.1 = 21.7 ℃；湿度 648×0.1 = 64.8 %RH

读全部 6 个输入寄存器（含 float32）
  TX: 04 04 00 00 00 06 70 5D
  RX: 04 04 0C 00 D5 02 8E 41 AB 1E DB 42 82 D1 72 B5 69

读站号 + 波特率
  TX: 04 03 00 0A 00 02 ...
  RX: 04 03 04 00 04 00 07 ...
                 └站号4┘└7=115200

读 003DH（手册声称的校验寄存器）—— 无应答
  TX: 04 03 00 3D 00 01 ...
  RX: （超时）

读 0032H（厂家软件发过）—— 无应答
  TX: 04 03 00 32 00 01 25 90
  RX: （超时）

FC06 写站号（写回原值 4，无副作用）
```
