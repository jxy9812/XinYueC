# HsfServer 会话泄漏 + 事件环挂死 + 温湿度失效 —— 诊断报告（2026-11-06）

> 现象、证据、机制链与修复候选。本报告只做诊断与方案登记；平台层修复另行实施。

## 1. 现象（时间线）

| 时刻 | 现象 |
|---|---|
| 20:22:13 | `HsfServer.exe --sim` 启动（PID 35688），一切正常 |
| 20:18:04 起 | `bin/cfg/hsf_data.db-wal` 最后写入时刻（20:37:33 为最后一拍）→ **5s 历史采样链已死** |
| 20:26-20:37 | Python 探针反复连接/登录/关闭（联调变频器换向）——每次连接都会话接入、传输断开，但会话计数只增不减 |
| 21:0x | 客户端全部登录被拒；`HsfServerApp: 登录被策略拒绝（root：会话数已达上限）` |

同构前科：19:35 旧实例上客户端出现**温湿度 `--` + FPS 7.8（帧耗时 363ms）**——同一冻结机制的前一次发作（旧实例 19:50 已杀）。

## 2. 证据链（cdb 活体采样 + 日志 + 文件指纹）

1. **主线程三采一栈**（间隔 25s）：恒阻塞于
   `WS2_32!select ← xw32_selectOne+0x2ff ← XDeviceNetwork_win32_selectDispatchReady
   ← pollWsaEvents ← VXNetIoRingWin32_waitForEvents ← processEvents 等待段`
   （Drive/windows/Core/XNetIoRingWin32.c:428-456 的 WSA 分片等待 → pollWsaEvents
   → Drive/windows/Device/Network/XDeviceNetwork_win32_select.c:1197）。
2. **CPU 增量为零**（10s 窗口采样 3.234s → 3.234s）：不是忙转，是真阻塞。
3. **轮刻度滞后**：`[WHEEL] lag=179/186`（≈3.6s）两次打印相隔 **101s**，tick 差
   5057 拍=101.1s@20ms/拍 —— 轮 handler 约 100s 才被调一次（有界追赶每次清一段）。
4. **0 条 `XLinkSession: 静默超时判线`**、reap 移除仅 2 次（早期 HsfClient 会话）
   —— pump（内建 100ms tick）停摆后，静默判线与 reap 全部失能。
5. **38 路 `原 state=3`（Connected，未完成认证）会话**：`XLinkSession_onDisconnected`
   已触发并复位到 Inactive（`[xlsess] 传输断开，会话复位` 39 条），但 **reap 停摆**
   ⇒ Inactive 会话永久滞留 `m_sessions` 向量。
6. **登录策略闸读 `XLinkServer_sessionCount`**（HsfServerApp.c:2490）——僵尸会话
   把上限 8 打满 ⇒ 一切新登录被拒（链上文案误报 "bad password"，真实原因见服务端
   日志「会话数已达上限」——两侧拒绝文案口径不一致，另登记）。
7. `xw32_selectOne` 全函数唯一 select 调用点源码为**零超时**（tv={0,0}，
   XDeviceNetwork_win32_select.c:443-444），但活体上该 select **挂死不返回**
   （cdb 三采 + CPU 零增量）——选中的套接字句柄处于病态（对端 RST/已死连接），
   AFD_SELECT 在该句柄上永久悬挂。38 条死连接的 socket 未从 WSA 轮询表注销
   （见 §3.3），pollWsaEvents 每圈对**每一条**已登记句柄做 select，只要其中一条
   挂死，主循环即整体冻结。

## 3. 机制链（根因）

```
客户端高频连接/断开（联调探针、断线重连）
  └─ 会话死亡：socket 对端 RST，传输断开 → 会话复位 Inactive ✓（信号路径正常）
      └─ 但 socket 设备生命周期归 XTcpServer，reap **故意不关 socket**
         （XLinkServer.c reap 注记「僵尸 socket 处置 2026-11-04」：close 必 UAF）
          └─ socket 也**未从 WSA 轮询表注销**（xw32_disarmSocket 无人调用）
              └─ pollWsaEvents 每圈对死句柄做 select ⇒ 某条死句柄上
                 零超时 select 永久悬挂（Winsock AFD 病态）
                  └─ 主线程冻结在 processEvents 等待段
                      ├─ 全局时间轮停摆 ⇒ 全部 Coarse 定时器死：
                      │    XLinkServer 100ms tick（pump/reap/静默判线/健康/
                      │    历史采样/IO 轮询节拍）全停
                      ├─ 会话只增不减 ⇒ 会话上限策略拒绝一切登录
                      ├─ 485 总线轮询停 ⇒ 温湿度/流量/浊度全部「陈旧」→ 界面 "--"
                      └─ 客户端同栈（HsfClient 同一 XCoreApplication 派发器）
                           ⇒ 19:35 那次客户端 FPS 7.8 + 显示冻结同源
```

一句话根因：**死亡会话的 socket 未注销出 WSA 轮询表，其中一条死句柄上的
零超时 select 永久悬挂，把整个事件循环（连同全部 Coarse 定时器）拖死。**

## 4. 修复候选（按影响面排序，待评审后实施）

> **[2026-11-06 根修已落地]** 候选 1 的等价实现落在 select 设备后端
> （`Drive/windows/Device/Network/XDeviceNetwork_win32_select.c`）：EOF/硬错误
> 旗（`p->closed`）置位的同一拍**即刻摘出 WSA 轮询表**（`xw32_disarmSocket`，
> 幂等），`selectDispatchReady` 对 closed 句柄早退（冗余护栏）。closed 是终态
> （无假 EOF 复活路径），摘表只动环形表项、不关 socket（不碰 2026-11-04
> UAF 面）。**复现验证**：24 次快速连断后登录/控制/遥测全通，会话计数
> 25 接入 / 24 断开全量回收，不再冻结。
> **残留**：24 连断风暴中仍有**一次性** 4.2s 轮滞后（`[WHEEL] lag=208`，之后
> 完全恢复）——病态句柄上那一次 select 的内核侧延迟，非永久冻结。候选 2
> （WSAEventSelect+WFMO 免疫）可消除该残留，列为后续改进。

1. **[治本·已落地] 死亡即注销**：会话传输断开（`XLinkSession_onDisconnected`）或 socket
   `disconnect` 时，同步把该 socket 从 WSA 轮询表注销（`xw32_disarmSocket` 等价
   通道）。注销≠关闭（不碰 2026-11-04 的 UAF 面）：只摘轮询项。死亡句柄从此
   不再被 select，挂死源消失。
2. **[防御·已落地+补丁] 轮询层免疫挂死**：`pollWsaEvents` 的每句柄零超时 select 换成
   `WSAEventSelect + WSAWaitForMultipleEvents(0)` 语义（事件对象不会被 AFD 悬挂），
   或对 `select` 返回 `WSAENOTSOCK`/连续异常的句柄自动注销并留痕。
3. **[兜底·未实施] 看门狗**：主循环卡死自愈（如 dispatcher 每圈喂狗，独立线程检测
   >N 秒未喂则 `wakeUp`（PostQueuedCompletionStatus）强拆等待并留痕）。
4. **[伴生修复·未实施] 拒绝文案口径**：策略拒绝（会话上限/同账并发）链上应答统一为
   可区分的文案/状态码，客户端不再显示「bad password」误导现场。
5. **[运营缓解·未实施]** 登录策略 `active` 统计剔除 Inactive 会话（reap 停摆时上限闸
   不被僵尸打满）——治标，作 1-3 的缓冲。

> **[2026-11-07 候选 3 已落地：关联一次化]** 候选 2（每轮 `WSAEventSelect`
> 重发关联）在实战中**换皮复现同一 hang 类**：root 单会话策略拒绝 + 截图
> 客户端秒退的会话在对端 FIN 后进入 CLOSE_WAIT，服务端每轮 poll 对其重发
> `WSAEventSelect`；重注册在 AFD 里是「取消旧 poll IRP + 重挂新 IRP」的
> 复合操作，病态端点上旧 IRP 取消不完 ⇒ 新 IRP 在端点锁上排队**永不返回**。
> cdb 活体栈：主线程冻在 `ntdll!NtDeviceIoControlFile ← mswsock ←
> WS2_32!WSAEventSelect+0x7c ← xw32_selectOne+0x332 ← selectDispatchReady`，
> 时间轮停摆 ⇒ 会话不再回收（计数爬到上限 9）、策略拒绝堆积。事件环冻结
> 前最后一组日志恰是策略拒绝留痕——被拒会话正是病态端点的来源。
> **修复**（`xw32_selectOne`/`xw32_probeArm`/`xw32_armSocket`）：关联只发
> **一次**（`probeArmed` 守卫，换 socket/断开时复位），此后每轮只做
> `Wait(0)`（超时即 0，连 Enum 都省）+ `WSAEnumNetworkEvents`——MSDN 事件
> 模型服务器的标准姿势；事件位由 WSANETWORKEVENTS 累积、Enum 一并取走，
> FD_WRITE 跃迁/FD_READ 余量重报/FD_ACCEPT 重查均由 AFD 在对应操作后自行
> 重置，写续传链路（writePending→Write-ready→ContinueWrite）不受影响。
> **复现验证**：root 连击 6 连发（3 中 3 拒、2s 间隔，正是冻死旧版的序
> 列）——服务端全程存活、拒绝实时留痕、静默判线回收照常（8 次）、后续
> 登录恢复成功，无 `[WHEEL] lag`。
> **顺带修正**：`deleteContext` 漏关 `probeEvent` 句柄（原仅 disconnect
> 收）一并堵上；`socketSetDescriptor/serverSetDescriptor` 接手新句柄时复
> 位 `probeArmed`。
