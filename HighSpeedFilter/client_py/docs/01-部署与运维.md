
## 2. 部署

```sh
cd HighSpeedFilter/client_py

sh deploy.sh                          # 部署（不配自启）
sh deploy.sh --auto 192.168.0.10      # 部署 + 配开机自启（连该服务端）
sh deploy.sh --auto 192.168.0.10 --windowed   # 自启但窗口化（不全屏）
```

脚本做的事：打包 → scp → 检查 PyQt5/中文字体 → 写 `run_client.sh` →
（可选）写 systemd 单元 → 离屏自检并生成一张截图。

### 2.1 与板上 demo 抢屏幕

板上 `run_test.service` 会启动 `XGuiWindowDemo_Test` 全屏占屏。
两个全屏程序同跑会让 XFCE 面板闪出来，且互相遮挡。

```sh
# 只跑客户端
ssh root@192.168.0.10 'systemctl stop run_test.service'

# 恢复 demo
ssh root@192.168.0.10 'systemctl stop hsfclientpy; systemctl start run_test.service'
```

## 3. 启动

### 3.1 命令行

```sh
# 板上手动启动（全屏，连服务端）
ssh root@192.168.0.10 'cd /root/Desktop/XinYueC/hsf_client_py && \
    DISPLAY=:0 ./launch.sh --auto 192.168.0.10 --fullscreen'

# 指定页（0~16）
./launch.sh --auto 192.168.0.10 --page 5

# 离线浏览（不连服务端，只看界面）
./launch.sh --offline

# 窗口化 + 指定尺寸
./launch.sh --auto 192.168.0.10 --size 1024x600
```

### 3.1.1 端口：集中在 `ports.py`（改一处就行）

客户端端口不写死在代码里，统一从 `hsfsrv_client/ports.py` 取：

```python
# hsfsrv_client/ports.py（与服务端那份内容必须完全相同）
PY_SERVER_PORT = 6200      # ← 改这里：缺省连接端口
C_SERVER_PORT = 6100       # C 版端口（--port 6100 时用）
```

改 `PY_SERVER_PORT` 一处，客户端的缺省连接端口、`--help` 显示、
部署脚本全部跟随。

> **必须同步服务端那份**：`server_py/hsfsrv/ports.py`。
> `tests/test_ports.py` 会逐字节比对两份，不一致测试失败。

缺省连 6200（Python 版服务端），C 版是 6100。

```sh
./launch.sh --auto 192.168.0.10              # 连 Python 版服务端（6200）
./launch.sh --auto 192.168.0.10 --port 6100  # 连 C 版服务端（6100）
```

两套协议完全兼容，客户端可以连任意一方；错开端口是为了让**两套服务端
同机并存**做对比调试（共用端口会让后启动的起不来）。

### 3.2 参数一览

| 参数 | 说明 |
|---|---|
| `--auto HOST` | 无头登录（跳过登录窗） |
| `--port N` | 端口（缺省 **6200**；连 C 版服务端用 6100） |
| `--user U` / `--pass P` | 凭据（缺省 root/root） |
| `--offline` | 离线浏览 |
| `--page N` | 启动后切到第 N 页（0..16） |
| `--fullscreen` | 全屏 |
| `--size WxH` | 窗口尺寸 |
| `--shot PATH` | 渲染后截图并退出（验收用） |
| `--seconds N` | N 秒后自动退出（CI 用） |

### 3.3 systemd（`deploy.sh --auto` 会写）

```ini
[Unit]
Description=HSF Client (Python/PyQt5)
After=graphical.target network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
Environment=DISPLAY=:0
Environment=QT_QPA_PLATFORM=xcb
Environment=QT_OPENGL=software
WorkingDirectory=/root/Desktop/XinYueC/hsf_client_py
ExecStart=/usr/bin/python3 -m hsfsrv_client --auto 192.168.0.10 --port 6200 --fullscreen
Restart=on-failure
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=hsfclientpy

[Install]
WantedBy=graphical.target
```

```sh
systemctl status hsfclientpy
journalctl -u hsfclientpy -f
```

## 5. 操作说明

### 5.1 切页与订阅

客户端**只订阅当前页需要的主题**（切页时自动增删）。所以：

- 页面一打开就能看到数据（订阅即补发一拍，不用等周期推送）
- 离开某页后不再为它占链路带宽
- 顶栏的温湿度/健康是全局的，始终订阅

### 5.2 变频器控制（页 5）

| 操作 | 说明 |
|---|---|
| 正转/反转启动 | 下发 `op=4` + 方向 |
| 停机 | 减速停机（`op=5`） |
| 自由停车 | `op=6` |
| 故障复位 | `op=8` |
| 频率给定 | 输入 Hz → 「下发」（`op=2`），超量程会被服务端钳位 |
| **正转/反转点动** | **按住**按钮才转，松手立刻停 |

> **点动是"按住"式**：按住期间每 200ms 重发一次，松手发 `JogRelease`。
> 服务端 600ms 收不到就自动停机（安全兜底）。这是设计，不是卡顿。

**控制被禁用时**按钮会灰掉并显示原因（未连接 / 自动模式 / 权限不足 / 设备未就绪）。

### 5.3 数字量操作（页 3）

- **DI 区**：只读灯阵列（绿=通，红=断）
- **DO 区**：可点按钮，点击切换通/断

DO 操作与变频器控制走**同一套闸门**（自动模式拒绝 / 需 root）。
禁用时按钮灰掉，并在下方显示原因。

多台模块用顶部下拉切换。

### 5.4 运行模式切换

两个入口：
- 顶栏的模式钮（手动/自动，点击切换）
- 设置 → 远端设置 → 切换按钮

**自动模式会拒绝全部远程控制**（变频器 + DO 都不行），这是安全设计。
切换需 root。

## 6. 截图验收

### 6.1 用 Qt 抓图，**不要用 xwd**

```sh
ssh root@192.168.0.10 'cd /root/Desktop/XinYueC/hsf_client_py && \
    DISPLAY=:0 python3 tools/shot.py /tmp/a.png'
```

> **为什么不用 xwd**：本板 X root 是 `depth=24` 但 `xwd -root` 导出的是
> 24bpp packed（`bytes_per_line=5120`，每像素占 4 字节）。自己写转换脚本
> 极易把 stride 算错 → 相邻像素错位 → **红/绿交错成"条纹"**，看着像客户端
> 渲染坏了，其实纯属转换伪影。本项目为此白查了两轮。
> `QScreen.grabWindow(0)` 由 Qt 自己做像素格式转换，一行搞定零风险。

### 6.2 逐页巡检

```sh
# 板上执行：逐页启动 + 抓图，输出 /tmp/ui_sweep/
ssh root@192.168.0.10 'cd /root/Desktop/XinYueC/hsf_client_py && \
    DISPLAY=:0 python3 tools/ui_sweep.py --host 192.168.0.10 --settle 7'
```

### 6.3 离屏截图（不抢前台）

```sh
QT_QPA_PLATFORM=offscreen python3 -m hsfsrv_client \
    --offline --shot /tmp/x.png --size 1280x720 --page 3
```

离屏模式不依赖 X，适合 CI；但**拿不到真实字体/合成效果**，
颜色/布局验收仍建议用 X11 + `tools/shot.py`。

## 7. 故障处理

### 7.1 界面是方框/乱码

中文字体没选对。检查：

```sh
ssh root@192.168.0.10 'fc-list :lang=zh | head -3'
```

客户端选字体的顺序（`theme.pick_font_family`）：
1. 按族名找 `WenQuanYi Zen Hei` / `文泉驿正黑` / `文泉驛正黑` / `Microsoft YaHei`…
2. 都没命中 → 按**文件路径** `addApplicationFont` 加载 `wqy-zenhei.ttc`，
   并用它**返回的**族名（该文件里注册的是繁体「文泉驛正黑」）

> **别把 `DejaVu Sans` 放进候选**：它在板端存在，但**没有任何汉字**，
> 匹配成功后界面全是方框（本项目踩过）。

### 7.2 登录后 6 秒必掉线

这是**心跳没发出去**。服务端日志会写「静默超时（6xxx ms）→ 断链」。

根因（已修）：客户端心跳判断用了 `max(发送时间, 接收时间)` 判静默。
订阅了 100ms 一拍的遥测后接收时间每 100ms 刷新一次，条件永不成立 →
一帧心跳都不发。**心跳是"我方向对端证明存活"，只该看自己的发送时间。**

若再遇到，先在客户端侧确认心跳是否在发：

```sh
# 服务端日志：有"静默超时"就是没收到客户端的任何帧
journalctl -u hsfserverpy -f | grep 静默
```

### 7.3 状态栏显示"已连接"但数据是 `--`

1. 该页对应的设备在服务端是否装配（远端设置页 / 首页设备表看 health）
2. `health=2`（数据过期）说明设备通讯在但没新数据
3. `health=3`（离线）说明设备失联或未装配

### 7.4 控制按钮点不动

按钮会灰掉并在页面上写明原因。对照：

| 提示 | 处理 |
|---|---|
| 未连接服务端 | 检查网络与登录 |
| 自动运行中… | 用 root 切到手动模式 |
| 权限不足… | 当前是 admin，换 root 登录 |
| 变频器未就绪 | 服务端串口未装配或变频器失联 |

### 7.5 窗口是 1x1（看不到界面）

xfwm4 会在首次 map 时覆盖尺寸。程序已在 `show()` 前后各 resize 一次；
若仍遇到，用 `--fullscreen` 或 `--size WxH` 显式指定。

### 7.6 启动报 libGL 错误

```
libGL error: failed to create dri screen
libGL error: failed to load driver: rockchip
```

**这是厂商 GLX 驱动的既有噪声，不影响运行**（板端 GLX 走 llvmpipe，
客户端也不需要 GL）。`launch.sh` 已设 `QT_OPENGL=software` 减少这类输出。

### 7.7 root 单会话冲突

服务端限制 root 只能一个在线会话（防并行修改）。**同时开两个客户端
用 root 登录，第二个会被拒**。

- 第二个实例会显示「连接已断开」并自动重连（每 2 秒重试）
- 要么关掉第一个，要么第二个用 admin（只读）

## 8. 升级 / 卸载

```sh
# 升级（保留任何本地设置；QSettings 存在 ~/.config/XinYueC/）
sh deploy.sh --auto 192.168.0.10

# 卸载
ssh root@192.168.0.10 'systemctl disable --now hsfclientpy'
ssh root@192.168.0.10 'rm -f /etc/systemd/system/hsfclientpy.service && systemctl daemon-reload'
ssh root@192.168.0.10 'rm -rf /root/Desktop/XinYueC/hsf_client_py'
```

客户端用 `QSettings("XinYueC", "HsfClientPy")` 记住服务器地址/端口/用户名
（**不存口令**），位置 `~/.config/XinYueC/HsfClientPy.conf`。
