## 3. 启动

### 3.1 命令行

```sh
# 板上手动启动（全屏，连服务端）
ssh root@192.168.0.10 'cd /root/Desktop/XinYueC/hsf_client_py && \
    DISPLAY=:0 ./launch.sh --auto 192.168.0.10 --fullscreen'

# 指定页（0~16）
./launch.sh --auto 192.168.0.10 --page 5

# 离线浏览（不连服务端，只看界面）
./launch.sh --offline

# 窗口化 + 指定尺寸
./launch.sh --auto 192.168.0.10 --size 1024x600
```

### 3.1.1 端口：集中在 `ports.py`（改一处就行）

客户端端口不写死在代码里，统一从 `hsfsrv_client/ports.py` 取：

```python
# hsfsrv_client/ports.py（与服务端那份内容必须完全相同）
PY_SERVER_PORT = 6200      # ← 改这里：缺省连接端口
C_SERVER_PORT = 6100       # C 版端口（--port 6100 时用）
```

改 `PY_SERVER_PORT` 一处，客户端的缺省连接端口、`--help` 显示、
部署脚本全部跟随。

> **必须同步服务端那份**：`server_py/hsfsrv/ports.py`。
> `tests/test_ports.py` 会逐字节比对两份，不一致测试失败。

缺省连 6200（Python 版服务端），C 版是 6100。

```sh
./launch.sh --auto 192.168.0.10              # 连 Python 版服务端（6200）
./launch.sh --auto 192.168.0.10 --port 6100  # 连 C 版服务端（6100）
```

两套协议完全兼容，客户端可以连任意一方；错开端口是为了让**两套服务端
同机并存**做对比调试（共用端口会让后启动的起不来）。

### 3.2 参数一览

| 参数 | 说明 |
|---|---|
| `--auto HOST` | 无头登录（跳过登录窗） |
| `--port N` | 端口（缺省 **6200**；连 C 版服务端用 6100） |
| `--user U` / `--pass P` | 凭据（缺省 root/root） |
| `--offline` | 离线浏览 |
| `--page N` | 启动后切到第 N 页（0..16） |
| `--fullscreen` | 全屏 |
| `--size WxH` | 窗口尺寸 |
| `--shot PATH` | 渲染后截图并退出（验收用） |
| `--seconds N` | N 秒后自动退出（CI 用） |

#### 环境变量

| 变量 | 缺省 | 说明 |
|---|---|---|
| `HSF_UI_SCALE` | **1.5** | 界面字号统一缩放（1.0~2.0，越界/非法回落缺省）。板端 1280x800/7.9 寸屏上 1.0 的字太小，故缺省已放大 1.5 倍。现场嫌大嫌小**不用改代码**，设这个变量即可（如 `HSF_UI_SCALE=1.7`） |
| `HSF_TOUCH` | 自动探测 | 软键盘开关：`1` 强制开 / `0` 强制关 / 未设则探测（Windows 查触摸数字化器，非 Windows 默认开） |
| `HSF_CLIENT_DEBUG` | 未设 | `1` 打印收发包轨迹 |
| `HSF_PINYIN_ASSET` | 内置 | 换拼音词库路径 |

## 5. 操作说明

### 5.0 主界面设备状态表

五列：**设备 / 类型 / 状态 / 地址 / 错误信息**。

| 列 | 含义 | 示例 |
|---|---|---|
| 设备 | 现场叫法（变频器驱动的那台叫「搅拌泵」） | 搅拌泵 |
| 类型 | 设备类别（维修时据此判断该查什么） | 变频器 |
| 状态 | 正常 / 数据过期 / 离线 / 故障 | 正常 |
| **地址** | **连接参数，查故障第一步** | `COM17 · 115200 · 站 2`<br>`192.168.0.12:502`<br>`192.168.0.12:502 · DO22` |
| 错误信息 | 出问题时的原因（正常时 `-`） | 从站失联 |

> 「地址」与「错误信息」**分成两列**是刻意的：合并成一列时，一旦出故障
> 地址就被错误文本挤掉，而排故障正需要"它在哪个地址 + 为什么连不上"
> 同时可见。

### 5.1 切页与订阅

客户端**只订阅当前页需要的主题**（切页时自动增删）。所以：

- 页面一打开就能看到数据（订阅即补发一拍，不用等周期推送）
- 离开某页后不再为它占链路带宽
- 顶栏的温湿度/健康是全局的，始终订阅

### 5.2 搅拌泵控制（页 5，设备是变频器）

| 操作 | 说明 |
|---|---|
| 正转/反转启动 | 下发 `op=4` + 方向（**同时携带当前给定**） |
| **运行中切方向（2026-11-06）** | 下拉改选**立即换向**：发反向 `op=4`（捎带当前给定），服务端按减速时间降到 0、过零翻向、再反向加速（横幅"减速中→加速中→反转运行"） |
| **停机时切方向** | 只**预选**，不发帧；下次启动按新方向走 |
| 停机 | 减速停机（`op=5`）—— 变频器按减速时间斜坡降到 0 |
| 自由停车 | `op=6` —— 立刻断输出，没有停机过程 |
| 故障复位 | `op=8` |
| **调速（运行中）** | 拖滑块或改数字框，**停手即自动下发**（`op=2`/`op=3`） |
| **调速（停机时）** | 只**预置**给定，不发帧；启动时随启动命令生效 |
| **正转/反转点动** | **按住**按钮才转，松手立刻停；**运行中置灰**（服务端也拒——点动只在停机态可用，2026-11-06） |

> **点动是"按住"式**：按住期间每 200ms 重发一次，松手发 `JogRelease`。
> 服务端 600ms 收不到就自动停机（安全兜底）。这是设计，不是卡顿。

#### 调速（2026-11-06 改版：无「下发」按钮）

原「下发」按钮已去掉 —— 改值即生效，少一次点击：

| 控件 | 下发时机 |
|---|---|
| **拖动调速滑块** | 停手 250ms 去抖后发一条；**松手立即**发 |
| 数字框（键盘/箭头） | 停手 400ms 去抖后发一条 |

- **停机时改值只预置**：服务端拒绝停机在线给定（见 server 文档 1.3），
  界面提示"已预置给定 N（启动时生效）"，启动时随命令带下去。
- 为什么要去抖：逐格/逐字符下发会在总线上刷一串 FC06，泵会跟着抖。
- 滑块控件高 **56px**、圆形手柄 34px、轨道 10px —— 按控件矩形内**任意
  位置**都能起拖（Qt 原生只在手柄/轨道上响应，按上下空白没反应）。
- 调速方式缺省是**转速**（rpm），可切频率（Hz）；量程随之切换
  （0~1440 rpm ↔ 0~50 Hz）。

#### 运行状态显示（含过渡态）

| 显示 | 含义 | 颜色 |
|---|---|---|
| 加速中 | 输出频率正在爬向目标 | 蓝 |
| **减速中** | 运行中把给定调低，还在转 | 蓝 |
| **正在停机** | 已发停止命令，输出斜坡下降中 | 蓝 |
| 正转运行 / 反转运行 | 已到目标频率 | 绿 |
| 停机 | 输出已归零 | 黑 |
| 故障 | 有故障码（优先级最高） | 红 |

> 变频器状态字 `0x3000` **只有 3 个值**（正/反/停），不报这些细分 ——
> 加速/减速/正在停机是**服务端按频率关系推导**的，见 server 文档 1.3。

> 停机后可能看到"输出 0.00Hz + 设定频率 48.61Hz"这种组合：那个设定频率
> 是变频器**保留的旧给定**，不是故障。

**控制被禁用时**按钮会灰掉并显示原因（未连接 / 自动模式 / 权限不足 / 设备未就绪）。

### 5.3 数字量操作（页 3）

- **DO 区**：可点按钮，点击切换通/断

DO 操作与变频器控制走**同一套闸门**（自动模式拒绝 / 需 root）。
禁用时按钮灰掉，并在下方显示原因。

### 5.3b 电磁阀与水质页

**电磁阀（页 7）**：6 路开/关，状态**由反馈推导**（不看命令回显）。
按钮的可用状态跟随服务端的处置结果，客户端不自己猜：

| 服务端回的 `cmdResult` | 界面表现 |
|---|---|
| `issued` / `reversed` | 正常下发，进「动作中」并开始 20s 计时 |
| `repeated` | 提示"动作中，重复命令不重置计时"（**不会**把超时计时清零） |
| `ignored` | 提示"已在目标位置，无需动作"，那一侧按钮置灰 |

`repeated` 不重置计时是**安全要求**：若每次点击都重置，连点就能让卡住的阀
永远不报警（实测连点 8 次 0 告警）。

**水质监测（页 6）**：流量计 + 浊度 ×2 + 进水泵，三样在工艺上是一条链
（泵 → 流量 → 浊度），合成一页免来回切。

| 区域 | 内容 |
|---|---|
| 上卡 | 瞬时流量 / 瞬时流速 / 正向累积 / 反向累积 + 报警状态 |
| 左下 | 浊度仪 1 / 2（NTU，两位小数；超 20 NTU 标红，**仅显示口径**） |
| 右下 | 进水泵「启动 / 停止」+ 输出状态 + **"无运行反馈"说明** |

> ⚠ **泵显示的是"输出命令状态"，不是"泵确实在转"**：现场只有接触器输出、
> 没有运行反馈点。界面上那句说明不能删 —— 删了就是把一个推断当实测报给操作员。

浊度仪与电磁流量计**共用一路 485**（站号 1 / 站号 3）。

### 5.4 运行模式与自动运行（**两件事**）

| 操作 | 在哪 | 效果 |
|---|---|---|
| 切换**模式**（手动/自动） | 顶栏模式钮 / 设置→远端设置 | 自动模式**只是授权**，控制器仍停 |
| **启动/停止自动运行** | 设置→远端设置 →「启动自动运行」／**现场操作柱按钮** | 才真正让自动逻辑驱动设备 |

**自动模式会拒绝全部远程控制**（搅拌泵 + DO + 阀 + 泵都不行），这是安全设计。
切换需 root。

> ⚠ **切到自动 ≠ 开始自动运行。** 切模式只代表"允许自动逻辑跑"，控制器
> 仍然停着；要真的开始跑必须再按一次「启动自动运行」（或现场按操作柱的
> 启动按钮）。
> 服务端**重启后控制器一律为停止状态**（即使配置是自动模式）—— 断电/升级
> 重启不该让设备自己动起来。
> 顶栏会同时显示两段：左侧「自动」是模式，右侧「自动 · 已停止 / 运行中」
> 是控制器的真实状态。手动模式下第二段隐藏。

**单向强制**：切回手动时服务端**强制停止**自动运行**并停全部设备**
（变频器减速停机 + 全部泵停 + 全部阀关）。手动模式下自动逻辑还在
跑 = 设备被偷偷驱动，属硬性安全问题。

> 顶栏的「自动 · 运行中／已停止」由客户端**每秒向服务端对账一次**
> （服务端没有"自动运行"的独立推送主题）。所以在现场操作柱上按了启动/
> 停止，顶栏最多 1 秒就会跟着变。

### 5.5 现场操作柱（按钮组）

装在电箱面板上的 4 个按钮 + 3 盏灯，点位与语义见 server 文档
`03-设备与寄存器口径.md` §4.1b。客户端侧只需要知道**看到什么就是什么**：

| 灯 | 亮 = |
|---|---|
| 启动灯 | 自动运行**中** |
| 停止灯 | 未运行（与启动灯严格互斥） |
| 复位灯 | 正在按复位（点动，松手灭） |

**按键行为**：

| 按钮 | 效果 |
|---|---|
| 启动 | **只在自动模式下有效**。手动模式下按了没有反应（灯也不亮） |
| 停止 | **任何模式下都生效**，并且会停全部设备 |
| 复位 | 解除急停锁存（不启动设备） |

> ⚠ **手动模式下按启动是"没反应"，不是"坏了"。** 按钮只是请求，要满足
> 「自动模式 + 急停正常 + 未锁存 + 没在跑」四项才真的切状态。

**急停**（`DI12`，常闭）：

- 按下（或线断了）⇒ 自动运行立刻停、全部设备停、**锁存**
- 锁存后按启动无效，必须先按**复位**
- 急停期间停止灯亮、启动灯灭

> **常见误报**：急停点位配在**离线**的数字量模块上时，服务端读不到 →
> 报「急停状态未知」→ 按启动永远被拒。排查第一步是看首页健康表里
> 数字量模块是否在线。

## 6. 截图验收

### 6.1 用 Qt 抓图，**不要用 xwd**

```sh
ssh root@192.168.0.10 'cd /root/Desktop/XinYueC/hsf_client_py && \
    DISPLAY=:0 python3 tools/shot.py /tmp/a.png'
```

> **为什么不用 xwd**：本板 X root 是 `depth=24` 但 `xwd -root` 导出的是
> 24bpp packed（`bytes_per_line=5120`，每像素占 4 字节）。自己写转换脚本
> 极易把 stride 算错 → 相邻像素错位 → **红/绿交错成"条纹"**，看着像客户端
> 渲染坏了，其实纯属转换伪影。本项目为此白查了两轮。
> `QScreen.grabWindow(0)` 由 Qt 自己做像素格式转换，一行搞定零风险。

```sh
    --offline --shot /tmp/x.png --size 1280x720 --page 3
```

离屏模式不依赖 X，适合 CI；但**拿不到真实字体/合成效果**，
颜色/布局验收仍建议用 X11 + `tools/shot.py`。

## 7. 故障处理

### 7.1 界面是方框/乱码

中文字体没选对。检查：

```sh
ssh root@192.168.0.10 'fc-list :lang=zh | head -3'
```

客户端选字体的顺序（`theme.pick_font_family`）：
1. 按族名找 `WenQuanYi Zen Hei` / `文泉驿正黑` / `文泉驛正黑` / `Microsoft YaHei`…
2. 都没命中 → 按**文件路径** `addApplicationFont` 加载 `wqy-zenhei.ttc`，
   并用它**返回的**族名（该文件里注册的是繁体「文泉驛正黑」）

> **别把 `DejaVu Sans` 放进候选**：它在板端存在，但**没有任何汉字**，
> 匹配成功后界面全是方框（本项目踩过）。

### 7.2 登录后 6 秒必掉线

这是**心跳没发出去**。服务端日志会写「静默超时（6xxx ms）→ 断链」。

根因（已修）：客户端心跳判断用了 `max(发送时间, 接收时间)` 判静默。
订阅了 100ms 一拍的遥测后接收时间每 100ms 刷新一次，条件永不成立 →
一帧心跳都不发。**心跳是"我方向对端证明存活"，只该看自己的发送时间。**

若再遇到，先在客户端侧确认心跳是否在发：

```sh
# 服务端日志：有"静默超时"就是没收到客户端的任何帧
journalctl -u hsfserverpy -f | grep 静默
```

### 7.3 状态栏显示"已连接"但数据是 `--`

1. 该页对应的设备在服务端是否装配（远端设置页 / 首页设备表看 health）
2. `health=2`（数据过期）说明设备通讯在但没新数据
3. `health=3`（离线）说明设备失联或未装配

### 7.4 控制按钮点不动

按钮会灰掉并在页面上写明原因。对照：

| 提示 | 处理 |
|---|---|
| 未连接服务端 | 检查网络与登录 |
| 自动运行中… | 用 root 切到手动模式 |
| 权限不足… | 当前是 admin，换 root 登录 |
| 变频器未就绪 | 服务端串口未装配或变频器失联 |

### 7.5 窗口是 1x1（看不到界面）

xfwm4 会在首次 map 时覆盖尺寸。程序已在 `show()` 前后各 resize 一次；
若仍遇到，用 `--fullscreen` 或 `--size WxH` 显式指定。

### 7.6 启动报 libGL 错误

```
libGL error: failed to create dri screen
libGL error: failed to load driver: rockchip
```

**这是厂商 GLX 驱动的既有噪声，不影响运行**（板端 GLX 走 llvmpipe，
客户端也不需要 GL）。`launch.sh` 已设 `QT_OPENGL=software` 减少这类输出。

### 7.7 root 单会话冲突

服务端限制 root 只能一个在线会话（防并行修改）。**同时开两个客户端
用 root 登录，第二个会被拒**。

- 第二个实例会显示「连接已断开」并自动重连（每 2 秒重试）
- 要么关掉第一个，要么第二个用 admin（只读）

## 8. 升级 / 卸载

```sh
# 升级（保留任何本地设置；QSettings 存在 ~/.config/XinYueC/）
sh deploy.sh --auto 192.168.0.10

# 卸载
ssh root@192.168.0.10 'systemctl disable --now hsfclientpy'
ssh root@192.168.0.10 'rm -f /etc/systemd/system/hsfclientpy.service && systemctl daemon-reload'
ssh root@192.168.0.10 'rm -rf /root/Desktop/XinYueC/hsf_client_py'
```

客户端用 `QSettings("XinYueC", "HsfClientPy")` 记住服务器地址/端口/用户名
（**不存口令**），位置 `~/.config/XinYueC/HsfClientPy.conf`。
