### 3.2 落盘容量限额与满额策略（2026-11-06 新增）

用户提出：**现场那台机器硬盘很小**，DB 必须有最大占用，写满后要能选
几种处理方式（含循环储存），并已实测验证。

* **配置面（两端对齐）**：storage 节新增三个键
  - `maxMb`：容量上限（int MB；**0 = 不限**，缺省 0）
  - `fullPolicy`：满额策略 —— `ring` 循环覆盖（缺省）/ `stop` 到限停写 /
    `rotate` 分段滚动
  - `keepFiles`：rotate 模式保留的分段数（含当前库，1..99，缺省 3）
  配置文件侧另有 `max_kb`（管理员手工编辑口径，支持 KB 级细粒度；
  极小盘与回归测试用，远端协议仍只暴露整数 MB）。
* **三种策略的语义**
  | 策略 | 满了以后 | 适用 |
  |---|---|---|
  | `ring` 循环覆盖 | 删最旧的数据（三表同一时间线），腾出的页真正还给系统 | 长期无人值守（缺省） |
  | `stop` 到限停写 | 停止入库，已有数据原样保留只读；界面显示 `[已停写]` 原因 | 宁可丢新数据不能丢历史证据 |
  | `rotate` 分段滚动 | 当前库改名成带时间戳的分段文件、另起新库，只留最近 N 段 | 要按时间段整体归档/拷走 |
  rotate 的**单段上限 = 总上限 / keepFiles**，所以总占用仍封顶在
  `maxMb`，不会因为多留几段悄悄翻倍。
* **界面**（远端设置页 → 数据存储卡）：容量上限数值框（0 显示「不限」）、
  满额策略下拉（含一句话说明）、保留分段数（仅 rotate 可编辑）、
  用量进度条 + 文字（已用/上限/百分比/行数/策略/分段数/已循环丢弃行数/
  停写原因）。
* **实测**（三套，全部实跑）

### 3.2.1 这一轮实测抓到的四个真缺陷（都是"看起来能用其实没生效"）

1. **`auto_vacuum` 设了不生效**：必须在切 `journal_mode=WAL` **之前**设，
   顺序反了恒得 0 —— 循环删除只把页放进 freelist、文件永远不缩。
2. **WAL 检查点被永久阻塞**：Python `sqlite3` 缺省隔离级别会在 SELECT 后
   挂一个隐式读事务，`wal_checkpoint` 返回 `(0, N, N)`（N 帧待写、一帧
   都写不进去），`-wal` 一路涨到 527KB 而主库只有 8 页。改
   `isolation_level=None` 后返回 `(0,0,0)`，WAL 立即归零。
3. **循环裁剪的判据与闸门不同口径**：闸门按「逻辑+WAL」判超限，裁剪里却
   按纯逻辑判「够了就停」→ WAL 占大头时"进去即达标、一行不删"的死循环。
   改成同口径，并在每轮删除后 vacuum + checkpoint。
4. **极小库一行都删不掉**：按 25% 算出的删除量若小于最小行数阈值，
   `OFFSET` 越界拿不到分界 → 直接 break。改成按比例且不足时清空历史表。

### 3.3 历史数据服务端分页（2026-11-06 新增）

用户提出：**历史页启动时不会加载服务器上的历史数据**，要加载；为了防止
数据过多打爆服务器，客户端与服务端都要分页，一次取一页，一页多少条由
客户端决定，但**总数要告知并实时获取**（在历史页时）。

* **协议（新命令 `CMD_HISTORY_PAGE = 0x0118`）**
  - 载荷 `{offset, limit, beforeTs?, loTs?, hiTs?}`；`limit` 由客户端定，
    服务端夹到 1..`HISTORY_PAGE_MAX(50)`。
  - 应答 `{ok, total, offset, limit, cols, rows, dbRows, latestTs,
    windowStartTs, windowEndTs}`；`rows` 是**二维数组**（每行按 `cols`
    顺序），时间正序。
  - 只读，**不需要 root**（看历史不是控制面动作）。
* **为什么单页上限是 50**：XLink 载荷硬上限 16KB。实测一行 18 列约
  230B（键名只发一次、用数组承载比每行一个子文档省一半），50 行 ≈
  11.8KB，留 4KB 给包络与异常长字符串。
* **两个必须的语义**
  1. **窗口锚定 `beforeTs`**：库在持续入库（5s 一行），若每页都按"现在"
     取，翻到第 2 页时前面的行已被新行顶走，相邻两页会重复/漏行。客户端
     首屏取一次锚点、之后原样回传，整段分页钉在同一批数据上。
  2. **总数与页内容同口径**：`total` 与 `rows` 用同一 `WHERE`，所以
     "共 N 条 / 第 x 页"与实际能翻到的行永远一致。时间范围筛在 SQL 里
     做（有 ts 索引）；列+关键字筛仍在客户端（它比的是**显示文本**，
     在 SQL 里重建一套格式化规则会与界面漂移）。
* **客户端界面**（`pages_other.py` HistoryPage）
  - 入页（`on_enter`）自动拉第 1 页，离页（`on_leave`）停轮询。
  - 分页行常驻表上方（板端竖屏下表在下面，翻页钮会被挤出屏幕）：
    每页 10/20/50 三档 + 上一页/下一页 + "第 x/y 页" + "共 N 条
    （本页 M）库内共 K 条" + 刷新。
  - **总数实时**：3s 一次。第 1 页时带新锚点整页重取（新行直接出现在
    表头）；停留在第 N>0 页只探计数、不动页内容（否则每 3 秒内容全跳一格）。
  - 服务端不可用（未连接 / 未开落盘）→ 退回本地缓存并在分页行说明原因，
    不假装有数据。
  - 时间范围筛选**下推**服务端（这样 total 是范围内的条数，不是整库），
    清除筛选后复位。
* **BSON 补齐两种类型**（`bson.py` 两端同文件）
  - `0x04 array`：分页返回多行用数组，比手拼 `r0/r1/…` 干净。解成 list
    时按键名序号**数值**排序（"10" 不能排到 "2" 前面）。
  - `0x0A null`：库里"该列没数据"是 NULL，必须能表达成 null（与 0、
    空串是两件事）。此前 Python 侧只支持 5 种类型，遇到这两种会抛错。
* **修掉的两个真缺陷**（都由本轮测试暴露）
  1. **历史表的 `ts` 用的是 monotonic**（`_now_ms()`，开机后计时）：

### 3.6.1 关键字筛选下推服务端（2026-11-06 追加，用户实测"筛选无效"根修）

* **现象**：历史页搜"运行"截图显示「共 3790 条（本页 20） 库内共

### 3.6.10 拖动调速两处口径修正 + 板端字号整体放大（2026-11-06）

**用户新增要求（原话）**
- 「不启动的时候也要能拖动调速，默认用速度调速」

**① 停机也能拖动 = 预置给定（不是在线下发）**

服务端 `_VFD_SETPOINT_OPS` 拒绝停机在线给定是有道理的（否则变频器坡道
爬升，界面出现"停机但输出 25Hz"的自相矛盾状态）。故停机拖动走**预置**
语义：

* 滑块不再与 `running` 合闸，只受控制闸（`control_blocked_reason`）约束。
* 停机停手后 `_send_set_speed(preset_only=True)`：**不发帧**，只置
  `_preset_dirty` 并提示"已预置给定 N rpm（启动时生效）"。
* 启动时 `_on_run_stop` 把预置值随 `OP_START` 捎带下去（`hz`/`rpm`），
  发完清标记。
* `_preset_dirty` 同时**挡住遥测采纳**：停机时变频器回报的是上次旧值，
  不挡住的话用户刚拖好的预置值会被 200ms 刷新改回去（表现为"拖不动"）。

**② 缺省调速方式改为转速**

`DEFAULT_SPEED_MODE = SPEED_MODE_RPM`。操作员关心"泵转多快"，频率只是
实现手段；铭牌 50Hz≈1440rpm。注意必须在下拉框与 `freq_spin`/`freq_slider`
**都建好之后**再 `setCurrentIndex`——`_on_speed_mode` 会改它们量程，
早设会 `AttributeError`（构造期实测踩过）。

### 3.6.11 软键盘底部空白（真根因：行外框钉不住高度）（2026-11-06）

前一轮把面板高改对了（334，底部只剩 6px 边距），但**板端仍有一大块空白**
（用户截图红框）。离屏渲染正常、板端异常 —— 差异在真实布局度量上。

**真根因（板端实测量出）**

`_render_page` 里每行的行外框是**裸 `QHBoxLayout`**。QLayout 是二维容器，
**没有 setFixedHeight**；不包控件时它的 sizeHint 高度按子项**最小**要求算
⇒ 板端实测四行键高被压成 `32 / 58 / 32 / 35`（期望全 58），底部因此空出
**77px**。第 2 行碰巧没被压，所以看起来像"某几行特别扁"。

**修法（三处配合）**

1. 行外框**包一层 `QWidget`** 并 `setFixedHeight(key_h)`；行布局挂在它里面。
   布局只能在该控件内水平排布，行高由控件决定。
2. `_key_style` 显式 `setMinimumHeight/setMaximumHeight`，并在 QSS 里也写
   `min-height/max-height`（只靠 `setFixedSize` 挡不住 QSS 的 sizeHint）。
3. **QSS 高度要扣边框**：`min-height` 是内容区尺寸，`border: 1px` 会再加
   2px（实测写 58 量出 60）⇒ 样式里写 `h-2`，控件上仍钉 `h`。

**板端实测（修复后）**

```
panel h = 334  compact = False
row0..row3 host h=58  keys keyh=[58]
末行底 255 / 容器高 257 → 死白 2px；面板底部死白 8px（= 6px 底边距 + 2px）
```

**顺带修的一处隐患**：`_is_compact()` 原来直接按 `main.height() < 700`
判定。主窗尚未布局时 `height()` 只有几十像素（板端探针实测 52），会被
误判成紧凑档（键高落到 50），而 `reflow()` 已按当时高度钉了面板高 ——
主窗随后变大就对不上。现在 `< 300` 一律按非紧凑。

**回归锁**（`test_softkeyboard.py`，80 项）：G 段新增
`G5 行外框是固定高度的 QWidget`、`G6 按键实测高度 == 槽位值（边框已
补偿）`，并把 G 段的遍历口径改成"行外框是控件、要钻进去" —— 旧口径只
递归 layout，改结构后会拿到空列表（实测 7 项假红）。

### 3.6.12 字号再提一档（1.3x）+ 输入框弹出即全选（2026-11-06）

**用户新增要求**
- 「字体再大点」（1.15x 仍偏小 → **1.3x**）
- 「变频器那个界面输入框弹出界面后，默认选中全部，这样可以直接重新完整
  输入一个值」

**① 字号 1.15x → 1.3x**

- `theme.ui_scale()` 缺省改 1.3（`HSF_UI_SCALE` 仍可覆盖 1.0~2.0）。
- 上一轮把字号**写死**成了 `设计值×1.15` 的整数，原始设计值已不在文件里；
  这次按 1.15 反推设计值（取最接近的候选）再乘 1.3，重算 47 处。
- 软键盘 `KEY_FONT 23→30`（23×1.3）、`FUNC_FONT 16→21`。
- 板端实测：`字体：文泉驿正黑（缩放 1.30x）`；运行时数值（12.10 Hz /
  348 rpm / 554.7 V）醒目可读，整页无截断、软键盘按键文字零溢出。

**② 输入框弹出键盘即全选**

- `_InputTarget.select_all()`：调用编辑器 `selectAll()`。
- `bind()` 里在 `show()` 之后调用（先让目标控件拿到焦点，再全选）。
- **判据**：只在「面板原本不可见」或「换了目标/键盘类型」时全选。
  同一目标上连续按键（拼音组串、翻页、切中英）会走 reflow 但**不得**
  再次全选 —— 否则每按一个字符就把已输入内容全选，输入变成覆盖。
- 为什么要全选：触摸屏调数值时操作员想的是"改成 35"而不是"先删 25"；
  全选后第一个字符顶掉原值（`QLineEdit.insert()` 有选区时是替换），
  是最少动作的输入方式。
- 回归锁：`test_softkeyboard.py` G7（弹出全选，选中 720）/ G8（同一目标
  重复 bind 不重复全选）/ G9（换目标后重新全选，选中 abcdef）。

### 3.6.13 去掉下发按钮 + 过渡态显示 + 软键盘类型缺陷 + 字号 1.5x（2026-11-06）

**用户要求**
- 「去掉频率或转速下发，改成在启动状态下实时显示」
- 「点击停止后，变频器是慢慢停机的，希望正在停机这个过程状态显示出来，
  还有正在加速、正在减速都显示下」
- 「字体在大点」（1.3x 仍偏小 → **1.5x**）
- 报告：「弹出他不是数字键盘，需要切换」「输入合规的数字无响应，还是
  原来的值」

**① 软键盘：数值框弹错键盘 + 输入无效（真缺陷，已修）**

根因：点 QSpinBox 的文字区时事件落在**它内部的 QLineEdit** 上，而
`_resolve_input_widget` 从内向外走、停在 lineEdit：

- `inputMethodHints` 在 **QSpinBox** 上（Qt 自动设 ImhDigitsOnly），
  lineEdit 的 hints 是 **0** ⇒ 判成**拼音键盘**（数值框弹出字母盘）。
- 插入直接改 lineEdit 文本，没人调 `interpretText()` ⇒ `spin.value()`
  不跟着变 ⇒ 打进去的合规数字"没反应，还是原来的值"。

修法：新增 `_spinbox_owner()`，把输入目标统一解析成**外层 spinbox**。
复现验证：给 lineEdit 发按下 → `target=QSpinBox, kind=numeric`，
点 550 后 `value=550`。

**② 去掉「下发」按钮（改值即生效）**

- 数字框改值 → 静默 400ms 去抖 → 自动下发；滑块停手 250ms / 松手立即。
- 停机时仍只预置（服务端拒绝在线给定），启动时随 `OP_START` 带走。
- 【实锅】滑块与数字框**互相回写**会各启动一个去抖计时器 ⇒ 双发
  （实测"松手 1 条 + 去抖补 1 条"）。修法：任一侧改值时 `stop()` 掉另
  一侧的计时器。

**③ 加速中 / 减速中 / 正在停机**

[M512 状态字 0x3000 硬件只有 3 个值]（1=正转 / 2=反转 / 3=停机），
厂商不报细分 ⇒ 只能由服务端按频率关系推导（`devices._derive_phase`）。

【真机实锤缺陷】第一版按「目标 vs 输出」差值判，真机停机时**全程显示
"加速中"**：因为点停止后 0x1000 仍保留旧给定 48.6Hz，`target > out`。
修法：加 `_stop_requested` 标记（发过停止命令且输出未归零 ⇒ 正在停机），
差值判据只用于运行中的升降速。

真机实测（板端 + 真实 M512）：
```
启动:  7(加速中) 0.3→48.6Hz 全程 → 3(正转运行)
停机:  8(减速中) 45.7→5.6Hz 全程 (running=False) → 1(停机)
```

客户端文案：`RUN_DECELERATING` 且 `running=False` → 显示「正在停机」
（区分"降给定"与"停机"）；过渡态用强调蓝、运行绿、故障红、停机黑。

虚拟模型同步改：减速停机（命令 6）走斜坡（`on_access` 里降到 0 才置
停机）、自由停车（命令 5）瞬断 —— 否则界面上永远看不到停机过程。

**④ 字号 1.3x → 1.5x**

`theme.ui_scale()` 缺省改 1.5；47 处写死字号按 1.3 反推设计值再乘 1.5
重算；软键盘 `KEY_FONT 23→35`、`FUNC_FONT 16→24`。
板端实测 `字体：文泉驿正黑（缩放 1.50x）`，整页无截断。

**测试**
- `test_units`：+9 项（`TestVfdRunPhase`：加速/减速/停机区分、故障优先、
  状态字仍只有 3 值、减速停走斜坡、**停机不得误判加速**、重启清标记），
  226 全绿。
