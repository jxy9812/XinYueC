### 2. 数据落盘（server_py `store.py` 新模块 + `CMD_CONFIG_GET/SET`）

* SQLite 三表一文件：`history`（5s 一行）/`logs`（全部业务日志旁路）/
  `alarms`（阀超时等事件）。缺省 `server_py/hsf_data.db`，路径可配。
* WAL + 同步小事务；失败不致命（落盘停、采集推送不停）。
* 新命令 **CMD_CONFIG_GET=0x0116 / CMD_CONFIG_SET=0x0117**（需 root，
  按节部分更新）；采集周期**下一拍热生效**（轮询循环每拍重读配置）、
  采集开关经 `restart_polling` 即时生效；storage 变更在线开/关/重开库。
* 持久化补漏：`flowmeter_enabled/turbidity_enabled/turbidity_poll_ms`
  三个键曾只有 load 通路没有 save 通路（远程改完重启丢——e2e 抓到）。
* 远端设置页两张卡：采集配置（5 设备开关+周期）、数据存储（启用/路径/
  入库周期 + 当前库文件实况）；bridge 回调统一 **解码 BSON + configReady
  信号投递 UI 线程**（此前回调签名不匹配 → TypeError 被网络线程吞掉

## 二、当日修掉的真 bug（均为实测暴露）

1. **bridge 回调签名不匹配**（设置"没生效"主根因）：config 回调裸传底层
   三元组，页面按 doc 收 → TypeError 被网络线程吞掉。修复：bridge 统一
   解码 + configReady 信号；缺省 on_error 发状态栏（超时不再无声）。
2. **服务端 poll_keys 点分路径解包崩溃**：浊度/数字量周期是 cfg 顶层
   属性，`split(".")` 后解包失败 → 这两路 SET 必失败（e2e 抓到）。
3. **采集配置表头占位覆盖第一行控件**（QGridLayout 同格后加者顶掉
   先加者）——表头独占第 0 行。
4. `_cell_float` 未锚尾正则把时间戳解析成数值污染排序。
5. `DataTable` 列宽算法三次迭代的第三版（全 Fixed+权重算像素）新增
   `min_widths` 按列下限，时间列 165px 硬保证。
6. 首个 e2e 用 `--port 6299` 起服时 `cfg.save()` 把端口写进 live 配置
   ——已恢复；后续 e2e 一律 `--config` 独立临时目录。
