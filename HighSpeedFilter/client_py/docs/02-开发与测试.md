### 1.1 分层与数据流

```
网络线程                        UI 线程
─────────                       ─────────
XLinkClient
  ├─ _pump() 收帧
  └─ _on_publish(topic, bytes)
        │
        ├─ bson.decode()
        ├─ model.apply()          ← 深拷贝到 AppModel
        └─ dataUpdated.emit(kind) ──(Qt 队列连接)──> 页面 refresh()
                                                      读 ctx.model
```

**关键约束**：
- `AppModel` 只由网络线程写、UI 线程读。Python 的 GIL 保证单次赋值原子，
  且所有字段都是标量/新建 dict，不存在"读到半个对象"。
- **不要在回调里直接碰 QWidget**（那在网络线程，必崩）。一切经 Qt 信号。

### 1.1 请求回调必须用 `bridge.run_in_ui()`（崩溃坑）

`bridge.request` / `send_*` 的 `on_done` / `on_error` **都在网络线程执行**。
这些回调里只要读控件（`label.text()`）、改按钮态（`setEnabled`）或重建卡片，
就是从非 UI 线程碰 QWidget —— **Qt 直接崩进程，没有任何 Python traceback**。

```python
def _done(code, dtype, data):
    doc = bson.decode(data)          # 纯数据，网络线程里做没问题
    def _apply():                    # 碰控件的部分全部放进这个闭包
        self.ctx.set_status(...)
        self._apply_doc(doc)
    self.ctx.bridge.run_in_ui(_apply)   # ← 排队到 UI 线程执行
```

`PageContext.set_status` 已接到 `bridge.statusMessage.emit`（信号），
所以 `set_status` 本身跨线程安全；但**读控件/改控件必须包进 `run_in_ui`**。

> **实测症状**：点「自由停车」后界面立刻消失、服务端会话一起断，
> 日志里查不到任何异常（进程是被 signal/SIGSEGV 干掉的）。
> 电动球阀页更严重：回调里读 `card.name_label.text()` 并重建卡片。

## 2. 关键设计决策

### 2.1 网络为什么跑在独立线程

用 `asyncio` 跑网络（天然适配"多请求并发 + 超时"），但 asyncio 的阻塞点
不能与 Qt 事件循环共用一条线程——否则一边等网络就卡住重绘。

故：**网络线程跑自己的 asyncio loop，UI 线程跑 Qt loop**，
两者只通过 Qt 信号通信（`QObject` 的信号跨线程会自动排队）。

### 2.2 为什么用 Qt 信号而不是轮询标志位

轮询（定时器查一个 `self.latest = ...`）一定会漏事件或读到撕裂状态。
Qt 信号 + 队列连接是**唯一安全的跨线程通道**，且顺序有保证。

### 2.3 订阅为什么按"当前页"收敛

17 个页面如果每个都订全部 5 个主题，链路会同时推 17 份数据。
改为「切页时把订阅集合**收敛成本页需要的主题**」（`bridge.set_topics`）：

- 数据页不需要变频器遥测 → 不订 → 省带宽
- 订阅即补发一拍 → 页面一打开就有数据（不用等周期）
- 顶栏的温湿度/健康是全局的，始终订

### 2.4 为什么模型层要自己判新鲜度

服务端给了 `valid` / `staleMs`，但**断线后推送停止，`valid` 仍是最后一次的值**。
直读服务端的 `valid` 会把旧值当实时数据显示（温度显示 21.7℃ 但其实设备早就掉了）。

故 `model.py` 每个状态对象都记 `updated_ms`，`is_fresh()` 看**本地**最后更新时间。
UI 一律经 `is_fresh()` 判断，不直接信服务端的 `valid`。

### 2.5 主题为什么用 Fusion + QSS

平台原生样式（Windows/macOS）会忽略一部分 QSS 规则，导致同一份样式表
两端观感不同。Fusion 是 Qt 自绘样式，QSS 行为最可预期。

样式表规则体**逐字照搬 C 端 `HsfThemeCss.h`**，只把选择器换成 Qt 类名
（`XPushButton` → `QPushButton`）。这是"界面对齐"能成立的基础。

### 2.6 页面为什么套滚动壳（`Page.__init__`）

`Page` 把内容装进 `QScrollArea`，子类照旧往 `self.root` 加控件：

```python
outer = QVBoxLayout(self)            # 页面 = 滚动壳
self.scroll = QScrollArea()
self.scroll.setWidgetResizable(True)
self.scroll.setVerticalScrollBarPolicy(Qt.ScrollBarAsNeeded)
inner = QWidget()
self.root = QVBoxLayout(inner)       # ← 子类加东西的地方（没变）
self.scroll.setWidget(inner)
```

**为什么必须这样**：原来页面直接把自己的 `QVBoxLayout` 当根布局，控件
高度由**窗口剩余高度**决定。窗口一矮，布局就把卡片压到 `minimumHeight`
以下 —— 数字量页 32 点时 DI 卡片只露出 3 行半，CH24 那排的圆点还在、
下面的通道号/语义名被卡片边框切掉。

套壳后内层按**自然高度**（各控件 `minimumSizeHint` 之和）排布，
窗口放不下时右侧自动出现垂直滚动条：

| 窗口高 | 视口高 | 内容高 | 滚动范围 | DI 卡片高 |
|---|---|---|---|---|
| 620 | 637 | 705 | 0..68 | 317（最小 296） |
| 900 | 812 | 812 | 0..0 | 317（最小 296） |

即「布局完全显示」与「窗口大小」解耦：矮窗口是**滚动**，不是压缩。

> 横向也设 `AsNeeded`：窗口太窄时内容不会挤到边框外被裁。

### 2.7 各页交互口径（2026-11-05）

**变频器页**：

| 控件 | 形态 | 口径 |
|---|---|---|
| 方向 | **下拉框**（正转/反转） | 先选方向再启动。原来两个按钮把"方向"和"启动"挤成一个动作，容易误点 |
| 启停 | **一个按钮**，按状态切换 | 运行中显示「停止」（红）、停止时显示「启动」（绿）。动作按点击那一刻的遥测状态判定，**不按按钮文字**（文字可能滞后一拍） |
| 点动 | **独立按钮**（按住才动、松手即停） | 与启停语义完全不同，混在一起会按错。方向跟随方向下拉框 |
| 调速方式 | **下拉框**（频率调速/转速调速） | 切换时重置输入值——15Hz 当成 15rpm 下发等于不转 |
| 输出转速 | 只读字段 | **换算值**（50Hz ≈ 1440rpm），界面标注"换算"；额定点由服务端下发 |
| **下发**（调速） | 只在**运行中**可点 | 服务端拒绝停机时的给定（给定是运行参数，不是可预置配置）。界面若让点，用户点完只收到拒绝、还以为是故障 —— 置灰 + 提示"请先启动"才是诚实的前馈 |

> 判据用**遥测的运行状态**（`st.running`），不是按钮文字：文字可能滞后一拍，
> 而按钮动作按点击那一刻的真实状态走。

**模拟量页**（四列：通道 / 名称 / 数值 / 单位）：

```
通道 1 | 压差计 | 11.988   0.499 | mA / MPa
通道 2 |        | 3.996          | mA
```

- 有工程量换算的通道**原始 mA 与换算值并排**：排查按原始值（判断断线/欠量程），
  看工艺按换算值。
- 换算是服务端配的（`analog.scales`），客户端只显示。量程是现场标定参数，
  放客户端意味着每台机器各配一遍。

**数字量页**：点数由服务端 `count` 决定（单模块 16、聚合后 32），
灯阵/按钮阵按需重建。被电动球阀占用的口显示**通道号 + 语义名**
（`CH0` 下方「电动球阀1 开到位」），未占用的只显示 `CH<n>`。

**电动球阀页**：6 路卡片看板。状态双编码（颜色 + 文字），已到位那一侧的按钮
置灰。告警帧**必须先认 `ac` 键**再解析——告警帧没有 `count`/`v{i}_*`，
照状态帧解析会把点位清空、界面闪一下。

| 场景 | 界面行为 | 依据 |
|---|---|---|
| 已到位 + 点同侧 | 按钮**置灰点不动**；绕过界面发包则服务端回 `ignored` | 服务端幂等，不写 DO、不重置计时 |
| 动作中 + 点同侧 | 可点，状态栏「动作中，重复命令不重置计时」 | 服务端防抖：重置计时会让**卡阀永远不报警** |
| 动作中 + 点另一侧 | 可点，状态栏「已反向（重新计时）」，卡片提示"点另一侧可反向" | 现场常见：开错了立刻叫回 |
| 外部写了这个 DO | 卡片跟着变（服务端接管为一次新动作） | 数字量页/HMI/自动逻辑都能绕过阀接口 |

**状态显示以服务端为准**：`refresh()` 从 `model.valve` 取（推送的落地处），
不是只用入页快照。控制应答也写回 model —— 否则 200ms 后旧的推送会把
刚拿到的应答状态覆盖回去（症状：点第一下没反应）。

**远端设置页**：采集/落盘两卡之外，2026-11-08 增「登录策略（账号）」卡
（`_login_anon` / `_login_concur` / `_login_max` + 「应用登录策略」按钮）：
匿名登录、同账并发、会话总数上限（0=不限）三个键与 C 客户端
（`HsfSettingsRemote.c`）**同名同义**（`loginAllowAnonymous` /
`loginAllowConcurrent` / `loginMaxSessions`），走 `CMD_CONFIG_SET` 的
`login` 节；管理员（root）可改，只对下一次登录生效。

## 3. ⚠ 已踩过的坑

### 3.1 致命级（会让功能整体失效）

| 坑 | 表现 | 根因与修法 |
|---|---|---|
| **心跳永不发送** | 登录 6 秒后服务端必踢线，日志「静默超时 6067ms」 | 心跳判据用了 `max(发送, 接收)`。订阅 100ms 遥测后接收时间一直刷新，条件永不成立。**只该看自己的 `last_send_ms`** |
| **`wait_for` 吃掉半帧** | 一条数据都收不到 | `asyncio.wait_for(readexactly(16), timeout=0.5)` 超时时会**取消读取，已读到的字节丢失** → 此后整条流错位。改成不带超时读，存活判断交给心跳循环 |
| **`health=0` 被当成缺失** | 所有健康设备显示"离线" | `int(doc.get(k, 3) or 3)`：`0 or 3 == 3`。健康值 **0 是"正常"**，必须用 `doc.get(k, 3)` 不带 `or` |
| **字体匹配到无汉字字体** | 界面全是方框 | 候选里放了 `DejaVu Sans`（板端存在但无汉字）。**候选只放真含中文的字体**；找不到就按文件 `addApplicationFont` |
| **窗口 1x1 看不到界面** | xwininfo 里是 `1x1+0+0` | xfwm4 在首次 map 时覆盖几何。`show()` 前后各 `resize()` 一次 |
| **点「自由停车」界面直接消失** | 进程没了，**日志里没有任何 traceback** | 控制应答回调跑在**网络线程**，里面调 `set_status()` → `status_bar.set_message()` 从非 UI 线程碰 QWidget ⇒ **Qt 直接中止进程**。修法：所有碰控件的回调包进 `bridge.run_in_ui()`（Qt 信号 + 队列连接）。见 §1.1 |
| **数字量页只剩 `CH<n>`，电动球阀语义名全丢** | 名字只闪 200ms | 服务端周期推送是增量帧（`full=false`，不带 `din*`/`don*`），名字只在全量帧里。客户端原来**每帧都整表重建名字表** ⇒ 全量帧给的名字被下一帧增量擦成空。修法：**帧里没有名字键就不动名字表**（沿用缓存），比只判 `full` 更保守 |
| **矮窗口底部内容被裁** | 32 点时 CH24 那排的名字被卡片边框切掉 | 页面根布局直接吃窗口高度，控件被压到 `minimumHeight` 以下。修法：`Page` 套 `QScrollArea`（`setWidgetResizable(True)`），内层按自然高度排布，装不下就滚动。见 §2.6 |
| **流量计页永远显示 `--`** | 以为设备没接，其实是服务端没实现 | Python 服务端原先只有主题常量、没有流量计设备（C 端才有 `XFlowMeter`）。**这暴露了一个客户端侧的盲区**：`bridge.TOPIC_KIND` 漏登主题时 `_on_publish` 会静默 `return`，一样表现为"页面永远没数据"，两种原因症状相同。已补服务端设备；排查顺序建议：先看 `TOPIC_KIND` 有没有登，再看服务端有没有这个设备 |

### 3.2 样式/渲染

| 坑 | 表现 | 修法 |
|---|---|---|
| **裸 `QWidget { background }` 级联** | 深蓝标题栏被刷成页面灰、白字变灰黑 | 一律用 **ID 选择器**（`QWidget#HsfTitleBar`），并把子控件规则也限定在父 ID 下 |
| **`QWidget { color }` 压掉白字** | 顶栏文字不可读 | 全局表里**不写**裸 `QWidget { color }`；正文色交给调色板 |
| **纯 QWidget 不画样式背景** | 设了 background 但看不见 | 必须 `setAttribute(Qt.WA_StyledBackground, True)` |
| **`●` 字符渲染成条纹** | DI 灯看不出通断 | 用 QPainter 自绘圆点（`LampDot`）；关抗锯齿、用纯色 |

### 3.3 布局

| 坑 | 表现 | 修法 |
|---|---|---|
| **`addLayout(grid, 1)` 拉伸** | 主菜单按钮被拉到 500px 高、文字漂中间 | 用 QWidget 包住 grid 并 `setMaximumHeight`，外层再 `addStretch` |
| **表格 4 列时 item 为 None** | `AttributeError: 'NoneType' object has no attribute 'setText'` | 建行时按**实际列数**补齐 item；写入前逐格判空 |
| **窄屏不收起导航** | 560px 窗口内容被挤 | `resizeEvent` 里按 `COMPACT_MAX_W` 切形态 |
| **点数写死 16** | 服务端发 32 点，界面只画 16 格（上半区永远看不见） | 灯阵/按钮阵按快照 `count` **动态重建**（`set_count()`，幂等）；位宽也跟点数走（>16 点用 8 位十六进制，`%04X` 会截掉上半区） |
| **`setFixedHeight` 压不住 QSS** | 同一行按钮高度 46/33 参差 | QSS 的 `padding` + `min-height` 算出的 sizeHint **压过** `setFixedHeight`（后者只约束 maximum）。用 `QPushButton#<objectName>` 显式给统一行高 |
| **`setHorizontalHeaderLabels` 不扩列** | 传了 4 个表头但表仍 3 列，第 4 列**根本不存在**、界面上什么都看不到 | 显式 `setColumnCount` 再设表头（封装成 `DataTable.set_headers()`） |
| **`setText` 抹掉语义名** | 每拍刷新后通道名字消失 | 按钮文字统一由 `_render()` 生成（状态 + 名字），别在 `set_state` 里直接 `setText` |
| **语义名把通道号挤掉** | 只显示"阀1 开到位"，看不出是第几个点 | 通道号与语义名**分两行/两列**：通道号是接线/排查口径，名字是操作口径，两个都要 |
| **裸 `QHBoxLayout` 钉不住行高** | 软键盘按键下方一大块空白（面板 334px，键底只到 186px） | `QLayout` **没有** `setFixedHeight`/`setMaximumHeight`；不包控件时它的 sizeHint 高度按子项**最小**要求算，整行被压扁（板端实测四行 32/58/32/35，期望全 58）。行外框必须**包一层 `QWidget`** 再 `setFixedHeight` |
| **QSS `min-height` 是内容区尺寸** | 写 58 量出 60 | `border: 1px` 会额外加 2px ⇒ 样式里写 `h-2`，控件上仍钉 `h` |
| **只靠 `setFixedSize` 挡不住 QSS** | 按键被压/被拉 | QSS 的 `min-height`/`padding` 参与 sizeHint 计算 ⇒ 同时显式 `setMinimumHeight/setMaximumHeight` **且**在 QSS 里写 `min/max-height` |
| **Qt.Tool 窗口被 WM 补装饰** | 板端软键盘 X 上比 Qt 几何高 15px，且一 map 就把 xfce4 面板抬到全屏窗之上盖住软件标题栏 | X11 上加 `Qt.X11BypassWindowManagerHint`（override-redirect：无装饰、不参与排层）。排查手法：`xwininfo -id <wid>` 拿 **X 上的真实尺寸**与 Qt `geometry()` 对比，差 15px 就是 WM 装饰 |
| **QSlider 只在手柄/轨道响应** | 触摸屏上"按上去没反应" | 控件 56px 高但可见轨道只 10px，按上下空白事件被忽略 ⇒ 子类重写 `mousePressEvent`「按哪跳哪」（`_TouchSlider`） |
| **QSS 的 `top:-1px` 会让自绘文本发虚** | 文字边缘发灰 | 字号用整像素（`font_px()` 四舍五入），不要用半像素 |

### 3.4 时序

| 坑 | 表现 | 修法 |
|---|---|---|
| **`connected` 信号不回放** | `--auto` 下状态栏永远"未连接" | 登录发生在窗口构造**之前**，信号早发完。窗口 `__init__` 末尾要**主动同步**一次连接态 |
| **重连后状态不复位** | 断线重连成功但界面仍显示未连接 | `_on_state(READY)` 里也要置 `connected_flag` 并补发信号（自动重连不走 `connect_to`） |

### 3.6 测试自身的坑

| 坑 | 表现 |
|---|---|
| **拿假设备预设值测真机** | 对真实 `.12` 断言 `DI=0b0101`（那是假设备的值）→ 假红 |
| **测试没覆盖 6 秒后** | 只跑 3 秒的测试全绿，实际 6 秒必掉线 → 心跳 bug 漏网 |
| **改布局结构后不同步遍历口径** | 行外框由裸 layout 改成 `QWidget` 后，测试仍只递归 layout ⇒ 按键列表为空，7 项假红 |
| **空字符串断言没有区分力** | `sel2 == text` 在两者都是 `''` 时恒成立。要验"全选"必须**先填内容**再断言 |
| **重载模块用 `del sys.modules` 无效** | `from pkg import mod` 拿到的仍是**包属性上缓存的旧对象**，断言"滞后一拍"（A5 读到旧值、A6 读到 A5 的值）。必须 `importlib.reload(mod)` |

长连接类功能至少观察 3 个心跳周期（≥9 秒）。

> **G 与 H 的区别（这个区分很关键）**：G 组是**注入式** —— 往 `model` 塞数据、
> 读控件文字。它锁的是"数据到了界面**显示**对不对"，**不是**"用户点了按钮界面
> **反应**对不对"。H 组用 `btn.click()` 走完整链路（请求 → 网络线程收应答 →
> `run_in_ui` 投回 UI 线程 → 改控件）。
>
> 为什么要分两组：控制应答回调跑在**网络线程**，里面碰 QWidget 会让 Qt **直接
> 崩进程且不产生 Python traceback**。这类缺陷注入式测试**永远测不出**（它不
> 触发请求），单点断言全绿也照样炸 —— 变频器页"点自由停车后界面消失"就是这类
> 事故。另有一类也测不出：按钮 `clicked` 没接、lambda 捕获错位。
>
> **H 组只在 `--auto` 时跑**（离线无从发请求），离线运行会显示 SKIP。
>
> **`test_vfd_combo.py` 是 H 组的加强版**：29 步 × N 轮，把变频器/电动球阀/进水泵
> 的按钮连点一遍并检查**进程存活**（`app` 事件循环还在 ⇒ 没崩）。它连点同一侧
> 两次，专门走到服务端 `repeated` / `ignored` 那两个分支。

> **G 组有一条特殊的几何断言**：`浊度数值与单位不重叠`。
> 它必须在 `win.show()` 之后跑（测试里用 `WA_DontShowOnScreen` 只布局不上屏）
> —— 未 show 的窗口子控件几何全是 `(0,0,640,480)` 这种占位值，拿它比 x 区间
> 会**假通过**。这条锁的是"把 label 和单位塞进同一 QGridLayout 单元格"那个

## 5. 代码约定

### 5.1 注释

- 模块头写**它解决什么问题**，不是它包含哪些函数。
- **非显然的常量/分支必须写"为什么"**，尤其是踩坑后改的（标 `[实锅]`）。
- 不写"获取xx""设置xx"这类废话。

### 5.2 命名

- 私有：前缀 `_`；常量：`UPPER_SNAKE`
- 与 C 端对应的概念保持同名语义（`VfdPage`、`LampRow`）

### 5.3 异常

- **网络/协议可预期失败** → 回调里返回错误字符串，页面显示在状态栏
- **单页异常** → `main_window` 的兜底 `except` 记到状态栏，绝不崩整个界面
- **绝不让异常静默**：静默成功是最危险的失败模式

### 5.4 改动检查清单

```sh
QT_QPA_PLATFORM=offscreen python tests/test_client.py --auto <host>   # 自测
python -m hsfsrv_client --offline --shot /tmp/x.png --size 1280x720   # 渲染冒烟
```

改了 `pages_registry` → 必须同步 C 端 `HsfPages.h`（页序/页名/导航树）。
改了协议键名 → 必须同步服务端 `hsfsrv/proto.py` 与 `app.py`。
