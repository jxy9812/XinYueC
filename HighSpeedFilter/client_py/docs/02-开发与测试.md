## 1. 模块结构

```
hsfsrv_client/
  proto.py / bson.py   线协议常量 + BSON（与服务端 server_py 同一份，逐字复制）
  xlink.py             XLink 客户端会话层（握手/认证/请求/订阅/心跳/重连）
  model.py             设备数据模型（BSON → 结构化状态 + 本地新鲜度）
  bridge.py            网络线程 → UI 线程的 Qt 桥（唯一跨线程通道）
  theme.py             配色/度量/样式表（与 C 端 HsfThemeCss.h 同源）
  widgets.py           标题栏/状态栏/导航/卡片/数值块/三段式骨架
  page_base.py         页面基类 + 表格/灯阵列/DO 网格
  pages_registry.py    页索引/页名/导航树（与 C 端逐项一致）
  pages_monitor.py     数字量 / 模拟量 / 变频器 / 流量计
  pages_other.py       主界面 / 菜单 / 数据 / 设置
  login.py             登录窗
  main_window.py       主窗 + 切页/订阅协调
  __main__.py          入口

tools/
  shot.py              板端抓图（Qt grabWindow，**不要用 xwd**）
  ui_sweep.py          逐页巡检截图

tests/
  test_client.py       无头自测（页面/注册表/订阅/数据/闸门）
```

### 1.1 分层与数据流

```
网络线程                        UI 线程
─────────                       ─────────
XLinkClient
  ├─ _pump() 收帧
  └─ _on_publish(topic, bytes)
        │
        ├─ bson.decode()
        ├─ model.apply()          ← 深拷贝到 AppModel
        └─ dataUpdated.emit(kind) ──(Qt 队列连接)──> 页面 refresh()
                                                      读 ctx.model
```

**关键约束**：
- `AppModel` 只由网络线程写、UI 线程读。Python 的 GIL 保证单次赋值原子，
  且所有字段都是标量/新建 dict，不存在"读到半个对象"。
- **不要在回调里直接碰 QWidget**（那在网络线程，必崩）。一切经 Qt 信号。

## 2. 关键设计决策

### 2.1 网络为什么跑在独立线程

用 `asyncio` 跑网络（天然适配"多请求并发 + 超时"），但 asyncio 的阻塞点
不能与 Qt 事件循环共用一条线程——否则一边等网络就卡住重绘。

故：**网络线程跑自己的 asyncio loop，UI 线程跑 Qt loop**，
两者只通过 Qt 信号通信（`QObject` 的信号跨线程会自动排队）。

### 2.2 为什么用 Qt 信号而不是轮询标志位

轮询（定时器查一个 `self.latest = ...`）一定会漏事件或读到撕裂状态。
Qt 信号 + 队列连接是**唯一安全的跨线程通道**，且顺序有保证。

### 2.3 订阅为什么按"当前页"收敛

17 个页面如果每个都订全部 5 个主题，链路会同时推 17 份数据。
改为「切页时把订阅集合**收敛成本页需要的主题**」（`bridge.set_topics`）：

- 数据页不需要变频器遥测 → 不订 → 省带宽
- 订阅即补发一拍 → 页面一打开就有数据（不用等周期）
- 顶栏的温湿度/健康是全局的，始终订

### 2.4 为什么模型层要自己判新鲜度

服务端给了 `valid` / `staleMs`，但**断线后推送停止，`valid` 仍是最后一次的值**。
直读服务端的 `valid` 会把旧值当实时数据显示（温度显示 21.7℃ 但其实设备早就掉了）。

故 `model.py` 每个状态对象都记 `updated_ms`，`is_fresh()` 看**本地**最后更新时间。
UI 一律经 `is_fresh()` 判断，不直接信服务端的 `valid`。

### 2.5 主题为什么用 Fusion + QSS

平台原生样式（Windows/macOS）会忽略一部分 QSS 规则，导致同一份样式表
两端观感不同。Fusion 是 Qt 自绘样式，QSS 行为最可预期。

样式表规则体**逐字照搬 C 端 `HsfThemeCss.h`**，只把选择器换成 Qt 类名
（`XPushButton` → `QPushButton`）。这是"界面对齐"能成立的基础。

## 3. ⚠ 已踩过的坑

### 3.1 致命级（会让功能整体失效）

| 坑 | 表现 | 根因与修法 |
|---|---|---|
| **心跳永不发送** | 登录 6 秒后服务端必踢线，日志「静默超时 6067ms」 | 心跳判据用了 `max(发送, 接收)`。订阅 100ms 遥测后接收时间一直刷新，条件永不成立。**只该看自己的 `last_send_ms`** |
| **`wait_for` 吃掉半帧** | 一条数据都收不到 | `asyncio.wait_for(readexactly(16), timeout=0.5)` 超时时会**取消读取，已读到的字节丢失** → 此后整条流错位。改成不带超时读，存活判断交给心跳循环 |
| **`health=0` 被当成缺失** | 所有健康设备显示"离线" | `int(doc.get(k, 3) or 3)`：`0 or 3 == 3`。健康值 **0 是"正常"**，必须用 `doc.get(k, 3)` 不带 `or` |
| **字体匹配到无汉字字体** | 界面全是方框 | 候选里放了 `DejaVu Sans`（板端存在但无汉字）。**候选只放真含中文的字体**；找不到就按文件 `addApplicationFont` |
| **窗口 1x1 看不到界面** | xwininfo 里是 `1x1+0+0` | xfwm4 在首次 map 时覆盖几何。`show()` 前后各 `resize()` 一次 |

### 3.2 样式/渲染

| 坑 | 表现 | 修法 |
|---|---|---|
| **裸 `QWidget { background }` 级联** | 深蓝标题栏被刷成页面灰、白字变灰黑 | 一律用 **ID 选择器**（`QWidget#HsfTitleBar`），并把子控件规则也限定在父 ID 下 |
| **`QWidget { color }` 压掉白字** | 顶栏文字不可读 | 全局表里**不写**裸 `QWidget { color }`；正文色交给调色板 |
| **纯 QWidget 不画样式背景** | 设了 background 但看不见 | 必须 `setAttribute(Qt.WA_StyledBackground, True)` |
| **`●` 字符渲染成条纹** | DI 灯看不出通断 | 用 QPainter 自绘圆点（`LampDot`）；关抗锯齿、用纯色 |

### 3.3 布局

| 坑 | 表现 | 修法 |
|---|---|---|
| **`addLayout(grid, 1)` 拉伸** | 主菜单按钮被拉到 500px 高、文字漂中间 | 用 QWidget 包住 grid 并 `setMaximumHeight`，外层再 `addStretch` |
| **表格 4 列时 item 为 None** | `AttributeError: 'NoneType' object has no attribute 'setText'` | 建行时按**实际列数**补齐 item；写入前逐格判空 |
| **窄屏不收起导航** | 560px 窗口内容被挤 | `resizeEvent` 里按 `COMPACT_MAX_W` 切形态 |

### 3.4 时序

| 坑 | 表现 | 修法 |
|---|---|---|
| **`connected` 信号不回放** | `--auto` 下状态栏永远"未连接" | 登录发生在窗口构造**之前**，信号早发完。窗口 `__init__` 末尾要**主动同步**一次连接态 |
| **重连后状态不复位** | 断线重连成功但界面仍显示未连接 | `_on_state(READY)` 里也要置 `connected_flag` 并补发信号（自动重连不走 `connect_to`） |
| **同机两个 root 客户端互踢** | 后登录的显示"连接已断开" | 服务端 root 单会话策略；第二个实例要么关掉第一个，要么用 admin |

### 3.5 工具链

| 坑 | 表现 | 修法 |
|---|---|---|
| **xwd 转 PNG 出"条纹"** | 看着像客户端渲染坏了，白查两轮 | 本板 `xwd` 是 24bpp packed（每像素仍占 4 字节）。**别自己转，用 `QScreen.grabWindow(0)`** |
| **deploy.sh heredoc 吞参数** | `run_client.sh` 里参数变成 `if [ -n "" ]` | 用 base64 传输脚本文件，不走 heredoc 插值 |
| **ssh 后台进程吞 stdin** | 命令链中途静默消失 | 后台启动一律 `< /dev/null`，并用 `setsid`；或每条单独一次 ssh |
| **pip 默认源超时** | 装 PyQt5 卡死 10+ 分钟 | `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| **清华镜像 qtbase 404** | `apt-get install python3-pyqt5` 报 404 | security 源缺 `u2` 版本；临时注释 security 源装 main 的 `u1` |

### 3.6 测试自身的坑

| 坑 | 表现 |
|---|---|
| **拿假设备预设值测真机** | 对真实 `.12` 断言 `DI=0b0101`（那是假设备的值）→ 假红 |
| **测试没覆盖 6 秒后** | 只跑 3 秒的测试全绿，实际 6 秒必掉线 → 心跳 bug 漏网 |

**判据**：真机测试只断言**结构**（有字段、类型对、能读回），不断言具体数值；
长连接类功能至少观察 3 个心跳周期（≥9 秒）。

## 4. 测试

### 4.1 无头自测

```sh
# 离线（只测 UI 结构、注册表、主题口径）
QT_QPA_PLATFORM=offscreen python tests/test_client.py

# 连真实服务端（测订阅收敛、数据落地、闸门）
QT_QPA_PLATFORM=offscreen python tests/test_client.py --auto 192.168.0.10
```

覆盖 30 项：
- **B** 注册表与 C 端逐项一致（页名、导航树含顺序）
- **F** 主题色值/度量与 C 端同源
- **A** 17 页可构建可切换、可复用不重建
- **C** 切页订阅收敛（主界面 4 个 / 无数据页 0 个 / 数字量页只 1 个）
- **D** 推送落地 model、健康 `0` 保持"正常"、在线设备与状态自洽
- **E** 控制闸门与模式/角色/新鲜度一致

### 4.2 板端视觉验收

```sh
# 单页抓图
ssh root@192.168.0.10 'cd .../hsf_client_py && DISPLAY=:0 python3 tools/shot.py /tmp/a.png'

# 逐页巡检
ssh root@192.168.0.10 'cd .../hsf_client_py && DISPLAY=:0 \
    python3 tools/ui_sweep.py --host 192.168.0.10 --settle 7'
```

### 4.3 交互闭环（真机）

DO 与变频器的控制必须**写后读回**验证，只断言 `ok=true` 不够：

```python
# 客户端侧点按钮 → 服务端写设备 → 回读快照 → 对比
c.request(CMD_DIGITAL_CONTROL, {"dev":0, "mask":0x00A5})
r = c.request(CMD_DIGITAL_SNAPSHOT, {"dev":0})
assert r["do"] == 0x00A5          # 读回必须一致
```

已用此法在真实模块上验证通过，也在客户端 UI 上验证过
（点 DO2 → 设备 `DO=0x0004` → 清除 → `0x0000`）。

## 5. 代码约定

### 5.1 注释

- 模块头写**它解决什么问题**，不是它包含哪些函数。
- **非显然的常量/分支必须写"为什么"**，尤其是踩坑后改的（标 `[实锅]`）。
- 不写"获取xx""设置xx"这类废话。

### 5.2 命名

- 私有：前缀 `_`；常量：`UPPER_SNAKE`
- 与 C 端对应的概念保持同名语义（`VfdPage`、`LampRow`）

### 5.3 异常

- **网络/协议可预期失败** → 回调里返回错误字符串，页面显示在状态栏
- **单页异常** → `main_window` 的兜底 `except` 记到状态栏，绝不崩整个界面
- **绝不让异常静默**：静默成功是最危险的失败模式

### 5.4 改动检查清单

```sh
QT_QPA_PLATFORM=offscreen python tests/test_client.py --auto <host>   # 自测
python -m hsfsrv_client --offline --shot /tmp/x.png --size 1280x720   # 渲染冒烟
```

改了 `pages_registry` → 必须同步 C 端 `HsfPages.h`（页序/页名/导航树）。
改了协议键名 → 必须同步服务端 `hsfsrv/proto.py` 与 `app.py`。
