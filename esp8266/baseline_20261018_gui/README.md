## 与总装固件的关键差异（排查线索）

**驱动源码本身在 10-18 15:10 之后被工作流改过**（加探针诊断，
`XDeviceDisplay_ssd1306_i2c.c` 从 14516 字节涨到 22133 字节，10-19 18:33）。
但改的是探针打印与 init 时的诊断输出，`twi_start`/`twi_write_bit`/
`twi_read_bit`/`twi_write_byte` 这几个位级原语按记录未动。

失败的现场读数（总装固件探针）：
```
early-after-pinmode GPF12=0xB0 GPF14=0xB0 GPC12=0x04 GPC14=0x04
idle sda=0 scl=1
[i2c] probe start refused (SDA stuck low)
```

引脚配置正确（0xB0 = GPIO 功能 + 内部上拉；0x04 = 开漏位），
但 SDA 读回低电平 → `twi_start()` 判定「总线忙」→ 一个事务都发不出去 →
`init` 记到 NACK 提前中止 → `display-on (0xAF)` 没发出 → 屏全黑。

### 关于之前那份「硬件故障」的判断——那是错的

曾用三份固件（`ctrl_gui` / `ctrl_oled3` / 总装 R13）都报 `idle SDA=0 SCL=1`，
据此判定为硬件侧问题。**该判据无效**：`ctrl_gui` 烧的是 466020 字节，
而基线是 473008 字节，**对不上 = 它是重新编译的**，带着当天被改过的驱动。
重新编译的固件当然也会失败，不能作为硬件判据。

教训：**对照实验必须用未改动的原始二进制**。重新编译出来的东西哪怕来自同一份源码、
同一份驱动，只要夹带了任何当日改动，就不构成对照。
