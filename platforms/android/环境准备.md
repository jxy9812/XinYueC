# 安卓构建环境准备（Windows）

> 面向：把 XGui 的安卓应用（XGuiDemo / 高速过滤器客户端）在这台机器上从零
> 编译成 APK 的完整步骤。**本文只讲装什么、怎么装、怎么验**；打包链路与
> 坑库见 `README.md`。
>
> **状态（2026-11-09 已装好并跑通）**：本机已装齐下列三件，工具链自检全过，
> 两款应用（XGuiDemo / 高速过滤器客户端）都能出 APK 并装机。
>
> | 组件 | 实装路径 | 版本 |
> |---|---|---|
> | Android NDK | `D:\android-ndk\android-ndk-r29` | r29 |
> | Android SDK | `C:\Android\Sdk` | build-tools 36.0.0 / platform android-36 / platform-tools 37.0.1 |
> | JDK | `C:\Java\jdk-17` | 17.0.20.1（OpenJDK） |
>
> CMake + Ninja 用 VS 2022 Preview 自带：

## 一、要装什么

| 组件 | 版本 | 建议路径 | 为什么是这个版本 |
|---|---|---|---|
| **Android NDK** | **r29**（r29b/r29c 均可） | `D:\android-ndk\android-ndk-r29` | 仓库实测版本；`platforms/android/CMakeLists.txt` 的 `ANDROID_NDK_ROOT` 默认值就指这里 → 脚本与 CMake **零改动** |
| **Android SDK** | build-tools **36.0.0** + 任意一个 platform + platform-tools | `C:\Android\Sdk` | `build_apk.sh:31` / `pack_apk.ps1:25` 写死 `build-tools/36.0.0`；platform 只取最新的 `android.jar`（脚本自动挑） |
| **JDK** | **17**（11/17/21 均可，需含 `javac`） | 任意，如 `C:\Java\jdk-17` | `javac`（编 Java 桥）、`keytool`（生成/使用签名密钥）、`apksigner`/`d8` 内部都要 java。**JRE 不够** |
| CMake + Ninja | 任意 | VS 2022 自带即可 | 本机 VS 2022 Preview：`D:\Program Files\Microsoft Visual Studio\2022\Preview\Common7\IDE\CommonExtensions\Microsoft\CMake\`（含 `CMake\bin\cmake.exe` 与 `Ninja\ninja.exe`） |

**不需要**装完整 Android Studio（约 1 GB），除非你只是想用它自带的 JBR。

> **ABI 选 arm64-v8a**：真机（小米 25102RKBEC / Android 16）的 ABI 是
> `arm64-v8a`，`adb shell getprop ro.product.cpu.abi` 实测。`x86_64` 只对
> 模拟器有用。

### 装法 A：Android Studio（最省事）

1. 装 Android Studio → 打开 **SDK Manager**（More Actions → SDK Manager）。
2. **SDK Platforms** 标签：勾任意一个（推荐 `Android 16 / API 36`）。
3. **SDK Tools** 标签：勾 **Android SDK Build-Tools 36.0.0**、**Android SDK Platform-Tools**、
   展开 **NDK (Side by side)** 勾 **26.x/29.x**（r29 最稳）、**CMake** 可不装（用 VS 的）。
4. JBR 路径：`C:\Program Files\Android\Android Studio\jbr`（当 `JAVA_HOME` 用）。

### 装法 B：全手工（不想装 Studio）

1. **NDK**：`https://developer.android.com/ndk/downloads` → 下 r29 的 Windows zip →
   解压到 `D:\android-ndk\`，得到 `D:\android-ndk\android-ndk-r29`（**注意别多套一层**）。
2. **SDK commandline-tools**：`https://developer.android.com/studio#command-line-tools-only`
   → 解压到 `C:\Android\Sdk\cmdline-tools\latest`。
3. 装 SDK 组件（先 `cd C:\Android\Sdk\cmdline-tools\latest\bin`，再 `sdkmanager.bat --sdk_root=C:\Android\Sdk "platform-tools" "platforms;android-36" "build-tools;36.0.0"`，
   首次会问 license，输 `y` 逐条接受）。
4. **JDK**：`https://adoptium.net/temurin/releases/?version=17` → 解压到 `C:\Java\jdk-17`。

## 二、环境变量

设三个（**系统属性 → 环境变量**，新开的终端才生效）：

```
ANDROID_SDK  = C:\Android\Sdk
ANDROID_NDK  = D:\android-ndk\android-ndk-r29
JAVA_HOME    = C:\Java\jdk-17
```

PATH 追加：

```
%ANDROID_SDK%\platform-tools     ← adb（注意：PATH 上已有的那个 adb 可能是
                                   RKDevTool 自带的，不是 SDK 的，务必用完整路径）
%JAVA_HOME%\bin
```

> 脚本里的默认值（`build_apk.sh:28-29`、`pack_apk.ps1:24,84`）就是上一台机器的
> `C:\Users\jxy\AppData\Local\Android\Sdk` 与 `D:\android-ndk\android-ndk-r29`。
> **设了环境变量就不用改脚本**；`D:\android-ndk\android-ndk-r29` 与 CMake 的
> `ANDROID_NDK_ROOT` 默认值一致，所以 CMake 侧连环境变量都不必设。

## 三、工具链自检（装完先跑这个）

Git Bash 里：

```bash
# NDK：工具链文件在不在
ls "$ANDROID_NDK/build/cmake/android.toolchain.cmake" 2>/dev/null || \
  ls /d/android-ndk/android-ndk-r29/build/cmake/android.toolchain.cmake

# SDK：build-tools 与 android.jar
ls "$ANDROID_SDK/build-tools/36.0.0/aapt2.exe" 2>/dev/null
ls "$ANDROID_SDK"/platforms/*/android.jar 2>/dev/null | tail -1

# JDK：javac + keytool
"$JAVA_HOME/bin/javac.exe" -version 2>&1 | head -1
"$JAVA_HOME/bin/keytool.exe" -help 2>&1 | head -1

# adb（用完整路径，避开 RKDevTool 的那个）
"$ANDROID_SDK/platform-tools/adb.exe" version
```

全有输出 = 可以往下走。**只要缺一个，后面打包必然失败**，且报错五花八门
（`找不到 android.jar` / `缺 javac/d8` / `apksigner failed`）。

## 四、构建

### 4.1 编排层（推荐，一条龙）

```bat
:: 高频过滤器客户端（x86_64）
cmake -S platforms/android -B build_android_hsf -G Ninja ^
  -DCMAKE_MAKE_PROGRAM="D:\Program Files\Microsoft Visual Studio\2022\Preview\Common7\IDE\CommonExtensions\Microsoft\CMake\Ninja\ninja.exe" ^
  -DANDROID_APP_DIR=HighSpeedFilter/client/android ^
  -DANDROID_ABI_NAME=x86_64 ^
  -DANDROID_NDK_ROOT=%ANDROID_NDK%
cmake --build build_android_hsf --target apk
```

> `-DANDROID_APP_DIR` 的相对路径按**仓库根**解析（`HighSpeedFilter/client/android`），
> 别写成 `../../HighSpeedFilter/...`（那是相对 `platforms/android` 的写法，基准混用会跑到仓库外）。

或者用预设（已含应用目录与 ABI）：

```bat
cmake --preset hsf          :: 高速过滤器客户端 · x86_64
cmake --build build_android_hsf --target apk
```

### 4.2 手动两步（排查问题时更有用）

```bat
:: ① 编译原生库
cmake -S . -B out/android-hsf-x86_64 -G Ninja ^
  -DCMAKE_TOOLCHAIN_FILE=%ANDROID_NDK%/build/cmake/android.toolchain.cmake ^
  -DANDROID_ABI=x86_64 -DANDROID_PLATFORM=android-24 ^
  -DANDROID_APP_PKG=com.xinyuec.hsfclient
cmake --build out/android-hsf-x86_64 --target xhsfclient

:: ② 打包
bash platforms/android/build_apk.sh x86_64 HighSpeedFilter/client/android
::   或（Windows 原生，不依赖 bash）
powershell -ExecutionPolicy Bypass -File platforms\android\pack_apk.ps1 -Abi x86_64 -AppDir HighSpeedFilter\client\android
```

> **`ANDROID_APP_PKG` 必须等于该应用清单里的 `package`**——它决定注入的字体目录
> 宏 `/data/data/<pkg>/files/fonts`（字库释放目标与 FT 查找目录必须同源）。
> 用编排层时这个参数由编排层**从清单派生**后自动传入，手工流程才要自己填。

## 五、安装与启动

```bat
:: 连设备（模拟器 127.0.0.1:5555；真机填 USB/无线调试的地址）
adb connect 127.0.0.1:5555
adb devices                              :: 确认在线；多设备必须 -s 指定

:: 装 + 起
adb install -r platforms/android/out/HsfClient-debug.apk
adb shell am start -n com.xinyuec.hsfclient/com.xinyuec.android.XGuiNativeActivity

:: 看日志（tag 是各应用自己的：HsfClient / XGuiDemo）
adb logcat -s HsfClient
```

> 组件名 = **清单包 + 完整 Activity 类名**。清单包与 Java 包是两个概念
> （Java 包恒为 `com.xinyuec.android`），**不能写成 `.XGuiNativeActivity` 简写**。

编排层也有一键装启：

```bat
cmake --build build_android_hsf --target install-apk
```

## 六、真机验收清单

> **2026-11-09 本轮已验 / 未验**（设备：小米 25102RKBEC，Android 16 / API 36，
> arm64-v8a，1200×2608 @480dpi ⇒ **逻辑 400×869**）：
>
> | 项 | 结果 |
> |---|---|
> | 工具链自检 | ✅ NDK/SDK/JDK 全通过 |
> | 两款应用编译 + 打包 | ✅ `libxguidemo.so`(29.3MB) / `libxhsfclient.so`(21.9MB) + 3.5MB 字库 asset |
> | 装机 + 两应用共存 | ✅ `com.xinyuec.xguidemo` 与 `com.xinyuec.hsfclient` 同设备并存 |
> | 原生侧启动 | ✅ logcat：`ANativeActivity_onCreate` → `font: released .../files/fonts/XFontOutlineCommon.otf (3511576 bytes)` → `app thread: enter hsf_client_main` |
> | 字库机制 | ✅ demo 的私有目录里确有 `XFontOutlineCommon.otf`（机制已被真机证实） |
> | 手机 → 板端服务端 | ✅ `nc 192.168.1.249 6100` 收到 XLink 设备健康快照（`devCount`/`d0_name`/`d0_health`…）；板端 `hsfserverpy` active、监听 `0.0.0.0:6100` |
> | **屏幕上的渲染效果** | ⏳ **未验**：设备息屏（`mWakefulness=Dozing`）+ MIUI 禁 `pm grant`，截图全黑（README 坑 15）。需设备侧解锁且屏幕保持唤醒后重截 |
>
> **板端地址以实测为准**：板端是 `192.168.1.249`（不是 `192.168.0.10`），
> 服务端口 **6100**，默认账号 **admin/admin**（`XhsfLinkProto.h` 的
> `HSF_DEFAULT_USER_*` 与 Python 侧一致）。

装完不等于能用。逐项过：

| # | 检查 | 判据 | 不达标时的根因方向 |
|---|---|---|---|
| 1 | **真装上了** | `adb shell dumpsys package com.xinyuec.hsfclient \| findstr lastUpdateTime` 的时间已更新 | 签名漂移 → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（README 坑 9） |
| 2 | **字库在位** | `adb shell ls -l /data/data/com.xinyuec.hsfclient/files/fonts/` 有 `.otf` | 壳的 asset 释放失败（README 坑 3） |
| 3 | **中文正常** | 界面上中文不是空白/方块 | 字体目录与查找目录不一致 → 回退 96 字的位图字库（README 坑 4/5） |
| 4 | **窗口满屏** | 竖屏时铺满整屏，不是被裁的横屏比例 | 主窗几何没跟 surface 逻辑尺寸（`HsfUi.c` 的安卓分支） |
| 5 | **登录可用** | 虚拟键盘弹起后，「密码框 + 登录钮」仍在可视区、点得到 | 键盘停靠压矮客户区 → 需滚动壳 + 焦点滚入（`HsfLogin.c` 的安卓分支） |
| 6 | **连上服务端** | 登录成功、主页出现**真实遥测数据**（不是「无数据」） | 板端服务端没起 / 网络不通 / 协议漂移 |
| 7 | **两应用共存** | 设备上 demo 与 HSF 客户端各自独立启动、互不覆盖 | 两个 APK 的包名或签名配错 |

### 板端服务端（高速过滤器客户端的联调对端）

客户端是**纯 TCP/XLink 客户端**（不开串口、不做 Modbus 主站），485 采集与落盘
全在服务端。板端（RK3568）现役是 Python 版 `hsfserverpy`：

```bash
# 板端：先停抢串口的服务，否则从站应答会被抢走
systemctl stop run_test.service
# 起板端 HSF 服务（端口 6100）
```

客户端登录时填板端 IP（`192.168.0.10`）+ 端口 `6100`、账号 `admin`/`root`。

## 七、故障速查

| 现象 | 多半是 | 去哪看 |
|---|---|---|
| `找不到 NDK 工具链` | `ANDROID_NDK_ROOT` 没设 / 路径多套了一层 | 本文 §三 |
| `找不到应用描述：…/app.env` | `ANDROID_APP_DIR` 相对路径基准写错（要按仓库根） | 本文 §4.1 |
| `缺 javac/d8` | `JAVA_HOME` 没指到含 `javac` 的 JDK | README 坑 6（PowerShell 5.1 + 无 BOM 的 .ps1 会按 GBK 解析） |
| `Missing AndroidManifest.xml` | `aapt add` 跑在了 `aapt2 link` 之前 | README 坑 2 |
| `font: asset fonts/… not found in APK` | 用 `aapt2 -A` 加的 asset（Windows 版写反斜杠路径） | README 坑 1 |
| 装上了但界面是老的 | 签名漂移静默装失败 | README 坑 9 |
| WiFi 扫描空表 | 定位权限没给（API 26+ 起算位置数据） | README 坑 8 |
| 界面卡死 / 100% CPU | 红黑树定时器环（安卓特有路径，桌面复现不了） | README 坑 10 |
| 中文整片空白 | 字体没落到 FT 轮廓字（静默回退位图字库） | README 坑 4/5 + 本文 §六 第 3 条 |
